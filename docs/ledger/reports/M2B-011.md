# M2B-011: runner: local checkpoints as shadow git commits

## Summary

- New `runner::checkpoint` module: `take` (snapshot as a commit under `refs/sm/checkpoints/<thread>/<n>`, parented on the previous one), `restore`, `diff` (checkpoint vs checkpoint or vs working tree), `list`, and `checkpoint_event` (builds the TurnEvent `Checkpoint`, kind `shadow_git`).
- Snapshots are built with plumbing against a temporary `GIT_INDEX_FILE` in the git dir, so the user's index, HEAD, branches, stash and working tree are not touched.
- Everything shells out to the `git` binary via `std::process::Command`. No new git library.
- Before building, merged `v2` (fast-forward to `c8d9b4d`) as the coordinator asked, for the hub `SessionConfig` fix.

## Acceptance criteria

1. **Per-turn snapshot, no user state touched: met.** `take_commits_a_chain_without_touching_user_state` checks that `refs/sm/checkpoints/th_1/1` and `/2` exist, that checkpoint 2's parent is checkpoint 1, that ignored files are excluded from the tree, and that `git status --porcelain`, `HEAD`, the index file bytes and `git stash list` are unchanged after each take.
2. **Restore and diff: met.**
   - `restore_brings_back_the_snapshot_and_keeps_ignored_files` covers a modified tracked file, a deleted tracked file, a deleted untracked file, a file created after the checkpoint (and its now-empty directory, which is removed), and an ignored file that keeps its post-checkpoint contents. It also checks the index bytes.
   - `diff_between_checkpoints_and_against_the_working_tree` checks unified text (`-one`, `+two`, `+++ b/new.txt`) and the changed-files list for both targets.
3. **TurnEvent `Checkpoint` validates against the schema: met.** `checkpoint_event_validates_against_the_turn_event_schema` builds the event, wraps it in an `Envelope`, validates against `envelope.schema.json` with the same retriever pattern as `protocol/tests/golden_acp_turn.rs`, and round-trips.
4. **No commits yet; clean refusal outside a repo: met.** `works_in_a_repository_without_commits` (HEAD stays unborn) and `refuses_outside_a_git_repository` (returns `Err` for take, restore and diff, no panic).

## Design notes

- `n` is `max(existing n) + 1`. `files_changed` counts paths that differ from the previous checkpoint, or from the empty tree for the first one.
- Git commit identity comes from env vars (`sm checkpoint <checkpoint@sm.invalid>`), so the user's git config is not needed and not read.
- Git env vars that would redirect the repo (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`) are cleared for every git call.
