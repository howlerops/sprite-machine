# M3-013: desktop notifications, deep links, notification settings

## Summary

`crates/client-gpui/src/notify/` now has:

- `Notifier`, fed `(thread_id, status)` pairs. It notifies once per transition to `needs_you`, `done` or `failed`. It stays quiet for a repeated status (refetch), for the focused thread, for a kind switched off, and for the seeded baseline. A suppressed transition is not replayed later.
- `NotificationSink` trait. The real implementation, `ToastSink`, uses gpui-component notifications with `in_app_and_system()` delivery. That posts to the OS notification center as well as showing an in-app toast, and the pinned gpui-component already supports it (via `notify-rust`, which is in Cargo.lock). No Cargo.toml change was needed. Clicking a toast queues `NotifyEvent::Open { thread_id }` on an `EventQueue`.
- `hub_link_thread(url, hub) -> Option<thread_id>`. It accepts `<hub>/t/<id>` only. It rejects other hosts, ports, schemes, user info, other or longer paths, and encoded or odd ids. The repo defines no custom URL scheme, so none is parsed.
- `NotifyPrefs` / `PrefsHandle` / `NotifyConfig { prefs_path }`. They hold per-kind toggles, all on by default, persisted as JSON; a missing or corrupt file gives the defaults.
- `NotifySettingsView`, a checkbox per kind that saves on every change.
- `locales/en/notify.ftl`. Titles are generic: "Needs your attention", "Task finished", "Task failed". No machine name is ever passed in.

## Criteria

- Transitions produce one notification each, with no repeats, no focused thread, and none for a disabled kind. Evidence in tests/notify.rs:
  - `each_transition_to_a_notifiable_status_notifies_once`
  - `a_refetch_with_the_same_status_does_not_notify_again`
  - `the_focused_thread_does_not_notify_and_is_not_retried`
  - `a_disabled_kind_does_not_notify_but_the_others_do`
  - `the_seeded_first_fetch_is_a_baseline_not_a_burst`
  - `quiet_statuses_never_notify`
- Clicking emits Open{thread_id}: `clicking_a_notification_opens_its_thread_once`. A toast click queues the same event on `EventQueue`; headless tests only cover a toast being shown (see Discovered work).
- Deep links: `hub_links_parse_to_the_thread_id` and `other_hosts_paths_and_schemes_are_rejected`.
- Prefs model and view, persisted to the configured path:
  - `prefs_default_on_and_persist_to_the_configured_file`
  - `unreadable_prefs_fall_back_to_the_defaults`
  - `a_prefs_file_that_cannot_be_written_reports_the_error_but_applies`
  - `the_settings_view_toggles_and_saves_each_kind` (headless: click, aria state, file, and the Notifier obeys the shared handle)
- Toast sink headless: `the_toast_sink_shows_queued_notifications_in_the_window`.
- Fluent catalog test: `every_string_id_the_notify_module_uses_is_in_the_catalog` (also fails on unused ids).
- Titles never include machine names: `titles_are_generic_and_carry_no_machine_name`.
- "Each test fails without the change": the module and tests are new, so without the change they fail to compile.

- id: M3-013-shell-hookup
  lane: client
  title: Wire Notifier, ToastSink and deep links into AppShell
  detail: >
    In shell/**. Build one EventQueue and one ToastSink; give a clone of the sink to
    Notifier::new(&NotifyConfig{prefs_path}, Box::new(sink.clone())).
    On the first inbox fetch call notifier.seed(rows.map(|r| (id, status))); afterwards call
    notifier.observe_all(...) on every inbox refresh and observe(thread, status) from the open
    thread's snapshot.
    Call notifier.set_focused(open_thread_id) when the open thread or window focus changes
    (None when the window is in the background).
    Each frame or tick, call sink.flush(window, cx) and drain events.drain();
    NotifyEvent::Open{thread_id} maps to AppShell::open_thread.
    Mount NotifySettingsView::new(notifier.prefs().clone()) in Settings.
    For deep links call hub_link_thread(url, &hub) on an opened URL and then open_thread.
  depends_on: [M3-013]
- id: M3-013-failed-status
  lane: client
  title: Surface a `failed` thread status to the notifier
  detail: >
    inbox::Status parses only idle/running/needs_you/done and maps everything else
    (including a failed run) to Idle. Pass the raw hub status string to Notifier::observe,
    or add Status::Failed. Confirm with client-api.md §5.2 which status string the hub
    reports for a failed run, because the Notifier matches "failed".

    The repo defines no custom scheme, so hub_link_thread parses hub https links only.

    MimeType). Once a scheme exists, extend hub_link_thread.
