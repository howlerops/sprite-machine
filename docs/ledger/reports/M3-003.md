# M3-003: client: onboarding + empty states

## Summary

- New `onboarding` module (plan §3 surface 0). With a signed-in session, a loaded machines feed that is empty (not failed) and an empty loaded inbox, the Inbox page shows onboarding instead of the list. Path (c) shows the exact commands (`sm login --hub <hub>`, `sm rc`), what to expect (QR code, a `session:` line, space bar re-shows the QR) and a waiting line, with Copy buttons. Paths (a) model API key and (b) BYO A2A URL are shown with disabled buttons and Fluent reasons naming M2-002 (P4) and M2-004 (P5). Flip `MODEL_KEY_API_AVAILABLE` / `BYO_URL_API_AVAILABLE` to enable them.
- Completion: when the shell's machines feed reports a machine, onboarding is done for the session (sticky; it does not return if the machine later disappears) and the Inbox page shows. A failed machines fetch is never mistaken for "no machines". A user who already has threads but no machine goes straight to the inbox. A "Skip for now" button ends it.
- Every list got an empty state with one primary action (table below).
- The branch was not at `v2` and had no commits of its own, so it was reset to `v2` first.

## Empty states and their primary action

| List | Empty text | Primary action (element id) | Effect |
| --- | --- | --- | --- |
| Inbox, no tasks | "No tasks yet. Start one with New task." | New task (`inbox-empty-action-new`) | `InboxEvent::NewTask`; shell opens the composer with the cursor in the prompt |
| Inbox, emptied by filters or search | "No tasks match." | Clear filters (`inbox-empty-action-clear`) | resets status, agent, workspace, search and refetches |
| Agents table | "No agents yet. A machine lists its harnesses after it connects to the hub." | Connect a machine (`no-agents-action`) | `AgentsEvent::SetupMachine`; shell shows the onboarding steps |
| New task, no machines | "No machines yet. Run sm rc on a computer to add one." | Connect a machine (`no-machines-action`) | `ComposeEvent::SetupMachine`; shell shows the onboarding steps |
| Transcript of an empty thread (only header rows) | "Nothing here yet. The agent's messages and tool calls appear as they arrive." | Write a message (`empty-thread-write`) | `TranscriptEvent::WriteMessage`; shell puts the cursor in the thread composer |
| Command palette, no match | "No matching commands" | Clear search (`palette-empty-action`) | empties the field and the model query, all commands show again |
| Machines page | not listed: `Section::Machines` is still the generic placeholder (see discovered work); the machines list is surfaced through the Agents table and the composer's machine choice, both covered above | | |

## Notes

- The onboarding page appears only on the Inbox page with no thread open, so the sidebar (Settings, sign out, other pages) stays reachable. The existing `tests/shell.rs` needed no change.
- `show_setup` is a no-op once a machine has been seen.
- A transcript counts as empty when every row is a header row (a loaded thread always has title/mode/presence header rows). The empty block is placed under those rows.
- `set_value` on the palette's input does not emit a change event, so `clear_query` tells the model directly.
- Process: git commands containing compound forms were refused by the sandbox wrapper; each was run separately.
