# M1A-007 report: permission / elicitation ⇄ Interrupt, cancel races

## Summary

- `session/request_permission` and `elicitation/create` (form -> `Interrupt{form}` with `response_schema`; url -> `Interrupt{auth}` with `url`) become Interrupts; the `approval` command answers ACP per the tunnel.md §3.5 outcome table.
- `protocol::tunnel::Outcome` now has `selected{option_id}`, `submitted{data}`, `declined`, `cancelled`.
- Mismatched outcome: ACP is answered cancelled/cancel and `command_result invalid`. A second or post-cancel/expiry answer: `unknown_interrupt` (hub maps to 409).
- Cancel while paused follows §4.9 (InterruptResolved{cancelled}, resume RunStarted, RunError{cancelled}); a form/url elicitation parked in the handler is dropped on cancel/expiry/task end, which answers ACP cancel.

## Files changed

- `crates/sidecar/src/bridge/permission.rs` (new: interrupt registration, `on_permission`, `approve`, permission outcome mapping)
- `crates/sidecar/src/bridge/elicitation.rs` (new: `on_elicitation`, elicitation outcome mapping + unit test)
- `crates/sidecar/src/bridge/handler.rs` (`Internal::Elicitation`, parked-reply table; no more auto-cancel)
- `crates/sidecar/src/bridge/runtime.rs` (approve/on_permission moved out, helpers `pub(super)`, parked cleanup on expiry and task end)
- `crates/sidecar/src/bridge/mod.rs` (module declarations only)
- `crates/protocol/src/tunnel/types.rs` (`Outcome` extended)
- `crates/sidecar/tests/permission.rs` (10 tests)
- OUT OF SCOPE, forced by the `Outcome` extension: `crates/hub/src/tracer/state.rs` (+2 match arms mapping `Submitted`/`Declined` to the same `ResolvedOutcome` variants; the exhaustive match no longer compiled). If M2B-002 lands the same change, drop this hunk.

Design note: mod.rs may only get module declarations, so `PendingApproval.reply` stays a permission-typed sender. An elicitation registers a placeholder there (for ttl, expiry, cancel and reconcile bookkeeping) and parks its real reply, with its kind, in the handler (`park` / `take_parked`).
