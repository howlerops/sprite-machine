# WEB-006 report: GitHub sign-in and members screen (web)

## Summary
- "Sign in with GitHub" on the sign-in page: S256 PKCE, random verifier and state kept only in sessionStorage, redirect to `/v1/auth/github/authorize`; the return at `/#/auth/github?code=&state=` is read once, the address is cleaned with `history.replaceState` before anything else, then code + verifier are traded at `/v1/auth/github/token`; the session is stored directly.
- A `#/members` screen (Members button in the session list bar): everyone sees the list; admins and owners also invite by GitHub login with a role, revoke open invites, change roles (never above their own) and remove members (two taps).
- Test support: a stateless mock GitHub (authorize, token, user) started by `helpers-hub.sh`; the hub there gets `GITHUB_CLIENT_ID`, a random per-run `GITHUB_CLIENT_SECRET` and `GITHUB_API_BASE` as `--var`.

## Criteria
1. GitHub sign-in against the mock GitHub ends with a working session; verifier stays in sessionStorage; code read from the fragment and removed from history: MET.
   - `signin_github.spec.js` "ends with a working session; the verifier stays in sessionStorage and the code leaves the address": the stored session has the invite's role and works on `/v1/members`; the verifier is written once, to sessionStorage only, never to localStorage; it is the S256 pre-image of the challenge of the authorize request; it is in no URL and only in the body of the single token POST; sessionStorage is empty afterwards; the page URL and the history entry before it carry no `code=`/`state=`.
   - "an account with no invite is turned away": `error=access_denied` gives a notice, no session, nothing left in storage.
   - "a return with the wrong state, or a second return, trades nothing": a forged state is refused with no token request, and the pending verifier is burned so the right state cannot be used afterwards.
2. Admins list members, invite by login, change roles, remove; viewers see the list only: MET.
   - `members.spec.js` "an admin sees everyone, invites by GitHub login, changes roles and removes members": list, invite (+ 409 shown), revoke, role change confirmed on the hub, remove (session of the removed member is 401 at once), no controls on own or owner row, no role above own offered.
   - "a viewer sees the list and nothing to change": no invite form, no invites list, no selects or buttons.

## Notes
- The Playwright hub is one process for all specs, so the GitHub vars are passed to it for every run (random secret, mock on a local port); only these two specs use them.
- The mock's authorize page reads who signs in from a cookie `gh_account=<login>.<id>` set for 127.0.0.1 (cookies ignore the port), so no port needs to reach the tests. It checks client id, S256 challenge and state; the token endpoint checks client id, secret and the hub's PKCE verifier.
- `process.stdout.write` is used to print the free port in `helpers-hub.sh`: Playwright sets FORCE_COLOR, which wrapped `console.log` output in ANSI codes.
