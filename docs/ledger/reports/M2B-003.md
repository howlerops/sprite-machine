# M2B-003 report: sidecar HostMode trait (local | sandbox)

## Summary

- `sidecar::host::HostMode` selects the host mode. `HostKind { Local, Sandbox }` comes from `SM_HOST`. Unset, empty or `local` gives `Local`, which is the default. `sandbox` gives `Sandbox`. Any other value is an error, so a typo never silently runs local.
- `host::from_config(&Config)` builds the mode. `host::from_kind` is the pure form with the kind passed in.
- Both modes return the same `TunnelConfig` (hub URL + credential) from a shared provided method, so there is no mode-specific transport.
- Keep-alive, checkpoints, identity and preview are behind traits, each with a local and a sandbox implementation. The sandbox ones that need the Workspace DO or the hub are stubs that return a typed `NotImplemented` naming the ledger item that fills them.
- `crates/runner` now depends on `sidecar`.

## Design notes

- **Keep-alive** is a guard-based hold. `hold(Hold::Turn | Hold::Approval)` returns a `KeepAliveGuard`, and dropping it releases the hold. `tick()` pings only while a hold is active, and `interval()` gives the cadence. The bridge (M1A-010) will drive the loop.
- **Identity**: sandbox takes `SM_MACHINE_CREDENTIAL` from `Config`, which already reads it into memory and redacts its `Debug`. The sandbox mode fails with `MissingCredential` if it is absent. The `harness_env` filter removes the variable from the env passed to harness children, in both modes.
- **Local identity** loads the credential from an injected `CredentialStore`. `from_config` uses an empty `MemoryCredentialStore` because the OS keychain store is not written yet (see discovered work).
- Async trait methods return `BoxFuture` (a boxed `Send` future), which keeps the traits object-safe without a new dependency.
