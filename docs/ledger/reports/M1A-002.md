# M1A-002 report: acp-mock: scriptable ACP v1 agent

## Summary

- `acp-mock` is an ACP v1 agent over newline-delimited JSON-RPC 2.0. It is a library (`acp_mock::run` over any tokio reader and writer, `acp_mock::Script`) and a binary (`acp-mock --script <path.json>` on stdio).
- Each prompt runs turn N of its session's script. Steps cover chunks, tool calls with diff and terminal content, plan, usage, commands, mode, permission, elicitation (form and url), client terminals, leaked fake keys and stop reasons.
- Every ACP payload is validated against the `protocol::acp` types when the script loads. Every outgoing `session/update` is built from those types, and the tests parse every update back into `SessionNotification`.
- `session/cancel` ends the prompt with `cancelled`, including while the turn waits on a permission, elicitation or terminal answer.
- 11 integration tests pass, one per feature group plus a script-validation test and a real-binary stdio test. Workspace clippy with `-D warnings` and `cargo fmt --all --check` pass.

## Behavior notes

- A prompt past the end of a session's turns fails with a JSON-RPC error instead of inventing a turn.
- A client answer that does not match `expect` fails the prompt with a JSON-RPC error. `expect` takes `any`, `cancelled`, `allow`, `reject` or an option id for permissions, and `any`, `accept`, `decline` or `cancel` for elicitations.
- `session/resume` and `session/load` create the session if the id is unknown. Resume keeps the prompt count. Load does not replay history.
- `session/new` and `session/resume` require `mcpServers` and `cwd`, as the v1 schema does. The mock enforces this.
