# M2B-008: runner: workspace trust prompt + remote-terminal opt-in

## Summary

`sm rc` now checks trust before a session starts in a directory. An untrusted directory asks `Trust <dir>? [y/N]` when stdin is a terminal and the yes is stored in `<state dir>/trust.json` (0600); without a terminal a hub dispatch into it fails with `command_result` `workspace_untrusted` and no agent starts. `/` and the home directory are asked every time and never stored. `sm trust <dir>` / `sm untrust <dir>` manage the store, and trust decisions go to a local audit log (`<state dir>/audit.jsonl`). The remote-terminal setting (`--allow-remote-terminal` / `settings.json`) is read and logged, but it is NOT enforced: the sidecar has no hook to deny `terminal/create`, so criterion 2 is blocked (see below).

## Files changed

- `crates/runner/src/trust/mod.rs` (new): `decide` (the check: stored, asked, refused, or once for home and `/`), `grant` / `revoke` for the CLI, `ask_on` (the question and answer), `terminal_asker`, `remote_terminal_allowed`.
- `crates/runner/src/trust/store.rs` (new): `TrustStore`, the canonical, 0600 list in `trust.json`; home and `/` are never persistable; an unparsable file is an error, not an empty list.
- `crates/runner/src/trust/audit.rs` (new): `Audit`, JSON lines in `audit.jsonl` (`at`, `event`, fields); a failed write is logged, not returned.
- `crates/runner/tests/trust.rs` (new): 12 tests (store, prompt, home/root, canonical paths, audit, remote-terminal setting, and 4 end-to-end dispatches against a fake hub and a stub harness).
- `crates/runner/src/server/router.rs`: `admit` (runs `decide` off the async runtime) before a new session in dispatch and before reopening a stored thread; `-c` checks the last session's directory; `reject` audits `workspace_untrusted` refusals.
- `crates/runner/src/server/mod.rs`: `Options` gains `asker: Option<Asker>` and `allow_remote_terminal: bool`; `RcArgs` gains `--allow-remote-terminal`; `run` builds the store and audit log and logs when remote terminal is allowed.
- `crates/runner/src/main.rs`: `sm trust <dir>`, `sm untrust <dir>`, `--allow-remote-terminal` passed to `sm rc`, and the terminal asker when stdin is a TTY.
- `crates/runner/src/lib.rs`: `pub mod trust;`.
- `crates/runner/tests/server_mode.rs`: `Rig::new` and `Rig::repo()` trust the directories the tests dispatch into (`TrustStore::trust`); `Rig::options` sets the two new `Options` fields (`asker: None`, `allow_remote_terminal: false`). No test assertion changed.

## Acceptance criteria

1. **Met, with one naming deviation.** The code is `workspace_untrusted`, not `untrusted_workspace` as the criterion says. The protocol enum (`CommandErrorCode::WorkspaceUntrusted`) and `docs/specs/tunnel.md` §3.6 already name it `workspace_untrusted`, and I did not change the protocol, so I used that code. Please confirm or correct the criterion text.
   - Prompt and store: `the_first_use_asks_and_a_yes_is_stored_so_the_next_use_is_not_asked` (asked once, stored, file mode 0600). Without a terminal: `a_no_and_a_missing_terminal_both_refuse_and_store_nothing`.
   - Home and `/`: `the_home_directory_and_root_are_asked_every_time_and_never_stored` (asked on each use, `trust` errors, a hand-written entry does not count).
   - Hub dispatch into an untrusted directory: `a_dispatch_into_an_untrusted_directory_fails_with_workspace_untrusted_and_starts_no_agent` (the stub agent never runs).
   - Canonical paths: `trust_is_by_canonical_path_so_a_symlink_resolves_to_its_target`.
   - `sm trust` / `sm untrust`: `sm_trust_and_sm_untrust_manage_the_store_and_each_leave_an_audit_line`.
   - Terminal answers end to end: `answering_yes_at_the_terminal_trusts_the_directory_and_starts_the_session`, `answering_no_at_the_terminal_refuses_the_dispatch_and_starts_no_agent`, and `a_dispatch_into_a_trusted_directory_starts_the_agent` (positive control).
2. **NOT MET. blocked_on: sidecar hook.** The bridge has no terminal policy. `sidecar::bridge::Config` has no field for it, `BridgeHandler::create_terminal` (`crates/sidecar/src/bridge/handler.rs`, around line 176) calls `Terminals::create` with no check, and the ACP client always advertises `.terminal(true)` (`crates/sidecar/src/acp/client.rs`, around line 152). Nothing is refused, so no deny test exists. The runner side is in place: the setting is parsed and logged (`remote_terminal_allowed`, tested in `the_remote_terminal_is_off_unless_the_flag_or_the_state_setting_turns_it_on`). The hook needed is in Discovered work.
3. **Met via the local-log fallback.** The protocol has no runner audit frame: `TurnEvent` has no notice or log variant, and the tunnel `Frame` enum has no audit kind. Decisions are written to `<state dir>/audit.jsonl`. Events: `trust_granted` (`by` prompt or `sm trust`, `persisted`), `trust_declined`, `trust_removed`, `dispatch_refused` (`code: workspace_untrusted`, thread, message). Checked by `sm_trust_and_sm_untrust_manage_the_store_and_each_leave_an_audit_line`, `a_dispatch_into_an_untrusted_directory_fails_with_workspace_untrusted_and_starts_no_agent` (`dispatch_refused`) and `answering_no_at_the_terminal_refuses_the_dispatch_and_starts_no_agent`. The protocol change is proposed below. No protocol file was changed.

## Known limits

- While a terminal question is pending, the router awaits the answer in its command loop, so other commands on this machine wait too. Acceptable for a question a person answers at the machine; a per-session queue would fix it.
- A reopened worktree session is checked against the worktree record's `repo`, which is the repository's top level. If the hub dispatched a subdirectory of a repository, the reopen check looks at a different path than the dispatch did.
- Only server mode (`sm rc`, dispatch, `-c`) checks trust. The interactive `sm` TUI does not.
