# M2-010h: thread list rows carry pending_interrupts, workspace, archived

## Summary

`GET /v1/threads` rows now carry `workspace` (string or null), `archived` (bool) and
`pending_interrupts` (`[{interrupt_id, title, options:[{option_id,name,kind}]}]`).

Where the data comes from: interrupts lived only in the Thread DO's SQLite, not in D1. The
cheapest correct option was to denormalise: migration 0015 adds `tasks.pending_interrupts`
(JSON text, default `'[]'`). The Thread DO already upserts the index row after every `Interrupt`
and `InterruptResolved` event (`changes_index`), so the column is written in the same upsert as
`status` and is exactly as fresh as it. The list query stays one bounded D1 SELECT, with no
per-row DO call. `InterruptRecord` (DO store) gained `title` and `options` (`#[serde(default)]`,
so records stored before this change still load; they list with empty options until resolved).
The reconcile compares `pending_interrupts` too, so rows created before the migration are
backfilled by the hourly reconcile.

Decisions:
- Only approval interrupts are listed. `form` and `auth` interrupts still make the row
  `needs_you` but are omitted from `pending_interrupts` (documented). Rows that are not
  `needs_you` always read `[]`.
- `archived=true` keeps its existing meaning (include archived alongside active; rows carry the
  flag). The client's show-archived toggle sends `archived=true` and filters locally, so this
  matches it. Default excludes archived. Deleted threads never list.
- `workspace` is `workspace_path` already in the index; empty is shown as null.
- Client parsing (`crates/client-gpui/src/inbox/model.rs`, `parse_row`) already reads exactly
  `workspace`, `archived`, `pending_interrupts`, `interrupt_id`, `title`, `options[].option_id/name/kind`.
  No client change was needed and the hub did not have to deviate from it.
- crates/client-core has no thread-list type with these fields, so it is unchanged.
- Files outside the listed paths: `crates/hub/src/db/mod.rs` (register the migration, required by
  the d1_schema test) and `crates/hub/src/threads/{core,store,tests}.rs` and
  `crates/hub/src/dev_fixtures/routes.rs` (the Thread DO builds the index row and stores the
  interrupt options; the dev fixture constructs `IndexRow`). All inside crates/hub/src, none in
  apps/ or packages/.
