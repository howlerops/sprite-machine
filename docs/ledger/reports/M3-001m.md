# M3-001m: step, subagent and raw view models

## Summary
- `Transcript` keeps `StepStarted/Finished` (`Item::Step`, keyed by step_id + iteration), `SubagentStarted/Finished/Error` (`Item::Subagent`, keyed by subagent_run_id, with name, parent/child ids, status and error) and `Raw` (`Item::Raw`, one item per event).
- New variants are additive; existing `Item` variants are unchanged. `apply` stays transactional (nothing in the new arms can fail; `last_seq` is still set last by `ThreadView::apply`).
- First close wins for steps and subagents (a later finish does not reopen or replace an outcome), matching interrupts.
- Breaking side effect outside this item's scope: exhaustive `match item` in `crates/runner/src/tui/render.rs` and `crates/client-gpui/src/task/transcript.rs` no longer compiles until those arms are added (see Discovered work). Found by reading the code; `cargo check -p runner` was not completed (shared build lock held by another process).

## Files changed
- `crates/client-core/src/view/transcript.rs`: new `Item` variants, `StepView`, `SubagentView`, `SubagentStatus`, `RawView`; apply arms; `step_slot` / `subagent_slot`.
- `crates/client-core/src/view/mod.rs`: re-exports; module doc.
- `crates/client-core/tests/view_models.rs`: three new tests.
- `docs/ledger/reports/M3-001m.md`

## Verify output
- `cargo test -p client-core`: exit 0. Unit and integration suites all pass; `view_models` 12 passed (includes the three new tests).
- `cargo clippy -p client-core --all-targets -- -D warnings`: exit 0, no warnings.
- `cargo fmt --all`: only the three files above changed.

## Criteria
"Transcript/ThreadView keep steps and subagents (name, status, parent/child ids, error) and Raw events; tests apply every example and assert none is dropped": MET.
- `steps_subagents_and_raw_events_are_kept_in_order`: applies StepStarted, SubagentStarted, Raw, SubagentFinished, StepFinished and a second subagent that errors; checks order, step fields, subagent ids/status/error, and the Raw payload.
- `steps_and_subagents_upsert_and_the_first_close_wins`: one item per key; later finish/error does not change the first outcome.
- `every_turn_event_example_applies_and_no_step_subagent_or_raw_is_dropped`: applies every file in `crates/protocol/schemas/turn-event/examples` on a shared prologue; each example applies, and each Step/Subagent/Raw example leaves its item.
- Other example kinds (not transcript items by design, such as Presence and StateSnapshot) are covered by the existing tests.

## Limits
- `Raw` has no id, so it is not deduplicated inside `Transcript`; dedupe by `seq` happens upstream in `ThreadView`/sync, as before.
- A finish or error that arrives before its start creates an item with an empty `name`.
- Task status is not changed by steps or subagents.

## Expected follow-on breakage (not fixed here)
- `client-gpui` test `known_gaps_are_still_gaps` now fails, as the brief anticipated; M3-008a handles it.
- Compile breakage not in the brief (by inspection; `cargo check -p runner` not completed): `crates/runner/src/tui/render.rs` `item_lines` and `crates/client-gpui/src/task/transcript.rs` `item_rows` are exhaustive `match item` with no wildcard. Both need arms for `Item::Step`, `Item::Subagent`, `Item::Raw` before the workspace builds. Those files are outside this item's allowed paths.
