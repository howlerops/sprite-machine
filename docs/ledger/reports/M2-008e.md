# M2-008e: thread routes scoped to the caller's org

## Summary
- New D1 table `thread_hosts(thread_id PK, org_id, machine_id)` (migration 0006), written idempotently (first org wins, a foreign org is refused) by `POST /v1/threads`, the Machine DO `thread_open` (org from the machine's DO state, which `POST /v1/machines` provisions from the machines row), and the DEV_FIXTURES init route.
- `authorize_thread` answers `404 not_found` ("no thread <id>") for a thread with no row or another org's row, after the role check and before any audit row or Thread DO call.
- Added a DEV_FIXTURES-only `POST /v1/dev/threads/{id}/host` (mapping only) so seq-counting fixtures (thread_do) need not add an init snapshot to the log.

## Notes
- A role failure (403) is still answered before the org check; it depends only on the caller's own role and reveals nothing about the thread.
- thread_hosts has no foreign keys (dev machines have no machines row).
- Cross-org `thread_open` refusal (Forbidden nack) is implemented in `WorkerHost::init_thread` but has no live test (thread_create's Runner has no thread_open helper).
