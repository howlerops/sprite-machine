# M2B-013 report: dispatch to a chosen machine; Where picker; machines screen

## Summary
Most of dispatch already existed. This item adds what was missing and proves the rest end to end.

### What already existed
- Hub: `POST /v1/threads` (Thread DO create, machine as host, tunnel `dispatch` queued on the Machine DO, delivered after `welcome`; `workspace.spawn` passed through), `GET /v1/machines`, `DELETE /v1/machines/{id}` (revoke), runner `command_result{capacity}` turned into `RunError{code:"capacity"}` by the Machine DO driver (live test `machine_do`), offline queue in the Machine DO, `thread_create.rs` live suite.
- Runner: `check_capacity` refuses with `Capacity`; spawn modes advertised in `hello`.
- Desktop: new-task composer already had the machine picker from the shell machines feed, the spawn picker (`Start in`) and the create request with `machine_id` and `workspace.spawn` (M3-012a); `Section::Machines` existed as a placeholder page; `ThreadRow.machine_id`; thread state `pending_tasks` and queued chips.

### What this item added
- Hub: `PATCH /v1/machines/{id}` rename (did not exist); `workspace.spawn` validation (unknown mode, or a mode the machine did not advertise, is 400 `invalid_request`, nothing queued); live suite `dispatch`.
- Desktop: Where picker gets presence in labels and a11y, a disabled cloud-workspace choice with its reason, and offline machines are now selectable (the hub queues; a note says the task will wait). Machines screen (list, presence, rename, revoke with confirmation) mounted in the shell and sharing its machines feed. Inbox computer icon with a11y label. Task view "Waiting for <machine>" banner with queued items.
- Plan quote for offline behaviour (plan 4.10): "Messages and approval answers sent from the phone are queued on the hub, and delivered in order when the runner reconnects"; "The phone shows 'waiting for my-laptop'".
- Capacity: the hub does not count sessions; the runner refuses (tunnel.md 3.6) and the task fails with `RunError{code:"capacity"}`. Documented in client-api.md.
