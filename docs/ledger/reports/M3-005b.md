# M3-005b report: session and pending-remove intents through the outbox

## Summary
- `client-core` outbox: new `Intent::SetSession { thread_id, mode_id: Option<String>, config: Option<SessionConfig{id,value}> }` (`POST /threads/{t}/session`, body has only the set fields) and `Intent::RemovePending { thread_id, task_id }` (`DELETE /threads/{t}/pending/{task}`, no body). Both get an `idk_` Idempotency-Key at enqueue, persisted and reused on retry, like Prompt/Approval/Cancel.
- `Intent::method()` returns the new `Method { Post, Delete }`; `PostRequest` gained `method` (body is `null` for DELETE). `HttpTransport` sends DELETE without a body. The `Transport::post` signature is unchanged, so existing transports compile as they are.
- 409 handling: `IntentState::Conflict` gained `error: Option<String>` (the hub's error code, serde-default so stored records still load). A `409 task_started` on `RemovePending` is terminal (never retried), counted in `FlushReport.conflicts`, and reported through `Outbox::started_removals() -> Vec<StartedRemoval{local_id, thread_id, task_id}>` (the caller should then cancel). `Outbox::conflicts()` still lists only approvals.
- Composer: `ThreadRequest` removed. `ComposerEvent::Request` replaced by `ComposerEvent::Intent(Intent)`; mode pick -> `SetSession{mode_id}`, model pick -> `SetSession{config}`, queued remove -> `RemovePending`. `ComposerEvent::Cancel(Intent)` is kept.

## Hub check (crates/hub/src/threads)
- `POST /v1/threads/{id}/session` and `DELETE /v1/threads/{id}/pending/{task_id}` are both documented in api.rs as taking `Idempotency-Key`, and run through the same required-key path (`idempotent`: missing -> 400, mismatch -> 422). So the hub honours the key on both routes.
- `DELETE pending` returns 409 `task_started` (core.rs). The hub session route needs at least one of `mode_id`/`config` and checks them against the thread's `session` state (400 `invalid_request` otherwise).
- Discrepancy: routes.rs says deleting a pending task needs **admin**, while client-api.md §5.3 does not state a role. A member's remove will come back 403 and surface as `Rejected`.
