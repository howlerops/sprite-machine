# M1A-006f: tracer respawn, harness-exit ending for every open interrupt

## Summary

- Criterion 1 is NOT MET (blocked_on `crates/sidecar/tests/tracer_bridge.rs`): switching `sidecar::tracer::run` to `spawn_with` changes its signature, and that test calls it with channels. The file is outside the allowed list, so `tracer.rs` and the cli e2e are unchanged.
- Mapper: a request the agent sends while a run is paused is now shown and resolved (`InterruptResolved{cancelled}`) when the task ends. Before, it was queued and dropped with no event. Harness exit and startup ends use the same path.
- Criterion 2 is met with one shape deviation: each queued request is resolved in its own resume run, not all before a single resume (see criterion 2).
- Criterion 3 is met: `acp::reattach::fail_stale_interrupts` is removed; the only `expired` endings left are TTL expiry.

## Acceptance criteria

1. **NOT MET (blocked).** Not implemented. `sidecar::tracer::run` (crates/sidecar/src/tracer.rs) still takes the channels and calls `Bridge::connect`. Changing it to take a command factory and call `Bridge::spawn_with` breaks `crates/sidecar/tests/tracer_bridge.rs` (5-argument call), which is not in the allowed list. Leaving `cargo test -p sidecar` compiling was the priority. Respawn at the bridge level is covered by the existing `bridge_robust::a_subprocess_agent_started_by_spawn_with_is_started_again_after_it_is_killed` (passes, unchanged). Plan once allowed: `run` takes `impl FnMut() -> tokio::process::Command`. The cli factory re-executes its own binary with an env var that makes `e2e::tracer::run` serve acp-mock on stdio, because `cargo run -p cli` does not build the `acp-mock` binary.

2. **MET, with a deviation from the literal wording.**
   - Golden: `golden_acp_turn::harness_exit_two_open_interrupts` (N=2). Output shape:
     `InterruptResolved{int_1, cancelled}` → `RunStarted{resume}` (run_2) → `Interrupt{int_2}` + `RunFinished{interrupt [int_2]}` → `InterruptResolved{int_2, cancelled}` → `RunStarted{resume}` (run_3) → `ToolCallEnd{call_c1, failed}`, `ToolCallEnd{call_c2, failed}` → `RunError{error, harness_exited}`. It passes `validate_sequence` and `validate_complete`.
   - Bridge: `bridge_robust::a_harness_exit_ends_every_open_interrupt_of_the_task_before_the_task_errors` (live: the agent asks for two approvals, the process is killed; asserts two `cancelled` ids equal to the stored open ids, two resumes, no `expired`, `harness_exited`, store empty).
   - Bridge: `bridge_robust::every_interrupt_an_earlier_process_left_open_is_cancelled_at_startup` (two stored interrupts on one task; asserts both `cancelled`, two resumes, `harness_exited`).
   - Fix: `abort` used to resolve only `Phase::Paused.unresolved`. A request buffered by `dispatch` during the pause was never announced or resolved. `abort` now ends the paused run, then shows and resolves each buffered request in its own resume run before `RunError`. Updates buffered before a request are dropped, as the `on_cancel` doc already said.
   - Deviation: the literal "N `InterruptResolved` then one `RunStarted{resume}`" cannot be produced for two requests that arrive one after another. The first request's `RunFinished{interrupt}` pauses the run, and §5 rule 6 buffers later updates until the resume. The second request therefore cannot be announced in the paused run, and the validator rejects an `InterruptResolved` for an interrupt that was never opened. The log above is the closest valid shape. The literal form needs two requests announced in one open run, which needs a spec decision (see Discovered work 2).
   - The new test assertions require an `InterruptResolved` for the queued request. The old `abort` never emitted one (read from the code; not run against the old code).

3. **MET.** `acp::reattach::fail_stale_interrupts` is removed. `grep -rn fail_stale_interrupts crates` finds no code reference; only the ledger and earlier reports mention it. The bridge's own `fail_stale` (in `bridge/runtime.rs`, calling `bridge::stale`) is a different function. Remaining `expired` endings are TTL-only: `expire_overdue_interrupts` (called from `expire_stale`), `expire_live` (bridge timer), and `on_interrupt_expired`. Startup and harness-exit paths end `harness_exited`. Tests that pin this: `interrupts_stored_by_a_previous_process_fail_their_task_at_startup`, `every_interrupt_an_earlier_process_left_open_is_cancelled_at_startup`, `a_dead_agent_fails_running_tasks_and_the_next_prompt_respawns_and_resumes` (all assert no `Expired`).
