# M3-001a report: client-core raw-envelope cache + connectivity from outbox failures

## Summary

- `cache`: the events table now stores the wire text of each envelope. New `Cache::append_raw` (parses each text, stores it byte for byte) and `Cache::raw_events` (returns the stored text in seq order). An `Event::Unknown` envelope is kept as its original JSON, so a newer build can interpret it after a restart. Known envelopes still round-trip. `append_events` is unchanged in behaviour; its doc now says it is lossy for unknown types.
- `outbox`: `Outbox` tracks a `Connectivity`. A transport failure sets `Offline`; any HTTP answer (any status) sets `Online`. Exposed as `Outbox::connectivity()`. It starts at `Connecting`.
- `connectivity`: unit tests drive the outbox with `ManualClock`, a scripted transport and an in-memory cache (no network).

## Files changed

- `crates/client-core/src/cache.rs`: `append_raw`, `raw_events`, private `store` shared by `append_raw` and `append_events`.
- `crates/client-core/src/outbox.rs`: `connectivity` field, `connectivity()` getter, set in `record_response` (Online) and `record_transport_failure` (Offline).
- `crates/client-core/src/connectivity.rs`: `#[cfg(test)] mod tests` with two async tests.
- `crates/client-core/tests/cache_unknown.rs` (new): three integration tests.
- `docs/ledger/reports/M3-001a.md` (this file).
- Not changed: `crates/client-core/src/sync.rs` (see Discovered work for why the one-line change was not needed or possible).

## Criteria

1. **Unknown envelopes cached as original JSON; survive restart; known ones still round-trip** — met.
   - `cache_unknown::unknown_event_is_cached_as_its_original_json_and_survives_a_restart`: file-backed SQLite, written, dropped, reopened; `raw_events` equals the input text byte for byte (the unknown text has deliberate odd spacing and key order to prove it is not re-serialised); the typed event is `Event::Unknown`; `ThreadSync::restore` resumes at seq 2.
   - `cache_unknown::known_envelopes_round_trip_through_the_raw_path`: a RunStarted envelope from the SPEC-001 examples round-trips to the same JSON value and the same typed envelope.
   - `cache_unknown::a_repeated_unknown_event_keeps_the_first_bytes_and_bad_input_stores_nothing`: duplicates keep the first copy's bytes; a gap and malformed JSON are refused and store nothing.
   - Existing tests unchanged and green (`sync`, `queue`, `view_models`, lib).
2. **Outbox transport failures move connectivity to offline; back to online on the next success; injected clock, no network** — met.
   - `connectivity::tests::transport_failure_goes_offline_and_the_next_answer_brings_it_back`: `ManualClock` at 1000 ms, transport error → `Offline` with a banner; at +499 ms nothing is sent and the state stays `Offline`; at +500 ms a 200 → `Done`, `Online`, no banner.
   - `connectivity::tests::an_error_status_from_a_reachable_hub_is_online`: after an offline failure, a 503 answer sets `Online` (the hub replied; the intent is retried).

## Discovered work

Spec issue 5 (M3-001) is only partly closed by this item. The cache can now hold unknown events verbatim, but the subscription driver does not pass the wire text to it.

```yaml
- id: M3-001e
  title: "client-core: Subscription exposes the raw frame text of each event so consumers persist it with Cache::append_raw"
  why: "Applied::Event carries only the typed Envelope, so a consumer persisting from the live subscription still stores {type: Unknown}. Fix needs Applied::Event to carry the text, which changes tests/sync.rs (outside M3-001a's allowed files)."
  depends_on: [M3-001a]
- id: M3-001f
  title: "client-core: one connectivity banner state merging the subscription and the outbox"
  why: "Subscription::connectivity() and Outbox::connectivity() are separate. A banner needs one state: Offline if either is Offline, Connecting if either is Connecting, else Online. Not done here: it is a UI-facing policy decision."
  depends_on: [M3-001a, M3-001b]
```
