# M3-002 report: desktop shell, login, settings, navigation, theming, i18n

## Summary

- `crates/client-gpui/src/shell/` now holds the app shell: login (device-code pairing with a QR code, or GitHub OAuth PKCE through the system browser with a loopback redirect), sidebar navigation, a settings page (theme, language, hub, account, sign out), light/dark theming and a Fluent catalog.
- Logic is plain Rust and tested without a window: `ShellModel`, `LoginModel`, `pairing`, `pkce`, `i18n`, `nav`, `prefs`, `session`. `AppShell` is the thin GPUI view.
- The PKCE loopback listener and both token exchanges run against a local fake hub in the tests; the browser launch goes through the `Browser` trait (`RecordingBrowser` in tests).
- The branch was not at `v2` and had no commits of its own, so it was reset to `v2` first.

## Notes

- Views never touch tokio: `LoginDriver` runs a flow on its own thread with a current-thread runtime and the view polls it every 100 ms.
- Not wired in this item (outside the allowed files): the shell holds a `Connectivity` value and shows the banner, but nothing feeds it from a `client_core::Connection` yet; the "New task" page is a placeholder.
