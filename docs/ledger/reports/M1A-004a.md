# M1A-004a report: sidecar terminal/fs hardening

## Summary
- `terminal/kill` signals the child's whole process group (the child leads its own session on the PTY) with SIGHUP, then SIGKILL after 2 s if any member of the group is left. Uses `nix::sys::signal::killpg` (safe API, no `unsafe`).
- `fs/read_text_file` and `fs/write_text_file` now do all I/O through a `cap_std::fs::Dir` opened on the canonical root. No check-then-use gap remains.
- A failed `Terminals::create` (reader clone, reader thread or waiter thread) kills the child's group, reaps the child, and ends its threads. Failures are injected with a public `SpawnHooks` trait and `Terminals::with_hooks`.

## Decisions and behaviour changes
- cap-std refuses every absolute symlink, even one pointing back into the root, which `fs_follows_symlink_that_stays_inside_root` needs. So `Workspace::confined` first expands symlinks left to right (absolute targets under the root are re-based, others refused), then the I/O goes through the capability `Dir` again. The walk is advisory; the guard is the capability lookup, which still refuses any escape if the tree changes after the walk.
- FsError kinds are unchanged. Two edge changes, documented in the `fs.rs` module docs: (a) an absolute path must be lexically under the canonical root (an absolute alias of the root through a symlink is `Outside`); (b) a dangling symlink that points inside the root is followed and its target created (it used to be `DanglingSymlink`). A dangling link pointing outside is still `DanglingSymlink`, an outward link `Outside`.
- `Workspace::resolve` stays path-based and is used only for a terminal's `cwd`.
- Kill escalation does not end when the leader exits: it ends when the group is empty (probe with signal 0), else SIGKILL at 2 s. This also kills grandchildren that ignore SIGHUP.
- The reader thread now waits for a start signal so the opening snapshot still goes out before any output, and a failed create emits no activity at all.
- File I/O runs in `spawn_blocking`.

## Security notes
- Confinement comes from `cap-std` (per-component `openat`, no-follow), not from a prior check. The race test covers the swap window.
- Remaining small window: the group SIGKILL after 2 s targets a pgid whose leader may already be reaped; a pid reused as a new group leader inside that window would be hit. Probability is negligible (needs pid wrap within 2 s) and the empty-group probe ends the wait early in the usual case.
- `killpg` refuses pid values <= 1 so the runner's own group or the whole system can never be signalled.
- A hard link or bind mount inside the root is not a symlink and is not addressed here.
