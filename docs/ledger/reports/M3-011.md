# M3-011: client: approval cards (desktop)

## Summary

- `src/approval/` now holds the card: `model.rs` (plain data built from a client-core `InterruptView`, its transcript and an injected `Clock`), `controller.rs` (answers via client-core's `Outbox`, 409/failure sync, local workspace presets), `view.rs` (GPUI widgets that emit `CardAction`s).
- Open approvals are pinned as cards above the transcript; answered ones stay in the transcript as "Allow by Jacob (dev_phone) at 22:01:19 UTC". The old text rows (Options / Expires) are replaced only when the host passes cards (`TranscriptPane::set_approvals`), so `thread_rows` and its existing tests are unchanged.
- The answer is `Intent::Approval{Selected{option_id}}` with the option's own id, queued with a fresh `idk_` key; a 409 becomes "Already resolved by <who> at <time>".
- No hub preset API exists: the `allow_always` preset offer is shown and the choice is recorded locally (JSON file when a path is given); stated on the card.
- Resolution time is the time this client first saw it (client-core does not expose the envelope `ts`); see Discovered work.
