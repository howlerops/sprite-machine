# M2B-015: Desktop app embeds the runner (Connect-to-phone toggle)

## Summary
- `runner::embed::Embedded` (new): the runner as a library for a host with no terminal. One machine tunnel to the hub (stored login via the runner's own `CredentialStore`/`KeychainCredentials`), a command router, and local sessions built on the TUI engine (`tui::session::Session` over a `Bridge`). `connect` registers a session with the hub (`thread_open`, then its log, then each new event); `disconnect` stops sending and makes the router refuse its commands (`unknown_thread`). A `dispatch` is refused (`unsupported`).
- `client_gpui::local`: `LocalRunner` (own tokio runtime; async methods plus `spawn`/`snapshot` for the view), `PhoneLink` (plain-Rust model: global auto-connect and one switch per session), `PhoneSettingsView` (Settings section "Phone"), Fluent strings in `locales/en/local.ftl`.
- Shell mount kept small: `Preferences::connect_to_phone_auto` (persisted), `ShellModel::set_connect_to_phone_auto`, and in `view.rs` one entity field, one subscription, one `.child(...)` and a getter.

## Files changed
- crates/runner/src/embed.rs (new), crates/runner/src/lib.rs (`pub mod embed`)
- crates/runner/src/tui/host.rs: `TunnelUpstream`, `now_ms`, `http_base`, `command_thread` made `pub(crate)`
- crates/runner/src/tui/session.rs: `Session::take_feed` (a host with no screen must drain the feed)
- crates/client-gpui/src/local/{mod,model,runner,view}.rs, crates/client-gpui/locales/en/local.ftl
- crates/client-gpui/src/shell/{prefs,model,view}.rs
- crates/client-gpui/Cargo.toml (`runner` path dependency; dev: `acp-mock` path, `tempfile`), Cargo.lock
- crates/client-gpui/tests/local.rs (new)

Runner change and why: no entry point existed that runs sessions without a terminal and shares one tunnel between several of them (`tui::host::Link` is private and single-session; `server::run` is dispatch-only). `embed.rs` is that entry point; it also keeps `sidecar` out of client-gpui's dependencies.

- `cargo test -p client-gpui --test local`: 9 passed (1 ignored: the stub agent).
- `cargo test -p runner`: pass (all suites ok)
- `cargo clippy -p client-gpui -p runner --all-targets -- -D warnings`: pass
- `cargo fmt --all -- --check`: pass
- During development the settings page test `pairing_shows_a_qr_and_the_code_then_signs_in_and_signs_out` failed because the Phone section pushed the Sign out button out of view; the section is mounted below the account actions.

## Acceptance
1. Desktop runs the runner in-process, starts/stops server and tunnel with the device credentials: MET. `LocalRunner::start/stop`, credential only through `runner::login::CredentialStore` (never logged or written). `a_session_is_visible_to_the_phone_only_while_it_is_connected` (hello seen, `stop` -> Stopped), `a_computer_that_was_never_enrolled_says_so_and_connects_nothing`.
2. Persisted global "Connect to phone automatically" and per-session toggle: MET. `the_global_setting_is_persisted_with_the_preferences`, `auto_connect_connects_new_sessions_and_existing_off_ones`, `a_session_connects_and_disconnects_with_its_switch`, `a_connect_that_finishes_after_the_switch_went_off_is_undone`, `a_failed_connect_is_shown_and_the_switch_tries_again`, `auto_connect_shares_new_and_existing_sessions_without_a_toggle`.
3. Connected session appears in the hub thread list; not otherwise: MET with a stated limit. `a_session_is_visible_to_the_phone_only_while_it_is_connected`: two local sessions, `GET /v1/threads` of the fake hub is empty, then lists only the connected one; a phone prompt reaches the agent and its events reach the hub; after disconnect no new events arrive and a phone prompt gets `command_result unknown_thread`; the never-connected session is never listed. Limit: tunnel.md has no frame that removes a thread, so a thread that was connected stays on the hub after disconnect (see M2B-015a).
4. Fluent strings with a catalog test: MET. `every_phone_string_the_code_uses_is_in_the_catalog_and_none_is_dead`.
5. Each test fails without the change: they use `runner::embed`, `local::*` and `Preferences::connect_to_phone_auto`, none of which exist before.

Hub used in the integration test: an in-process axum fake that speaks the tunnel (hello/welcome, acks, `thread_open`, `event`, `command_result`, down `command`) and serves `GET /v1/threads`. A real hub (workerd, `scripts/hub-test.sh`) is too heavy for `cargo test -p client-gpui`. The harness is the acp-mock stub `opencode` on a private PATH, as in `crates/runner/tests/server_mode.rs`.

## Limits
- The desktop has no UI that starts a local session yet, so the per-session toggles are listed in Settings (sessions from `LocalRunner::open_session`).
- The "Phone" view and the shell mount are not covered by a rendered-window test; the model, runner and persistence are.
- The embedded runner and a standalone `sm`/`sm rc` on the same machine id share one machine tunnel and supersede each other.
- Machine enrollment is not driven from the app: without `sm login` the Phone section says the computer is not enrolled.
