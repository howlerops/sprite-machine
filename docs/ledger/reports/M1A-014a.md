# M1A-014a: Attachments follow-ups

## Summary

- Image parts are sniffed: the bytes must start with the png/jpeg/gif/webp magic (WebP also checks `WEBP` at offset 8) or the attachment fails with `attachment` (`AttachmentError::ImageMismatch`) before any image block is built.
- A bridge test (acp-mock behind a recording relay) shows a failed attachment fetch ends the task with `RunError{code:"attachment"}` and that acp-mock receives no `session/prompt` for it.
- No change to `runtime.rs` or `mod.rs`: the failing URLs are refused by the production default policy, so no test injection was needed.

## Files changed

- `crates/sidecar/tests/files.rs`: fixtures for JPEG, GIF, WebP and mismatched bodies; 3 new tests.
- `crates/sidecar/tests/bridge_attachments.rs` (new): 1 test.
- `docs/ledger/reports/M1A-014a.md` (this report).

## Acceptance criteria

1. **Met.** `bridge_attachments::a_failed_attachment_fetch_ends_the_task_and_the_agent_never_gets_the_prompt`. Two failing prompts (`http://` URL, then `https://127.0.0.1` URL) each end with a `RunError` whose code is `attachment`. The error message does not contain the signed query. The recorder shows acp-mock received no `session/prompt` for them: a later text prompt is the only one, `prompts == 1`. The recorder is live, since that prompt reaches `session/prompt`, and the count would be 3 if the failed tasks had been submitted.
2. **Met.**
   - Match, all four types: `files::each_image_type_with_matching_bytes_becomes_an_image_block`.
   - Mismatch, four cases (text as png, gif as png, png as jpeg, wav as webp): `files::image_bytes_that_do_not_match_the_declared_type_fail_with_the_attachment_code`.
   - Per-type magic: `files::image_magic_is_checked_per_type`.
   - The mismatch test fails with the sniff disabled (`if false && ...`, `1 failed`), then passes once restored.
