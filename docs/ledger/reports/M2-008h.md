# M2-008h: subscribe ticket for browsers (SPEC-006)

## Summary
- `POST /v1/threads/{id}/subscribe-ticket` (viewer+, through `authorize_thread` / `thread_policy`, no audit action) returns 201 `{ticket, expires_at}`: `sst_` + 256 random bits, SHA-256 only stored, 60 s TTL, bound to session, user, org and thread.
- `GET .../subscribe?ticket=` with no Authorization header consumes the ticket with one conditional `UPDATE` (exactly one winner), rebuilds the principal from the live session (revoked session/device or removed member is refused) and re-checks the thread's org. Every failure is the same 401.
- The Worker strips `ticket=` from the URI before it reaches the Thread DO; the access log only logs `uri().path()`, never the query.
- Migration `0013_subscribe_tickets.sql`. Dev (`Bearer dev`) tickets have `session_id NULL` and work only with `DEV_FIXTURES=1`.
