# M1B-004b — gpui spike: diff pane (gpui-kit editor)

## Summary
The diff pane is a `DiffPane` view over gpui-kit's `Diff` component (a GPUI `list`, so only visible rows are laid
out). The rows come from the `diff-5k` fixture: its chunked `Activity{diff}` envelopes are reassembled by a pure model,
turned into a unified patch by a pure LCS line diff, and parsed with the component's `DiffFile::parse`. Syntax highlighting
is on for `src/generated.rs` (`rust`) through gpui-kit's `syntect` feature. The headless test lays out 26 of 5,000 source
rows, shows line 1 at the top, and after a 1,000-row wheel scroll shows line ~1,000 at the top.

## Acceptance criteria
1. **Met.** `DiffPane` (`diff_pane.rs`) renders the reassembled diff-5k file as a unified diff. `reassemble_diffs`
   folds the 5,000 lines of chunks, `unified_patch` writes the hunk `@@ -0,0 +1,5000 @@` with `+` lines, and
   `DiffFile::parse` reads it. Unit tests: `diff_fixture_reassembles_to_5000_added_lines`,
   `diff_fixture_parses_into_one_rust_file_with_5000_additions`, and the `diff_model` tests (LCS, hunks with 3 context
   lines, gap and order errors). The view is virtualized: `Diff` lays out only the visible rows.
2. **Met.** Syntax highlighting comes from gpui-kit's **`syntect`** feature (regex highlighter, about 200 languages
   through `two-face`). `Diff::syntax_highlight(true)` is set, and the language resolves to `rust` for `src/generated.rs`
   (asserted in `diff_fixture_parses_into_one_rust_file_with_5000_additions`). `tree-sitter` is not enabled.
3. **Met.** `tests/diff_headless.rs::diff_pane_virtualizes_and_scrolls_the_5k_line_diff` (`#[gpui_kit::test]`):
   - Renders a frame and checks that `find_all("source")` returns 26 laid-out rows (limit 200 of 5,000). The first
     visible row is `// generated line 0001: …`, and line 5000 is not laid out.
   - Measures the row pitch from two laid-out rows and wheel-scrolls down 1,000 rows. The first visible row is then
     line 950–1050, and line 1 is no longer laid out.
   - The hunk header row has no element id in the vendored component, so the headless test does not see it. The header
     text is checked in the pure model instead (`diff_fixture_reassembles_to_5000_added_lines` asserts the
     `@@ -0,0 +1,5000 @@` line).

## GPUI API notes vs CONVENTIONS.md
- `Diff` (`gpui_kit::component::diff`) is the diff view that §7 names "diff view"; it is a GPUI `list`, not an `Input`
  or `CodeEditor`. Use `DiffState::new(files, cx).with_mode(DiffMode::Unified)` and `Diff::new(&state)`.
- `DiffFile::parse(&str)` takes a unified patch. It is the only public constructor from text.
  `DiffState::list()` and `rows()` are `pub(crate)`, so tests cannot read the list offset. Visibility is checked through
  the row elements instead: `.id("source")` with the source line as aria label, which `Diff` sets itself.
- Gutter elements are `.id(("line", ix))`. The list is `diff-body`/`diff-horizontal` and carries no id that a test can
  scroll; scrolling `diff-pane` (the outer wrapper) works because `window.scroll` targets the centre of the observed
  element.
- Gotcha: `use super::*;` in a `#[cfg(test)] mod tests` that also imports gpui pulls gpui's `test` attribute into scope
  and shadows `#[test]`. It failed with "recursion limit reached while expanding `#[test]`". Import the items explicitly
  instead.
- `Envelope::new(thread, task, run, ts, event)` builds envelopes without a sequence number (`ThreadSeq::stamp` is only
  needed for logs).

## Discovered work
- Expose the diff's list offset, or the hunk-separator row id, in gpui-kit so tests can assert the hunk header on screen
  (currently it is checked in the pure model only).
- Wire `DiffPane` into the shell next to the transcript (not in scope for this item).
- Split-mode (`DiffMode::Split`) is not exercised here; the spike covers unified only.
- `unified_patch` is a basic LCS (O(n·m) cells, capped at 16M; above the cap it falls back to one delete block followed by
  one insert block). Replace it with a proper Myers diff if large rewrites are shown in the real app.
