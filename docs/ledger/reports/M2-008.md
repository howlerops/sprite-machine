## Spec issues (most literal reading taken)

1. **`DEV_FIXTURES` under `scripts/hub-test.sh`.** The script starts `wrangler dev` without `--env dev`, so `[env.dev.vars] DEV_FIXTURES="1"` does not apply and the live test could not authenticate. Not allowed to edit the script or wrangler.toml, so I added `crates/hub/.dev.vars` (`DEV_FIXTURES=1`; wrangler dev loads it, `wrangler deploy` ignores it). Leader: confirm, or move the var into the script (`--var DEV_FIXTURES:1`).
2. **`router.rs` vs `worker.rs`.** Routes are registered in `worker.rs`, which is not in my allowed list; I made the one-line `.merge(crate::threads::routes::thread_routes())` there and kept all handlers in `threads/routes.rs`. `router.rs` untouched.
3. **Cancel of a started task whose `prompt` command was never acked** (client-api §5.5 says the runner emits `RunError{cancelled}`): the §5 validator only accepts `RunError` inside an open run, so the DO retracts the undelivered `prompt` command and emits `RunStarted{prompt}` + `RunError{cancelled, code:"cancelled_before_start"}` itself. If the prompt command was already acked, it queues a `cancel` command instead. Cancel of a task still in the pending queue just removes it (it has no `UserMessage`, so no valid `RunError` can exist): 202 `{"status":"cancelled"}`.
4. **Cancel of a task paused on an interrupt**: the DO resolves its interrupts `cancelled` (resolved_by = the canceller) as instructed, but the validator then has no open run for a `RunError`; the runner must resume and error. Also, a runner that later sends its own `InterruptResolved{cancelled}` for those ids is nacked (422).
5. **Tunnel `Outcome`** (tunnel.md §3.5) only has selected/cancelled: a `submitted` form or `declined` answer is recorded as the event, and the `approval` command carries `cancelled`.
6. **Idempotency**: only 2xx answers are stored (a failed attempt may be retried under the same key). The request hash covers method, path and canonical body.
7. **Lazy thread creation**: prompts to an unknown thread id work (no org/role model yet, no `POST /v1/threads` in this item); `GET /v1/threads/{id}` is 404 until the thread has events or an `init`. Thread creation must call the internal `init` hook.
8. **`?after` beyond head** is clamped to the head. WebSocket auth uses the `Authorization` header only (browsers cannot set it; a later auth item must pick `Sec-WebSocket-Protocol` or a ticket).
9. **Redaction** (turn-event §2) is not implemented (not in this item's acceptance); see discovered work.
10. The 403 role check (viewer) is not implemented (no roles yet).

## Internal hooks for M2B-002 (Machine DO)

All through a THREAD DO stub (`env.THREAD.id_from_name(thread_id)`), path carries the thread id; not exposed by the Worker:

- `POST /internal/threads/{id}/events` body = one envelope (`seq: 0`) or `{"envelopes":[...]}` -> 200 `{"stored":[stamped...]}`; errors use the client-api error body (422 `invalid_sequence`, 413 `too_large`, 400 `invalid_request`); map to tunnel `nack`. Dedupe by tunnel `event_id` stays the Machine DO's job. Appended envelopes are broadcast to subscribers.
- `GET /internal/threads/{id}/commands?limit=N` -> `{"commands":[{"id","idempotency_key","issued_at","machine_id","command":<protocol::tunnel::Command>}]}`: unacked commands, oldest first (`prompt` when a task starts, `approval` for an accepted answer, `cancel`).
- `POST /internal/threads/{id}/commands/ack` `{"ids":[..]}` -> `{"acked":n}`: call when the runner acked the command frame. Unacked `prompt` commands of a cancelled-before-start task are retracted by the DO, so re-list before (re)sending after a reconnect.
- `POST /internal/threads/{id}/init` `{machine_id, agent, workspace, permission_mode, title}`: stores thread info (used for `machine_id` in the outbox and `GET /v1/threads/{id}`) and publishes `StateSnapshot{thread}`. Thread creation (`POST /v1/threads`) must call it.
- There is no push to the Machine DO yet: it must poll `commands` (for example when a prompt/approval/cancel hits the Worker, or on tunnel connect) until a notification is added (see discovered work).
- Presence: append a `Presence` envelope through `events` (thread-scoped).
