## Test design
- Two prompts go up so the test shows the refusal names the nacked frame's task, not the first line's.
- The hub acks seq 1 before nacking seq 2. This order is deliberate: a nack is cumulative in `protocol::tunnel::seq::Sender` (`on_nack` → `drop_through`), so nacking seq 2 while seq 1 is unacked would also drop seq 1.
- After the nack: the refusal arrives within 5s (`WAIT`), its message carries the hub's text, the outbox is empty (the nack counts as an ack), and no second refusal is pending (`try_recv` is empty).
