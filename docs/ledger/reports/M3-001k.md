# M3-001k report: a Subscription that starts offline

## Summary

- `Subscription::connect` still returns `Err` when the hub is unreachable, so existing callers are unchanged.
- New `Subscription::connect_or_offline` returns a `Subscription` in state Offline with no socket when the connect fails. Other errors (for example a bad base URL) are still returned.
- `Subscription::reconnect` retries it, so a `Connection` built on it publishes Offline at startup and then Connecting and Online once the hub is live.
- The new test `an_unreachable_hub_starts_offline_and_reconnect_brings_it_live` needs `connect_or_offline`, so it does not compile without this change.

## Files changed

- `crates/client-core/src/sync.rs`: `connect` now builds through a private `detached` constructor (no behaviour change); new `connect_or_offline`.
- `crates/client-core/tests/banner.rs`: new test `an_unreachable_hub_starts_offline_and_reconnect_brings_it_live`.
- `docs/ledger/reports/M3-001k.md` (this file).

## Criterion

- Met: "Connection::new with an unreachable hub publishes Offline, and a later reconnect to a live hub publishes Connecting then Online". Test: `an_unreachable_hub_starts_offline_and_reconnect_brings_it_live` in `crates/client-core/tests/banner.rs`. It checks the initial Offline state and banner, then the Connecting state after `reconnect()`, then Online once the subscription is live and the outbox has an answer.
- Note: the outbox only reaches Online after a flush gets an answer (`record_response`). An empty or idle outbox stays Connecting, so the test flushes one intent before asserting Online, as the existing banner test does.
