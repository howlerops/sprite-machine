# M3-007 report: desktop inbox

## Summary

- `crates/client-gpui/src/inbox/` is a plain-Rust `InboxModel` (sections, debounced search with an injected `Clock`, filters, optimistic rename/archive/quick-answer with rollback) plus `api.rs` (typed GET/PATCH/POST) and a thin virtualized `InboxView`.
- The view is mounted on the shell's Inbox page; strings are in `locales/en/inbox.ftl`.
- Server rows are kept apart from in-flight operations, so a rollback is dropping the operation.
- Gap: the hub's list rows carry no `pending_interrupts`, `workspace` or `archived` (see Discovered work). The model parses them when present; until then quick Allow/Deny never appears against the real hub.

## Acceptance criteria

- Needs you / Running / Done sections: met. `threads_fall_into_needs_you_running_and_done_in_the_hubs_order`, `empty_sections_have_no_header`, view `the_view_shows_the_three_sections`, `a_long_list_is_virtualized` (400 rows, under 40 laid out, scroll moves the window). `idle` threads are listed under Done.
- Debounced search: met. `search_asks_the_hub_only_after_the_box_is_quiet` (injected clock, restart on each key, fires once), view `typing_in_the_search_box_fetches_after_the_debounce_not_before` (no GET while the clock is frozen, GET with `q=axum` after advancing). `a_late_answer_to_an_older_request_is_dropped` covers stale answers.
- Filters: met. `filters_become_query_pairs_and_changes_are_reported`, `the_list_request_carries_the_filters_and_follows_the_cursor` (status/agent/workspace on the wire, cursor followed), view `status_and_agent_filters_refetch_with_their_query`. Archived threads are shown with the `archived=true` toggle.
- Archive + rename, optimistic with rollback: met. `rename_shows_at_once_keeps_on_success_and_rolls_back_on_error`, `archive_removes_the_row_at_once_and_restores_it_in_place_on_error`, `patch_and_answer_requests_have_the_documented_shape` (PATCH body and path), view `rename_sends_the_title_and_a_refused_rename_is_rolled_back` (500 gives rollback and the hub's message), `archive_sends_the_patch_and_the_row_leaves`.
- Quick Allow/Deny: met against the spec'd shape. `a_quick_answer_uses_the_interrupts_own_option_ids_and_one_key_per_intent` (fake option ids `yes_once` / `nope`, new `idk_` key per intent), `an_approval_someone_else_resolved_is_not_put_back` (409), `an_approval_without_allow_or_reject_options_has_no_quick_answer`, `patch_and_answer_requests_have_the_documented_shape` (Idempotency-Key header equals the request's), view `quick_allow_and_deny_answer_with_the_interrupts_own_option_and_a_key`. Conditional on the hub reporting `pending_interrupts` (below).
- Strings: `every_string_id_the_inbox_uses_is_in_the_catalog`.

## Notes

- Thread titles and paths from the hub are rendered only as text.
- One list fetch follows at most 5 pages of `next_cursor`.
- After every write the list is refetched, so the hub is the final truth.
- PATCH sends an `Idempotency-Key` too (the spec requires it only for POST/DELETE).
