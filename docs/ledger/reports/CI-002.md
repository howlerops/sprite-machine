# CI-002 report: per-worktree hub wasm target dir

## Summary

- Status: BLOCKED on disk space. The code change is in and clippy passes, but `hub-test.sh smoke` and `cli e2e tracer` could not run: `worker-build` failed with `No space left on device` in the new per-worktree wasm dir.
- `scripts/hub-test.sh` and the tracer's `build_hub` / `Wrangler::start` now build the wasm32 hub into `$CARGO_TARGET_DIR/wasm-<16 hex of sha256(checkout root)>`. Native builds keep the shared dir.
- The build log must name `(<this worktree>/crates/hub)`; the check is `CARGO_TERM_VERBOSE=true`, which makes cargo print `Fresh hub v0.1.0 (<path>)` on cached builds too.
- `wrangler dev` reruns the `[build]` command, which now uses the per-worktree dir through `HUB_WASM_TARGET_DIR` (`CARGO_TARGET_DIR` is set on the worker-build step only, so the strip step's `cargo run -p cli` still uses the shared dir).

## Files changed

- `scripts/hub-test.sh`: `REPO` via `pwd -P`; `WASM_TARGET_DIR` keyed by the root; `worker-build` runs with `CARGO_TARGET_DIR=$WASM_TARGET_DIR CARGO_TERM_VERBOSE=true`; a grep of the build log for `($HUB_DIR)` fails the run otherwise; wrangler gets `HUB_WASM_TARGET_DIR`. `cargo test -p hub --features live` is unchanged (shared dir).
- `crates/hub/wrangler.toml`: `[build] command` only: `env ${HUB_WASM_TARGET_DIR:+CARGO_TARGET_DIR=$HUB_WASM_TARGET_DIR} worker-build ...`. Unset means the normal target dir (cargo rejects an empty `CARGO_TARGET_DIR`, so a plain `CARGO_TARGET_DIR=$VAR` would break manual `wrangler dev`).
- `crates/cli/src/e2e/tracer.rs` (the shared helper for the tracer and the attachments check): `wasm_target_dir(hub_dir)` (sha2 of the canonical root, first 8 bytes as hex, under `CARGO_TARGET_DIR` or `<root>/target`); `build_hub` sets `CARGO_TARGET_DIR`, `CARGO_TERM_VERBOSE=true`, and fails unless the log names `(<hub_dir>)`; `Wrangler::start` passes `HUB_WASM_TARGET_DIR`; unit test `wasm_target_dir_is_keyed_by_the_checkout_root`.
