# M2-003c: browser sign-in routes + sm rc QR

## Summary
- `POST /v1/devices/signin-links` (machine credential, device-origin only) mints a 256-bit, single-use, 5-minute link bound to the approving user and org; `POST /v1/auth/links/redeem` trades it for a member-capped "web" session (410 `expired` for used/expired/unknown/revoked-machine).
- Browser device-code flow: `POST /v1/auth/device/{code,approve,token}`, own table `browser_pairings`, same RFC 8628 errors and the M2B-005a limits (`devices::limits`, shared counters).
- Sessions gained `role_cap` (migration 0011); the effective role is min(member role, cap).
- `sm rc` asks the hub for a link at start and on SIGUSR1 and prints QR + URL via an output sink; the code never reaches tracing/files.

## Design notes
- The runner cannot know a credential's origin locally; it asks and treats 403 as "no link". Sinks are opt-in (`Options.signin`), so other tests are unaffected.
- Browser session TTL is 7 days (`BROWSER_SESSION_TTL_SECONDS`); spec is silent. Both browser flows cap at member. The browser verification URI is `/pair/device` (page not built yet).
- Max 20 live links per machine (429). Purge also covers links and browser pairings.
- Mid-task, v2's broken `wrangler.toml` (two `[vars]`) blocked hub-test; fixed upstream and merged (v2 d3d8e00). I made no wrangler.toml change.
