# WEB-002: transcript rendering for every TurnEvent variant

## Summary
- Thread view (`#/t/<id>`) renders every TurnEvent variant from a pure model (`transcript.js`) via a safe DOM renderer (`render.js`, textContent only); tool calls, activities, interrupts, subagents, steps and runs upsert by id.
- `thread.js` mints a subscribe ticket (session token in the header only) before every WebSocket open/reopen, subscribes with `?after=<last seq>`, and keeps applied envelopes in localStorage so a reload resumes with no duplicates (dedupe by seq).
- Shows "Waiting for <machine> (offline|asleep)" plus the queued items (`thread.pending_tasks`) while the machine is not online (machine polled every 5 s).
- Dev fixture `POST /v1/dev/fixtures/threads` takes `init: true` to host the thread in the caller's org and run the Thread DO init hook; events go in through the existing `POST /v1/dev/threads/{id}/events`. All dev routes stay gated by `DEV_FIXTURES=1`.

## Notes

- Transcript caches (`sm.thread.*`) are cleared on sign out and on 401.
