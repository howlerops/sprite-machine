# M2B-001a report: protocol: strict tunnel frame parsing + unknown command kind helper

## Summary

- Every tunnel frame and command type rejects unknown fields (`deny_unknown_fields`). `parse_frame` also rejects extra fields on the unit frames `ping` / `pong`, which serde does not check.
- `parse_command_frame(&str)` returns `ParsedCommand::Typed` for a known `kind`, or `ParsedCommand::Unsupported{seq, idempotency_key, issued_at, kind}` for an unknown one, after validating the envelope strictly.
- `ParsedCommand::unsupported_result(up_seq, event_id)` builds `command_result{ok:false, code:"unsupported"}` for the runner.
- All spec JSON examples in `docs/specs/tunnel.md` §3 still round-trip (`tunnel_frames` is green). `envelope` in `event` is not checked.

## Files changed

## Acceptance criteria

1. **Unknown fields and unknown `t` / `kind` are rejected: met, with one explicit check.**
   - `deny_unknown_fields` is on `Frame`, `Capabilities`, `Command`, `Actor`, `ContentPart`, `Outcome` and `Workspace`.
   - serde does not apply `deny_unknown_fields` to the unit variants `ping` / `pong` of an internally tagged enum. `{"t":"ping","extra":1}` parsed through serde alone. `ping` and `pong` are used by `runner` and `hub`, which are outside my allowed paths, so I could not turn them into struct variants. `parse_frame` covers the gap with an explicit check, and the tests exercise it.
   - Tests: `extra_top_level_field_is_rejected_on_every_frame_type` (all 12 frame types), `unknown_frame_tag_and_tag_case_are_rejected`, `extra_field_in_nested_types_is_rejected` (capabilities, workspace, actor, text and file parts, prompt, approval outcome and resolved_by, dispatch, cancel), `known_kind_with_extra_field_is_a_protocol_error`.
   - Known gap: `serde_json::from_str::<Frame>` on its own still accepts extra fields on `ping` / `pong`. Wire code must call `parse_frame`. This is noted in the doc comment on `parse_frame`.
2. **`parse_command_frame` returns `Typed` or `Unsupported{seq, idempotency_key, issued_at, kind}`, and a helper builds the reply: met.**
   - `unknown_kind_is_reported_and_answered_as_unsupported` checks the parse result and the exact JSON of the `command_result{ok:false, code:"unsupported"}` reply, which also validates as a `Frame`.
   - `parse_command_frame_returns_typed_for_a_known_kind`, `typed_command_has_no_unsupported_reply`.
   - `unknown_kind_with_bad_envelope_is_a_protocol_error` (extra top-level field, missing `idempotency_key`, non-object `command`).
   - `input_that_is_not_a_command_frame_is_an_error`.
   - Design note: the `Typed` variant is boxed, so clippy's `large_enum_variant` lint passes. Callers match with `ParsedCommand::Typed(frame)` and then `*frame`.
3. **Spec JSON examples still round-trip; `envelope` is not checked: met.**
   - `tunnel_frames` is green (20 tests).
   - `event_envelope_is_not_checked_here` accepts arbitrary fields inside `envelope`.
