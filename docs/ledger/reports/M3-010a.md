# M3-010a: client: wire DiffView into the task view

## Summary

A diff activity in the transcript now has a summary row (`path: +added -removed`) with a "View diff" action. The action opens a `DiffView` over the transcript pane. The pane re-emits the viewer's open-file request as `TranscriptEvent::OpenFile { path, line }`.

- ACP tool-call diffs reach the view model as `diff` activities (`acp_turn.rs` maps them, with `tool_call_id` in the content). `ToolView.content` holds only text and file parts, so activities are the only diff source there is; both cases are covered.
- The summary row is a new `RowKind::DiffSummary`. Its `Row.view_diff` holds the activity id. It is shown only for a complete diff; a chunked diff still arriving has no action.
- The existing minimal `+`/`-` lines stay under the summary. Existing transcript tests assert on them, so they were not removed.
- Pane API: `set_workspace_root(Option<PathBuf>, cx)`, `view_diff(activity_id, cx)`, `close_diff(cx)`, `open_diff_id()`, `open_diff_view()`. Event: `TranscriptEvent::OpenFile` (exported from `task`).
- The open diff follows the thread: if the activity's content changes it calls `set_input`; if the activity disappears the panel closes. The root can change while it is open.

Why an overlay and not an inline panel: the transcript is a `v_virtual_list` with fixed 22 px rows. Rows are sized up front, and an inline diff needs a variable height (and a nested virtual list inside a virtual list). An absolutely positioned panel over the list (header with path and "Close", then the `DiffView`) leaves every row size unchanged and needs no layout changes. The cost is that the transcript is hidden while the diff is open.

Two existing assertions were adjusted, both for the extra row:
- `long_bodies_are_capped_with_a_more_row`: diff row bound `MAX_DIFF_LINES + 2` became `+ 3` (title, summary, lines, "more").
- `ten_thousand_events_are_virtualized_and_within_budget`: it used `labels[300]` as a row that must not be laid out. Summary rows repeat in the fixture, so it now picks the first row from 300 on whose text is unique.
- The `shell.rs` catalog test only supplies the args `code, detail, user, org, section, choice, uri, minutes, hub`, so the summary string uses `detail` (path), `choice` (added) and `code` (removed).

## Criteria with evidence

- **Summary with "View diff" for diff content:** `a_diff_activity_has_a_summary_row_with_a_view_diff_action` checks the row `src/lib.rs: +2 -1`, `view_diff == Some("d")`, and that the minimal lines are still shown. `a_diff_still_arriving_has_no_view_diff_action` checks the chunked case.
- **Action opens a DiffView in the pane:** `view_diff_opens_a_diff_view_over_the_pane_and_close_removes_it` clicks the action in the window and finds the panel and the diff pane, then clicks Close and finds neither. Before the click neither exists.
- **OpenFile re-emitted with path and line using the root:** `open_file_from_the_diff_is_re_emitted_with_the_workspace_root` sets root `/work/repo`, opens the diff, clicks "Open file", and the pane's subscriber receives `OpenFile { /work/repo/src/lib.rs, 13 }`.
- **No root, no action:** `without_a_workspace_root_the_diff_offers_no_open_file` finds the diff pane but no open-file element, and no event.
- **Fails without the change:** the tests use `TranscriptEvent`, `VIEW_DIFF_ID`, `DiffSummary`, `set_workspace_root` and the other new items, so without the change they do not compile. I did not mutation-test the assertions separately.
- **Existing transcript tests green:** see the adjustments above; the other 12 are untouched.

## Not covered

- Pixel output of the overlay is not checked.
- No keyboard binding to close the panel (Escape).
- Summary counts are computed with `DiffModel::build` on every rebuild of the rows, once per complete diff. For many large diffs that repeats work on every streamed event.
