# M2B-001 report: protocol: tunnel frame types per SPEC-002

## Summary

- Adds `protocol::tunnel` types for every frame in `docs/specs/tunnel.md` §3: `Frame` (tagged by `t`) and `Command` (tagged by `kind`), with round-trip tests against each spec JSON example.
- Adds pure seq/ack state machines `Sender<T>` and `Receiver` (§4.2–§4.4), plus `DedupeWindow` for `event_id` (24 h) and `idempotency_key` (7 days). No IO, clocks or randomness.
- Simulated reconnects (resumed and fresh) show exactly-once delivery; a nack counts as an ack; a gap is an error; replayed commands apply once.
- `ping`/`pong` serialize to the literal `{"t":"ping"}` / `{"t":"pong"}`. The hub builds for wasm32 with no tokio.

## Design choices

- The envelope in `event` is `serde_json::Value`, as the item asked. `parts`, `author`, `resolved_by`, `outcome` and `workspace` use small typed structs where the spec is precise.
- `Sender<T>` is generic over the frame body and does not know about `Frame`. It hands out `(seq, body)`, and the caller builds the frame. This keeps the state machine independent of the wire type.
- `Sender::on_welcome(resumed, peer_cursor)` implements the §3.2 resend rules for both cases.
- `Receiver::on_frame` advances `last` as it returns `Process`. The caller must persist that effect with `last()` before acking (§4.2 step 1). The pure type cannot enforce the transaction.
- `DedupeWindow` is an in-memory model keyed by `now_ms` supplied by the caller. The real store is durable (SQLite or DO storage).

## Spec issues found

1. **§3.5 placeholder.** The `command` example uses `"...": "per kind, below"`. I replaced it with the `prompt` example, as the acceptance criteria asked.
2. **Unknown `command.kind`.** §3.5 says the runner replies `command_result{ok:false, code:"unsupported"}`. A tagged enum cannot represent an unknown kind, so `Command` fails to parse. The runner needs to read the raw `kind` before typed parsing. The spec does not say how this is done.
3. **`presence.reason` optionality.** The spec gives an example with `reason` but does not say whether it is required. I made it required (`String`).
4. **`workspace` shape.** `thread_open` uses `{path, branch}` and `dispatch` uses `{path, spawn}`. The spec does not say which fields are required. I merged them into one struct with optional `branch` and `spawn`.
5. **`ActorKind` and `Outcome`.** Spec lists `user|policy|system|agent` for actors. The only `Outcome` example is `selected`. I added `cancelled` (ACP `RequestPermissionOutcome`), because §3.5 cancel says "open permissions answered `cancelled`".
6. **Strict parsing (§6).** §6 says a frame that does not match the spec is `close{protocol_error}`. Serde ignores unknown fields by default, so this is not enforced yet. The hub edge must add it (for example `deny_unknown_fields` where it works, or a schema check).
7. **Timers are not modelled.** The 50-frame ack batch is in `Receiver::ack_due`. The 200 ms timer, heartbeat timeouts, backoff with jitter and the 10 s welcome timeout are IO or clock concerns, left for the connection layer.
