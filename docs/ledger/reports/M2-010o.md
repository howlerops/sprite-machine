# M2-010o: clients show failed and cancelled

## Summary
The desktop inbox now parses `cancelled` as its own `Status::Cancelled` (it was mapped to Idle), sitting with Done like `failed`. Its filter row gains Failed and Cancelled buttons, and rows label as "Failed" / "Cancelled" from Fluent. On the web, `sessions.js` labels `failed` and `cancelled` (it fell back to Done). Unknown values still show as Done on both sides; the web lookup now uses an own-property check so names like `constructor` cannot leak through. A new web unit test file covers the chips; the desktop tests cover parse, section, query value, filter keys and the rendered row labels.

## Files
- crates/client-gpui/src/inbox/model.rs (`Status::Cancelled`; parse, as_query, Section::of; doc comments)
- crates/client-gpui/src/inbox/view.rs (filter row adds Failed and Cancelled; row label arm for Cancelled)
- crates/client-gpui/locales/en/inbox.ftl (`inbox-filter-status-cancelled = Cancelled`)
- crates/client-gpui/tests/inbox.rs (replaced the assertion that pinned `cancelled` to Idle; new tests for Cancelled, unknown values, failed/cancelled filter query, rendered row labels; catalog check covers failed and cancelled filter keys)
- web/src/sessions.js (STATUS adds failed and cancelled; `Object.hasOwn` check for unknown values)
- web/tests/sessions.unit.mjs (new, node:test)

## Criteria
1. Desktop parses `cancelled` as its own status, sits with Done, label "Cancelled" from Fluent: `a_cancelled_status_is_its_own_status_and_sits_with_done` (parse, as_query, Section::of, model row, Done section); `failed_and_cancelled_rows_show_their_own_labels_in_the_done_section` (rendered rows "Broke, claude, Failed", "Stopped, claude, Cancelled", "Upgrade axum, claude, Done"). The Cancelled variant did not exist before, and the old test pinned `cancelled` to Idle, so the pre-change code cannot pass these. I did not run them against the original code.
2. Filter key added: `inbox-filter-status-cancelled` in inbox.ftl; Cancelled and Failed buttons in the filter row; `the_failed_and_cancelled_filters_send_their_own_query_value` checks `status=failed` and `status=cancelled`; the catalog test includes both keys.
3. Web shows "Failed" and "Cancelled": `web/tests/sessions.unit.mjs` cases 1 and 2 (fail on original, pass now).
4. Web status filter: the web app has no status filter (sessions.js only lists threads), so nothing to extend there.
5. Unknown values behave like done on both: desktop `an_unknown_status_is_idle_and_sits_with_done` (paused, Idle, Done section); web unknown-status case (paused, empty, constructor, __proto__ all render "Done").
