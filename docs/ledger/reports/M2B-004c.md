# M2B-004c: runner: presence{asleep} before OS sleep and thread_open for local threads

## Summary

`TunnelSink::thread_open` queues a `thread_open` frame in the durable outbox, so it is sent, resent and acked like events and goes before any later event of that thread (also across resumed and fresh reconnects). `TunnelClient::sleep_hint()` returns a `SleepHint` whose `asleep()` makes the live connection write `presence{asleep, reason: "os_sleep"}` and reports whether it was written (bounded 1 s wait). Clean shutdown already sends `close{normal}`; a new test asserts the frames and that no reconnect follows.

## Acceptance criteria

1. **Met.** `thread_open_goes_out_before_the_first_event_of_its_thread` (thread_open queued while offline, seq 1 before the event at seq 2, fields checked), `thread_open_is_resent_first_after_a_resumed_reconnect` (both frames unacked, socket dropped, resumed welcome: same thread_open then same event, then acked and pruned), `thread_open_is_renumbered_first_after_a_fresh_stream` (fresh welcome: thread_open renumbered to seq 1, event to seq 2).
2. **Met.** `the_sleep_hint_sends_presence_asleep_on_the_live_connection` (exact frame `{"t":"presence","state":"asleep","reason":"os_sleep"}`, not in the outbox), `shutdown_after_the_sleep_hint_sends_close_normal_and_never_reconnects` (presence, then `close{normal}`, `Exit::Shutdown`, no second connection within 300 ms). Also `the_sleep_hint_gives_up_without_a_connection_so_the_sleep_is_not_held` (no connection: `false` after the 1 s wait). The existing `shutdown_sends_close_normal` still passes.

The new tests do not compile without the new API, so they fail on the unchanged tree.

## Design notes and limits

- `thread_open` is not idempotent: a second call for the same thread queues a second frame. The ordering guarantee depends on the caller calling it before the thread's first event; the sink does not check this.
- `presence{asleep}` is best effort and is only written while the socket is up (the connected loop). During backoff or a connect the hint returns `false` after 1 s. The hub then sees the socket loss without a hint and marks the machine `offline` rather than `asleep` (tunnel.md §3.7).
- Nothing yet calls `sleep_hint()` or `thread_open()`: no OS sleep hook and no local-session start path are wired. `tracer.rs` is outside this item.
