# M3-001b report: live events persisted as raw envelope text; one connectivity banner state

## Summary

- `sync`: `Subscription::next_persisted(&mut Cache)` appends the next new event's envelope wire text with `Cache::append_raw` before applying it to the view, so the view never runs ahead of the cache; a failed append returns the error and leaves the view unchanged. The text is taken from the frame by a small scanner that never re-serialises, so an unknown live event is stored byte for byte and comes back after a restart.
- `Applied::Event` keeps its shape, so `tracer.rs`, `tests/queue.rs` and the CLI e2e code are untouched. `Subscription::next` behaves as before.
- `connectivity`: `Connectivity::combine` gives one state from the subscription and the outbox: Offline if either is Offline, else Connecting if either is Connecting, else Online.

## Files changed

- `crates/client-core/src/sync.rs`: `next_persisted`, private `read` (shared with `next`, takes an optional cache and appends before `feed`), `SubscriptionError::Cache`, and the scanner (`envelope_text`, `skip_ws`, `string_end`, `value_end`).
- `crates/client-core/src/connectivity.rs`: `Connectivity::combine`.
- `crates/client-core/tests/sync.rs`: `a_live_unknown_event_is_stored_as_its_envelope_text_and_survives_a_restart` and `a_failed_append_leaves_the_view_where_the_cache_is_and_the_next_event_is_not_a_gap` (local WebSocket hubs, no fixture change), plus imports.
- `crates/client-core/tests/banner.rs` (new): four tests over all nine pairs and the banner text.
- `docs/ledger/reports/M3-001b.md` (this file).

Not changed: `Cargo.toml` (no `raw_value` feature was needed; the scanner avoids it), `cache.rs` (`append_raw` already existed from M3-001a), `outbox.rs`, `lib.rs`.

## Criteria

1. **Subscription hands each applied event's raw frame text to the cache (`Cache::append_raw`), so live unknown events survive a restart byte-identically** — met.
   - `sync::a_live_unknown_event_is_stored_as_its_envelope_text_and_survives_a_restart`: a local hub sends `hello`, a known event (spaced frame), an unknown event whose envelope has odd spacing, key order, and a string containing `}` and `\"`, then `live`. The client reads with `next_persisted` into a file-backed cache, the cache is dropped and reopened, and `raw_events` equals `[known compact text, unknown envelope text]` exactly. `last_seq` is 2. Without the change there is no `next_persisted` and nothing is stored.
   - The stored text is the envelope object, not the whole `{"type":"event",...}` frame, because `append_raw` parses each text as an `Envelope`.
   - `sync::a_failed_append_leaves_the_view_where_the_cache_is_and_the_next_event_is_not_a_gap` (added after coordinator review): the first event is for another thread, so the cache's own `WrongThread` rejection makes `append_raw` fail. `next_persisted` returns `SubscriptionError::Cache`, `ThreadSync::last_seq()` stays 0, and the cache stays empty. The next correct events then apply at seq 1 and 2 with no `Gap`, and the stored texts are exactly the known and unknown envelopes. Under the old apply-then-append order the view would have advanced to seq 1 on the refused event, so the test fails on that code.
2. **One banner state: Offline if either link is offline, Connecting if either is connecting, else Online; unit-tested** — met.
   - `banner::offline_if_either_link_is_offline`, `banner::connecting_if_either_link_is_connecting_and_none_is_offline`, `banner::online_only_when_both_links_are_online`: all nine pairs, both orders.
   - `banner::the_combined_state_drives_one_banner`: the combined state gives the offline banner text, and Online+Online gives no banner.
   - Without `combine` the test file does not compile.
