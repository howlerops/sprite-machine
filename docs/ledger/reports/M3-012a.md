# M3-012a report: desktop shell: Agents page and the shell's machines feed (also M3-005d)

## Summary
- New `shell/machines.rs`: the shell's single `GET /v1/machines` feed (`MachinesSnapshot` = agents `MachineInfo` rows + composer `MachineOption`s, off-thread fetch, `REFRESH_EVERY` = 30 s).
- `AppShell` owns the feed. It refetches when the session/target appears or changes, when the Agents page opens (click, Next/Previous section, palette), on a 30 s timer (gpui executor timer, so tests drive it with `advance_clock`), and on the public `refresh_machines`. A fetch in flight is not doubled; a failed fetch keeps the old data and shows `agents-feed-error` on the Agents page.
- The Agents section mounts `AgentsView` (`LaunchConfig { model_key_configured: false }`, `UnavailableManagedClient` whose launch returns "Launching managed agents is not available yet.").
- M3-005d: the thread composer's runner cap is read from the shell feed, not from the new-task composer. `ComposeView` no longer fetches when hosted by the shell: new `set_send_target`, `machines_loading`, `apply_machines`, `machines_failed`; its standalone `set_target` still fetches (tests/compose.rs unchanged).
