# M2-003e report: GitHub sign-in hardening

## Summary
- `GET /v1/auth/github/authorize` is limited per `CF-Connecting-IP` (10 per minute, 429 + `Retry-After`; no header means no limit), reusing the `device_attempts` windows in `devices/limits.rs`.
- The hourly cron now also deletes expired `oauth_requests`, `oauth_codes` and `org_invites` (`github::purge`, wired in `worker.rs`).
- A pre-created user (login, no `github_id`) is linked by login only if created less than 7 days before the sign-in; the link is audited as `auth.github.link` (written at redeem, carried by a marker in `oauth_codes.invite_ids`). An older one is never linked: the sign-in is `access_denied` unless there is an open invite, which creates a new user and releases the stale user's login.
- client-api.md §5.9 documents the limit, the purge and the linking rule.
