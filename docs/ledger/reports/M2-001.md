# M2-001 report: hub Worker skeleton (workers-rs axum router, routing, wrangler bindings)

## Summary

- The hub Worker is an axum router on the workers-rs `http` feature. It serves `GET /healthz` (build info as JSON), a JSON 404 for unknown routes, and an `x-request-id` header that is generated or echoed. The MVP-000 stub router is replaced, and the tracer's `#[event(fetch)]` now goes through the real router.
- Worker and DO glue sit behind `cfg(target_arch = "wasm32")`, so `cargo test -p hub` builds and runs natively.
- `crates/hub/wrangler.toml` declares THREAD, MACHINE and FLOW Durable Object bindings (SQLite-backed, with a migrations tag), D1 `DB` (`migrations_dir = "migrations"`), R2 `BLOBS`, Queue producers and consumers, Static Assets bound to `web/`, and dev vars.
- `scripts/hub-test.sh <name>` builds the Worker, applies local D1 migrations, starts `wrangler dev --local --test-scheduled` on a free port, waits for `/healthz`, then runs `cargo test -p hub --features live --test <name>` with `HUB_URL` set. A trap always stops wrangler and its process group.
- `crates/hub/tests/smoke.rs` has 3 integration tests. Without `HUB_URL` they fail with a clear message that names `scripts/hub-test.sh smoke`. They are gated on the `live` feature, so the verify run is not vacuous.
