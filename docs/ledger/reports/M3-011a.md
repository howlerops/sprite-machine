# M3-011a: client-core: InterruptView carries resolved_at

## Summary

- `InterruptView` (client-core `view/transcript.rs`) now has `resolved_at: Option<String>`: the envelope `ts` of the `InterruptResolved` that was accepted as the resolution. It is `None` while open, and after a 409 alone (which has no envelope of its own).
- The envelope `ts` reaches the transcript through `Transcript::apply(event, ts)`; `TaskView::apply` passes `envelope.ts`. Only the first accepted `InterruptResolved` sets it, so a replay gives the same value.
- The approval card (`ApprovalController::cards`) shows the envelope time of the resolution. Precedence is: a host time from `set_resolved_at` (unchanged override), then the parseable envelope `ts`, then the first-seen time as fallback when the `ts` is empty or unparseable.
- The envelope `ts` is informational in the spec (`docs/specs/turn-event.md`: ordering is by `seq`). It is used here for display only.

## Files

- `crates/client-core/src/view/transcript.rs`: `InterruptView.resolved_at`; `Transcript::apply` takes the envelope `ts`; set on the first accepted `InterruptResolved`.
- `crates/client-core/src/view/mod.rs`: `TaskView::apply` passes `envelope.ts`.
- `crates/client-gpui/src/approval/controller.rs`: separate maps for the host override (`resolved_at`) and first-seen (`first_seen`); `cards()` prefers the envelope time.
- `crates/client-core/tests/view_models.rs`: new test `an_interrupt_resolution_keeps_the_envelope_ts_of_the_first_accepted_answer`.
- `crates/client-gpui/tests/approval.rs`: `envelope_at` helper; new tests `the_card_shows_the_envelope_ts_of_the_resolution_not_the_time_it_was_seen`, `a_replayed_resolution_after_reconnect_shows_the_same_time`, `a_missing_or_unparseable_ts_falls_back_to_the_first_seen_time`; existing tests `a_resolved_card_shows_who_resolved_it_and_when` and `the_pane_pins_open_cards_and_shows_resolver_and_time_in_the_transcript` now give the resolution envelope its real time (before, they relied on first-seen stamping).
- `docs/ledger/reports/M3-011a.md` (this report).

Public API change: `client_core::view::transcript::Transcript::apply` gained a `ts: &str` parameter. No other caller in the workspace (checked: `cargo check -p runner --all-targets` passes).

1. `InterruptView` exposes `resolved_at` = the ts of the envelope that resolved it; `None` while open. Met. `an_interrupt_resolution_keeps_the_envelope_ts_of_the_first_accepted_answer`: open interrupt has `None`; after the first `InterruptResolved` (ts 22:00:30) and a second one (ts 22:09:00) it is `Some("2026-10-27T22:00:30.000Z")`. Replay into a fresh view yields an equal `InterruptView`. `a_replayed_resolution_after_reconnect_shows_the_same_time`: the card shows "at 22:00:30 UTC" both before and after a replay at a later clock.
2. The approval card uses the envelope time instead of first-seen; first-seen is only the fallback when the ts is missing or unparseable. Met. `the_card_shows_the_envelope_ts_of_the_resolution_not_the_time_it_was_seen` (stable at 22:00:30 while the clock moves on); `a_missing_or_unparseable_ts_falls_back_to_the_first_seen_time` (ts `""` and `"soon"` both show 22:01:19).
