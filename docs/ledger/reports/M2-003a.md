## Auth API later routes must use
- Thread-family routes: `auth::routes::authorize_thread_request(env, headers, method, path)` (wasm) or `auth::service::authorize_thread(db, authorization, dev_fixtures, method, path, request_id)` (native): returns `(Principal, Policy)`; add the route to `auth::policy::thread_policy` (unknown route => 404, fail closed).
- Other routes: `let p = auth::authenticate(&db, authorization, dev_fixtures).await?; p.require(Role::Admin)?;` then `audit::record(&db, &audit::Event::by(&p, "domain.verb", kind, id, request_id, detail)).await?` for each mutation. Actor for forwarding: `p.actor()`. Error shapes: `ApiError::new(403,"forbidden",..)`, 401 `unauthorized`, 409 `conflict`.

## Security notes
- Tokens/secret never stored or logged in clear; audit detail is passed through `audit::redact` (secret-looking keys and any `smt_` string).
- Bootstrap compares SHA-256 digests in constant time (length not leaked); unset secret disables bootstrap (401).
- D1 offers no multi-statement transaction via `Db`, so bootstrap/issue use a PK claim plus undo-on-failure (delete cascade); a Worker crash between claim and finish could leave a stale claim (recoverable by deleting the `auth_bootstrap` row).
- Audit is written BEFORE forwarding (fail closed): refused requests (401/403/400) leave no row, but an authorized request the Thread DO then rejects (e.g. 409 already_resolved) is recorded as an attempt.
- Tracer routes in `worker.rs` (MVP-000, unauthenticated) are untouched and still open.
- `request_id` in audit is the caller's valid `x-request-id`, else a fresh id that may differ from the one `observe` puts in the response.
