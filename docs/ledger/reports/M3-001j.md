# M3-001j report: transactional view apply

## Summary

- `ThreadView::apply` is transactional: every step that can fail (a state-delta patch, a `DeltaBeforeSnapshot`, an activity patch) runs before any field changes, and `last_seq` is set last. A refused envelope leaves the view exactly as it was.
- `ThreadView::check` reports what `apply` would refuse, without changing anything. `Subscription::next_persisted` calls it before `Cache::append_raw`, so the cache never holds an event the view refused.
- Cost: a state delta copies the one state document it patches, and a patch activity copies that activity's content. No whole-view clone per event.

## Files changed

- `crates/client-core/src/view/mod.rs`: `ThreadView::apply` (staged delta, then task, then fields, `last_seq` last), `ThreadView::check`, `staged_delta`, `apply_to_task` (a new task is pushed only after its first event is accepted; replaces `task_slot`), `TaskView::apply` runs the transcript first, `TaskView::check`.
- `crates/client-core/src/view/transcript.rs`: `apply_activity` computes the new content in `activity_content` before it writes the item; `Transcript::check`; `activity_content_so_far`.
- `crates/client-core/src/sync.rs`: `read` calls `self.sync.view().check(envelope)` before `append_raw` for a new event; doc comment on `next_persisted`.
- `crates/client-core/tests/view_models.rs`: `a_refused_envelope_leaves_the_view_and_last_seq_exactly_as_they_were`, `a_delta_before_its_snapshot_leaves_last_seq_at_zero`.
- `crates/client-core/tests/sync.rs`: `an_event_the_view_refuses_is_not_cached_and_the_cache_matches_the_view`.
- `docs/ledger/reports/M3-001j.md` (this file).

## Criteria

1. **A delta before its snapshot, or a bad patch, leaves `last_seq` and the view unchanged; `next_persisted` does not append it to the cache** — met.
   - `view_models::a_delta_before_its_snapshot_leaves_last_seq_at_zero`: `ThreadView` equality before and after a refused delta, and `last_seq` is 0.
   - `view_models::a_refused_envelope_leaves_the_view_and_last_seq_exactly_as_they_were`: a delta with a bad second op, and an activity patch that fails on a task the view has not seen. Whole-view equality is unchanged, `check` and `apply` both refuse, and the same seq then applies with a valid event.
   - `sync::an_event_the_view_refuses_is_not_cached_and_the_cache_matches_the_view`: a live hub sends a delta before its snapshot (refused, not stored), the snapshot, a bad patch at seq 2 (refused, not stored), then a valid seq 2. `last_seq` is 2 and `raw_events` is exactly the snapshot and the valid delta.
   - Without this change the old `apply` set `last_seq` first, so the view tests fail. The old `read` appended before feeding, so the sync test's `raw_events` would include the refused seq-1 delta.
