# M3-011c: client-gpui shell: wire ApprovalController into the app connection

## Summary

- `SessionLink` (link thread) now owns a `Subscription` for one thread, the `Outbox`, the `Cache` and an `ApprovalController`. It no longer uses `client_core::Connection`, because `Connection` gives no `&mut ThreadView` or `&mut Outbox`, which `ApprovalController::answer` needs. The combined banner state is computed the same way (`subscription.combine(outbox)`, outbox alone while no thread is followed).
- The link follows the thread the screens show. `SessionLink::open_thread` (and `AppShell::open_thread`) switches it: the view is rebuilt from the cache, a fresh subscription resumes from there, the same outbox is kept, the controller restarts for the new thread (presets carried over). Opening the thread already followed is a no-op. The `th_session` placeholder is gone: `default_config` has an empty `link_thread` (no subscription until a thread is opened).
- Ownership stays on the link thread. `SessionLink::with_thread(job)` runs a closure there with `ThreadAccess { view: &mut ThreadView, outbox: &mut Outbox, cache: &Cache, approvals: &mut ApprovalController }`, flushes the outbox afterwards and publishes a snapshot. `answer` and `set_remember_preset` are built on it.
- The UI gets a `ThreadSnapshot { thread_id, view, cards }` over a `watch` after every event, answer and refresh. The shell feeds it to a `TranscriptPane` (`set_thread`, `set_approvals` with a `CardHandler` that routes clicks to the link). The Inbox page shows this pane with a back button while a thread is open.
- Time left: the shell asks the link to `refresh()` every `APPROVAL_TICK` (1 s, a gpui background timer, driveable in tests with `advance_clock`). The link recomputes cards with the injected `AppConfig::clock` and publishes a snapshot when the cards changed. `refresh` also flushes, so a retry that falls due is sent.
- `AppConfig` gained `clock: Arc<dyn Clock>` (`default_config`: `SystemClock`); `link_thread` is now the initial thread, empty for none.
- `ApprovalController::into_presets` added. Presets are stored at `<config dir>/approval-presets.json` when prefs have a path.
