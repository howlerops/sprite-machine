# M3-017a: client-core create_thread

## Summary
- Adds `client_core::create_thread` (`POST /v1/threads`, client-api.md §5.2) with typed `CreateThread` / `FirstPrompt` / `ThreadCreated` and `CreateThreadError`. The caller passes the `Idempotency-Key` (checked against §3's charset before sending).
- `cli e2e app` and `cli e2e attachments` create their threads through it; the hand-built reqwest calls for thread creation are gone.
- Only thread creation moved. Prompt sends, attachment upload and the dev credential call are still raw reqwest (see Discovered work).

## Files changed
- `crates/client-core/src/threads.rs` (new): the request/response types, the error enum and `create_thread`.
- `crates/client-core/src/lib.rs`: `pub mod threads`, re-exports, module doc line.
- `crates/client-core/src/outbox.rs`: `valid_key` becomes `pub(crate)` so `threads` shares the key check.
- `crates/client-core/Cargo.toml`, `Cargo.lock`: `axum = "0.8"` as a dev-dependency for the fake hub (axum is already in the lock).
- `crates/client-core/tests/create_thread.rs` (new): five tests against an axum fake hub on 127.0.0.1.
- `crates/cli/src/e2e/app.rs`: thread creation through `client_core::create_thread`; the key is now `new_idempotency_key()`.
- `crates/cli/src/e2e/attachments.rs`: same; the file-part `Value`s are converted to `ContentPart`.
- `docs/ledger/reports/M3-017a.md`: this report.
