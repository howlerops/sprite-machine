## Criteria
1. Met. Exact pins: `@cloudflare/sandbox` 1.0.3, `wrangler` 4.154.0, committed lockfile, TS strict (+`noUncheckedIndexedAccess`), vitest 3.2.4. `wrangler.jsonc` has `WorkspaceDO` binding, migration `v1` `new_sqlite_classes`, `containers` (image `../../images/workspace/Dockerfile`, `standard-2`), R2 binding `BACKUPS`.
2. Met. Methods take one JSON request object each (`start({image, instance})`, `backup({dir})`, ...) and return `Result<T>` (`{ok:true,value}` or `{ok:false,error:{code,message}}`); this deviates from positional args so RPC and JSON bodies share one shape. HTTP statuses: 400 invalid_argument, 404 not_found, 409 invalid_state, 502 sandbox_error, 500 internal. The Worker entry also routes `/w/<workspaceId>/rpc/<method>` to the named DO (dev/smoke; the Rust hub binds the namespace directly).
3. Met. Test "selection > uses FakeSandbox when DEV_FAKE_SANDBOX=1".
4. Met. Describe blocks "lifecycle: stopped -> running -> stopped", "start validation", "stop", "snapshot / restore", "backup / restoreBackup", "exec", "preview", "HTTP surface: POST /rpc/<method>". They cover argument validation, state transitions, injected sandbox failures surfaced as `sandbox_error`, unknown ids as `not_found`, and the status mapping.
5. Met, with one deviation. `dev-smoke.sh` picks a free port, runs `wrangler dev --enable-containers=false --var DEV_FAKE_SANDBOX:1` under `setsid`, curls start/status/stop, and its trap kills the process group.

## Deviations (needed because images/workspace/Dockerfile does not exist yet)
- wrangler 4.154.0 validates the `containers.image` path even with `--enable-containers=false` and refuses to start. Per the instructions I created nothing outside `workers/workspace`. Instead `wrangler.dev.jsonc` is a copy of `wrangler.jsonc` without `containers`, and `dev-smoke.sh` uses it via `-c`.
- The vitest pool also reads wrangler config, so `vitest.config.ts` declares the DO and R2 bindings inline instead of pointing at `wrangler.jsonc`.
- Once M0-008c lands the Dockerfile, both workarounds can be dropped (smoke can use `wrangler.jsonc`).
- `vitest` is 3.2.4 because `@cloudflare/vitest-pool-workers` 0.12.21 is the newest version that works with it. The 4.x pool needs vitest 4, and `npm install vitest@4` crashes npm 10.9.4 in arborist (`edgesOut`). The pool nests its own wrangler 4.72.0 (tests only). `npm audit` reports advisories on dev deps; not addressed.

## @cloudflare/sandbox version and SDK calls used
Version 1.0.3. In 1.0 there is no `getSandbox`, `Sandbox` class, `exposePort` or SDK snapshot API: the DO owns `ctx.container` and the package adds `DirectoryBackup`, `Files`, `S3Mount` (read from the shipped `.d.ts`). Used:
- From the package: `DirectoryBackup(container, gateway, {binding:"BACKUPS", prefix})` with `.backup({dir, name, gitignore:true})` and `.restore(record, {dir?})`; `DirectoryBackupGateway` re-exported from the Worker entry (reached via `ctx.exports.DirectoryBackupGateway`); `SandboxBackupError.is`, `SandboxFileError.is` for error mapping.
- Native Container API (`ctx.container`): `start({image, instance, enableInternet:false})`, `start({containerSnapshot:{id}, instance, enableInternet:false})` (restore), `destroy()`, `running`, `snapshotContainer({name})`, `exec(cmd,{env,cwd})` then `.output()`, `getTcpPort(port).fetch()` (preview).
- Not used yet: `Files`, `S3Mount`, `interceptOutboundHttp` (outbound handler / credential injection / egress allowlist are later items).
- `CloudflareSandbox` is type-checked but not executed locally (no containers, FUSE); the real path is for the deployed preview env.
