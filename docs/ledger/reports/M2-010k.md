# M2-010k: inbox quick answer picks the approval

## Summary

The inbox client now reads `pending_interrupts[].kind` (client-api.md §5.2). `kind` is parsed into
a new `InterruptKind` (`approval`, `form`, `auth`; a missing kind is `approval`; any other string is
`Other`). Quick Allow / Deny answers the first `approval` entry, not the first entry of any kind. A
row whose first entry is a form therefore still offers Allow / Deny for the approval listed after
it. The row detail line shows the title of the first open interrupt of any kind. A row with only
form or auth entries shows no quick buttons and shows its first title as the detail.

Decisions:
- `ThreadRow::first_approval()` and `ThreadRow::detail()` are the two lookups. The view and
  `begin_answer` both use them, so the buttons and the request always agree.
- If the first approval has no allow (or reject) option, there is no quick answer. The client does
  not fall through to a later approval for that verdict.
- Allow / Deny accessibility labels name the approval's own title, not the row detail. Otherwise a
  row with a form first would label the Allow button with the form's title.
- Unknown kinds are `Other` and never quick-answered. Only `approval` gets buttons.

## Files

- `crates/client-gpui/src/inbox/view.rs`: Allow / Deny computed from `first_approval()`; button labels
