# M3-013d report: desktop inbox refreshes itself; one notification per run

## Summary
- `inbox::REFRESH_EVERY` = 20 s. `AppShell` runs a gpui-executor timer (driven by `advance_clock` in tests, like the machines feed) that calls the new `InboxView::refresh_if_idle`. The window coming to the front does the same (`AppShell::activate(active, window, cx)`, called by the activation observer; it also calls `set_window_active`).
- `refresh_if_idle` does not stack (no GET while one is in flight) and skips when signed out, when a filter or search text is set, or when a search is pending. Decision for criterion 4: skip while filtered, so the timer never replaces the user's filtered view and the notifier only sees unfiltered lists (existing rule kept). The next unfiltered list catches up.
- A failed refresh goes through the existing path: the model reports the error and keeps its rows.
- The open thread's last task status (`TaskStatus`) is fed to the notifier from `apply_snapshot` (mapped: Starting/Running to running, NeedsYou, Succeeded to done, Failed, Cancelled). Only after the baseline list is seeded; a thread the notifier has not seen yet is only recorded (`Notifier::knows`), never notified. The notifier already de-duplicates by thread and status, so the later list saying `failed` is silent. If the list is behind (still `running` after the snapshot said `failed`), that stale row is left out of the observation (`snapshot_status` guard, cleared when a list agrees or the thread closes/changes), so the catch-up list does not notify again.

## Criteria
1. Timer and focus refetch, one toast with no user action: MET. `the_inbox_refetches_on_a_timer_and_a_status_change_notifies_once` (only `advance_clock(REFRESH_EVERY)`; exactly 1 toast, still 1 after a second interval); `the_inbox_refetches_when_the_window_comes_to_the_front`.
2. No stacking; failed refresh keeps the list: MET. `a_refresh_does_not_stack_and_a_failed_one_keeps_the_list` (two ticks over a 3 s slow answer = one extra GET; then a 500: error set, th_a row kept).
3. Snapshot status fed, one notification per run: MET. `the_open_threads_snapshot_notifies_and_the_list_does_not_repeat_it` (background window, RunError pushed: 1 toast; stale `running` list, then `failed`, then `failed` again: still 1).
4. Filtered lists: MET. `a_filtered_list_is_not_refreshed_by_the_timer` (no GET, no toast); the existing filtered-list rule is unchanged.
