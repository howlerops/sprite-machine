# M1A-004 report: sidecar ACP client-side fs + terminals

## Summary
- `acp::fs::Workspace` serves `fs/read_text_file` and `fs/write_text_file`, confined to the canonical workspace root. It rejects `..`, absolute paths outside the root, symlinks (file or parent directory) that resolve outside, and writes through dangling symlinks, each with a typed `FsError`.
- `acp::terminal::Terminals` serves `terminal/create|output|wait_for_exit|kill|release` on a `portable-pty` PTY (0.9.0, pinned). It enforces `output_byte_limit` truncation from the start at a char boundary, honours `cwd` (inside the root) and `env`, and tees output as `Activity{terminal}` envelopes to an injected sink.
- Activity sequence: snapshot on create, append chunks of at most 64 KiB, then a closing snapshot with `exit` and the last 128 KiB of output. All envelopes validate against `crates/protocol/schemas/turn-event`.
- 24 tests in `crates/sidecar/tests/acp_fs_term.rs` pass, repeated 6 times without a failure. The rest of the sidecar suite still passes.
- `ClientHandler` is not implemented here. The runner delegates `fs/*` and `terminal/*` to `Workspace` and `Terminals`, which keep the session check.

## Decisions and limits
- Terminal `cwd` must be inside the workspace, the same rule as fs. The spec does not state this; it is my choice. Requests without `cwd` start at the root.
- `output_byte_limit` absent means 1 MiB retained (`DEFAULT_OUTPUT_LIMIT`). Requests above 16 MiB are clamped. The Activity tee is not limited by it.
- Relative fs paths are taken relative to the root. `line` 0 is read as line 1.
- `kill` uses portable-pty's unix killer, which sends SIGHUP. A child that ignores SIGHUP survives. A SIGKILL fallback would need `libc` and `unsafe`, so it is left out.
- The fs check and the following I/O are separate steps (TOCTOU). Closing that needs `openat`-style I/O, which is not done here.
- The closing snapshot waits up to 2 s for the PTY reader to drain. A grandchild holding the PTY open cannot block the terminal forever.
- Attribution: the brief asked for `Co-Authored-By: Claude Opus 5.5`. The attribution reminder in the session says Haiku 5.5, which is the model actually running. The commit uses Haiku 5.5, the harness line. This is the one difference from the brief.
