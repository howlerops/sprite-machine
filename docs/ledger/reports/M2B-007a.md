# M2B-007a: sm rc follow-ups (permission mode first, MCP capabilities, worktree sweep, session end)

## Summary

The bridge takes `Config::initial_mode` and sets it (after checking it is advertised) right after `session/new` / `resume` / `load` and before the first prompt; a refused or unadvertised mode ends the task with `RunError` and no `session/prompt` is sent. The bridge also takes `Config::mcp_provider` (`McpProvider`), called with the agent's `initialize` `mcp_capabilities`; `sm rc` uses it so http/sse servers pass when supported. `sm rc` sweeps leftover worktrees at start (clean removed, dirty listed in one warning) and ends a session on a hub `cancel` of an idle thread or after `--idle-timeout` (default 2 h).

## Notes

- `--permission-mode default` sets no mode (the agent starts in its own default); only non-default modes are applied and enforced.
- A session whose mode could not be set stays attached but is retried on the next prompt (the bridge only marks a session done once `set_mode` succeeded).
- After a session closes, a later prompt for the thread reopens it from its store, in the stored cwd (a removed worktree is "workspace is gone").
