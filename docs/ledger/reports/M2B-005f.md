# M2B-005f report

## Summary
- Machine DO has a new internal action `POST /internal/machines/{id}/disconnect`: it closes live tunnel sockets with `auth_revoked` (4003) and persists nothing, so the machine is not revoked and its credential works on the next connect. `revoke` is unchanged.
- `MachineControl` gains `disconnect`; `DoControl` posts it. `close_untrusted_tunnels` (policy flip on) now uses it instead of `revoke`.
- Guard: `/internal/*` is reachable only through a DO stub (the Worker router has no such route, same as `revoke`).

- crates/hub/src/machines/admin.rs (`MachineControl::disconnect`), crates/hub/src/machines/internal.rs (`DoControl::disconnect`)
- crates/hub/src/devices/service.rs (`close_untrusted_tunnels` uses disconnect)
- crates/hub/src/machines/tests.rs, crates/hub/src/devices/tests.rs (FakeControl implements the new trait method; devices test asserts disconnect-not-revoke). These two are outside the listed files but the trait change forces the fakes to change.

## Acceptance criteria
- POST /internal/machines/{id}/disconnect closes sockets with auth_revoked without setting revoked; revoke unchanged: MET. Live `the_tunnel_refuses_a_machine_that_is_not_vouched_for_when_the_org_requires_trusted_devices` (the open tunnel gets `close{auth_revoked}`, and afterwards the same credential gets `welcome`, which fails if the DO were marked revoked).
