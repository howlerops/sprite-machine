# M2B-005f report

## Summary
- Machine DO has an internal action `POST /internal/machines/{id}/disconnect`: it closes live tunnel sockets and persists nothing, so the machine is not revoked and its credential works on the next connect. `revoke` is unchanged. `/internal/*` is reachable only through a DO stub, like `revoke`.
- SPEC-007: new close code `device_untrusted` (4009, reconnect) in the protocol. The disconnect closes with it (not `auth_revoked`, which makes a runner wipe its credential). The tunnel upgrade refusal for an untrusted machine is now `403 device_untrusted` (was `401`).
- Runner: `device_untrusted` close and the 403 `device_untrusted` upgrade answer keep the credential, reconnect with the normal backoff, and log one clear warning per process. Any other 403 is still fatal.
- `close_untrusted_tunnels` (policy flip on) uses disconnect. Live: flip on closes the tunnel, flip off, the same machine and credential get `welcome`.
