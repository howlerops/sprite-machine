# M2-008d: POST /v1/threads machine org check + policy

## Summary

- `POST /v1/threads` now looks up `machines WHERE id = ? AND org_id = <caller org> AND revoked_at IS NULL` before anything is written; unknown, revoked and other-org machines all answer `404 not_found` (no audit row, no Thread DO, no dispatch).
- `auth/policy.rs` has a `(POST, /v1/threads)` rule (member, `thread.create`); the route takes its role and audit action from it instead of hard-coded values.
- A viewer gets 403 (native + live tests). Existing thread_create tests now create their machines through `POST /v1/machines` (a D1 row is required).

## Spec issues

1. `authorize_thread` (auth/service.rs, outside the allowed paths) rejects an empty policy thread id and audits before the machine check, so the route calls `thread_policy` + `authenticate` + `require` itself and audits after the machine check. The policy's `thread_id` is empty for this route. Finishing the move into `authorize_thread_request` needs an auth/service.rs change (below).
2. A request with a missing/invalid `machine_id` is now `400 invalid_request` in the Worker, before auditing.
