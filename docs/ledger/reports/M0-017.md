# M0-017 report: Spike: Cloudflare Workers (workers-rs + axum, SQLite DO + hibernatable WebSocket, D1, R2) under wrangler dev

## Summary

- `spikes/cf` is a standalone workers-rs 0.8.7 + axum 0.8 Worker: a SQLite Durable Object (counter + hibernatable WebSocket echo + `setWebSocketAutoResponse` ping/pong), D1 and R2 routes.
- `spikes/cf/test.sh` builds it, runs `wrangler dev --local` on a free port, asserts every route (HTTP + WebSocket via Node) and always kills the wrangler process group. All passes.
- Bundle is 147,705 bytes gzip; cold build 52 s, incremental 7 s. Limits, sources, gaps and recommendations are in `docs/spikes/cloudflare.md`.
- **Criterion 1 cannot hold literally**: `worker` 0.8.7 (and workers-rs `main`) depends on `tokio` unconditionally, with no features (only `tokio::io` traits). No tokio runtime is present; test.sh asserts that. Needs a decision to reword the criterion (`blocked_on` below).

## Acceptance criteria

1. **Partly met / literal wording not met.** Standalone project (empty `[workspace]`, own
   `Cargo.lock`, root Cargo files untouched); `worker` with `http` + `axum` features and an axum
   `Router` builds for `wasm32-unknown-unknown` via `worker-build --release`. But
   `cargo tree --target wasm32-unknown-unknown -e normal` lists tokio:
   ```
   $ cargo tree --target wasm32-unknown-unknown -e normal -i tokio
   tokio v1.54.1
   └── worker v0.8.7
       └── cf-spike v0.0.0
   $ cargo tree ... -f '{p} [{f}]' | grep '^tokio '
   tokio v1.54.1 []
   ```
   `worker/Cargo.toml` has `tokio = { version = "1.28", default-features = false }` as a
   non-optional dependency (used for `AsyncRead`/`AsyncWrite` on `worker::Socket`); it is the same
   on workers-rs `main`. No tokio feature is enabled, so there is no runtime. test.sh enforces
   "tokio only via `worker`, empty feature list". There is no way to satisfy the literal check
   with workers-rs short of forking it.
2. **Met.** `POST /counter/room-a` → 1, 2; `GET` → 2; `room-b` independent; still 2 after the
   WebSocket traffic (SQLite DO via `new_sqlite_classes`). WebSocket accepted with
   `state.accept_web_socket`, echo `hello -> echo:hello`; `setWebSocketAutoResponse` is exposed
   in workers-rs and `ping -> pong` comes from the runtime (the handler would answer `echo:ping`).
   D1: `POST /d1/notes` → `{"id":1,"body":"hello d1"}`, list returns both rows (schema from
   `wrangler d1 migrations apply DB --local`). R2: `PUT` → 201, `GET` → `hello r2`, missing → 404.
   Gaps recorded: `getWebSocketAutoResponseTimestamp` and `setHibernatableWebSocketEventTimeout`
   are not exposed.
3. **Met.** test.sh: `set -euo pipefail`, free port via Node, `setsid wrangler dev --local`,
   `trap cleanup EXIT INT TERM` killing the process group (TERM then KILL), exact status+body
   assertions, WebSocket checks in `ws-check.mjs` (Node 22 global `WebSocket`, 15 s timeout).
4. **Met.** `docs/spikes/cloudflare.md` has the gzip bundle size (147,705 bytes), build times
   (cold 52 s, incremental 7 s, no-op 2 s, dev ready ~5 s), limits for bundle size, startup, CPU,
   memory, DO storage and SQL, WebSocket message size (32 MiB), hibernation, D1 size and query
   limits, R2, each with its URL; workers-rs gaps (tokio, `strip = true` breaks worker-build,
   D1 alpha feature, hibernation API coverage, panicking trait defaults, `wasm_bindgen` import,
   axum `Send` caveats); and "Recommendations for the hub crate".

blocked_on: leader/human decision to reword M0-017 criterion 1 (and the plan §4.2 "no tokio" rule) to "no tokio runtime: tokio only as workers-rs's feature-less dependency", which test.sh already enforces.
