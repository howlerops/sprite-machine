# M2B-006c: MCP config command resolution, sse, var expansion

## Summary

- Local MCP stdio commands: a bare name (`npx`) is resolved against the runner's PATH with discovery's executable check; an absolute command is kept; an unresolvable one skips that server with a warning naming the server and the command as written.
- `sse` and `http` entries become `McpServer::Sse` / `McpServer::Http` only when the agent advertises `mcp_capabilities.sse` / `.http`; otherwise skipped with a warning.
- `${VAR}` and `${VAR:-default}` expand in command, args, env values, url and header values from the passed-in env map. A missing VAR without default expands to empty and is warned about by name.
- `local_mcp_servers` now takes the agent's `McpCapabilities` and the runner env (`Env`, a map); `process_env()` builds it from the process. 25 tests in `discovery.rs` pass.

## Files changed

- `crates/runner/src/harness/mcp.rs`: `local_mcp_servers(home, project_dir, caps, env)`, `Env`, `process_env`, `resolve_command`, `expand`; `sse` arm; capability gating.
- `crates/runner/tests/discovery.rs`: existing MCP tests moved to the new signature; 9 new tests (see below); imports `McpCapabilities`, `Env`.
- `docs/ledger/reports/M2B-006c.md` (this report).

`harness/mod.rs` is unchanged (`pub use self::mcp::local_mcp_servers` still applies; `is_executable` is reused by the child module).

## Signature change and callers

No caller of `local_mcp_servers` exists in this worktree outside the harness module and its tests. The old two-argument signature is not kept as a shim: a caller must pass the agent's capabilities and an env map (`harness::mcp::process_env()` for the runner's own environment). If M2B-007 has written a two-argument call, it needs that update on merge. The "all capabilities" shim was not added because it would silently allow `sse`/`http` entries that the agent may not support.

## Acceptance criteria

1. **Met.** Bare names are resolved in `mcp::resolve_command` (PATH entries that are absolute, `super::is_executable` check); absolute commands are kept; the skip warning carries `server` and the raw `command` template, not the expanded value and not env or args.
   - `bare_stdio_command_resolves_against_the_fake_path`
   - `bare_command_skips_non_executable_files_and_keeps_searching_path`
   - `absolute_command_is_kept_without_a_path_lookup`
   - `unresolvable_command_skips_only_that_server` (the skipped server's env and args carry sentinel values that are not in the result)
   - `relative_command_paths_and_empty_commands_are_skipped`
   - `bare_command_from_a_var_resolves_against_the_fake_path`
   - Note: the warning text itself is not asserted. No tracing subscriber is a dependency of `runner`, and `Cargo.toml` is out of scope. See the discovered work.
2. **Met.** `sse` and `http` are gated on the `McpCapabilities` parameter.
   - `sse_entries_need_the_agent_to_advertise_sse` (skipped without `sse`, `McpServer::Sse` JSON with `type: "sse"` with it)
   - `http_entries_need_the_agent_to_advertise_http`
   - `local_mcp_servers_merge_claude_sources_in_precedence_order` (an sse entry is skipped with `http` only)
3. **Met.** `expand` handles `${VAR}` and `${VAR:-default}`. A set-but-empty VAR takes the default (bash `:-` semantics). Malformed references (`${ bad }`, unterminated `${`) stay literal.
   - `var_references_expand_in_command_args_env_url_and_headers`
   - `var_defaults_and_missing_vars_never_read_the_real_environment` (`${HOME}` with no HOME in the fake env expands to empty, so the real environment is not read)
   - Warning text for a missing VAR is not asserted (same reason as criterion 1).
4. **Met.** Every test uses a fake PATH of temp-dir stubs (`fake_env`) and an explicit env map. No test reads the process environment.

## Decisions and deviations

- Only absolute PATH entries are searched; a relative PATH entry cannot give an absolute command.
- A relative command with a directory part (`./bin/tool`, `bin/tool`) is skipped rather than resolved against the project dir. ACP requires absolute, and the project dir is not a PATH.
- The generic `skipping local MCP server` warning can follow a specific one for the same server (for example the capability reason). Kept simple on purpose.
