# M1A-006e: runner respawn, harness-exit interrupts, acp-mock recording

## Summary

- Criterion 1 is NOT MET: the tracer's bridge is built in `crates/sidecar/src/tracer.rs` (`Bridge::connect`), not in `crates/runner/src/tracer.rs` (which only takes channels), and that file is outside the allowed list. A `spawn_with` respawn test is added against the bridge API; the production wiring is unchanged (blocked_on below).
- Interrupts ended at startup (stored by an earlier process) now end `InterruptResolved{cancelled}` + `RunError{error, code:"harness_exited"}`, not `expired`. `expired` stays for TTL expiry only.
- An approval for a thread the process has not loaded, whose thread the store knows, answers `unknown_interrupt` (409); an unknown thread still answers `unknown_thread`.
- acp-mock records every message it receives (`Recorder`, `run_recorded`) and advertises `modes` / `config_options` from the script on `session/new`, `session/resume` and `session/load`. bridge_robust's tee and two of its three hand-played tests are gone.
- The bridge's applied-keys set is pruned once `Store::seen_key` reports a key committed, so it holds only the keys in flight.

## Criteria

1. **NOT MET (blocked).** Added `a_subprocess_agent_started_by_spawn_with_is_started_again_after_it_is_killed` (bridge_robust): a real agent process started by `Bridge::spawn_with` is killed mid-run, the task ends `harness_exited`, and the next prompt starts a new process (its pid differs) and completes. The production path is not switched: `runner::tracer::run` receives channels from the CLI, and the bridge is built in `sidecar::tracer::run` with `Bridge::connect` over the acp streams. See blocked_on.
2. **MET.** Startup: `interrupts_stored_by_a_previous_process_fail_their_task_at_startup` (was `expired`) now asserts `InterruptResolved{cancelled}`, `RunError{error, code:"harness_exited"}`, no `expired`. Live harness exit: `a_dead_agent_fails_running_tasks_and_the_next_prompt_respawns_and_resumes` now asserts an `InterruptResolved{cancelled}` for the open approval and no `expired`. The live path already produced this (the mapper's `abort` ends paused interrupts `cancelled`); the test pins it. Caveat: see Discovered work 2 (a `RunStarted{resume}` is emitted before the `RunError`, which §4.9's harness-exit bullet says must not happen).
3. **MET.** `an_approval_for_an_interrupt_an_earlier_process_stored_answers_unknown_interrupt` (approval for `int_old` of `th_1` in a fresh process, thread stored, answers `unknown_interrupt`). `an_approval_for_a_thread_no_process_has_stored_answers_unknown_thread` (unknown thread still `unknown_thread`). The decision uses thread presence in the store, because startup has already closed the stored interrupts.
4. **MET.** `acp_mock::Recorder` / `run_recorded` records every received message in order: `acp-mock/tests/recording.rs::the_recorder_keeps_every_message_the_agent_received_in_order`. `session_new_resume_and_load_advertise_the_scripts_modes_and_config_options`, `a_script_without_modes_answers_session_new_without_them`, `a_script_with_malformed_modes_or_options_is_rejected`. bridge_robust uses the recorder for `session/new`/`resume` assertions and acp-mock with script modes for the snapshot test; the tee and the hand-played agent are dropped except `play`, which the raw-update test needs (acp-mock's typed script cannot send an update it rejects).
5. **MET.** `bridge::applied::tests::the_bridge_forgets_a_key_once_its_source_has_committed_it` (drives `Bridge::on_incoming` with a committing command source; the key is pruned from `Bridge::applied`; fails without the prune call), `committed_keys_are_pruned_and_the_rest_are_kept`, `the_set_stays_bounded_as_commands_keep_coming` (200 commands, set empty after each).

## Decisions and caveats

- The startup ending builds one mapper per task (not per interrupt), so a task ends with one `RunError`. A second open interrupt of the same task is passed to the mapper while it is paused, which queues it rather than tracking it; its `InterruptResolved` is then not emitted (Discovered work 4). Agents ask one permission at a time per turn, so this is rare.
- `crates/sidecar/src/acp/reattach.rs::fail_stale_interrupts` still ends with `expired` and is no longer called by the bridge. It is outside the allowed list and was left as is (Discovered work 3).
- The respawn test cannot tell `session/resume` from `session/new` through a subprocess (acp-mock reuses `sess_mock_1` in a new process). Resume is asserted by the in-process test `a_dead_agent_...`.
- Amendment on the M1A-006d note: the applied set is now bounded (criterion 5).
