# M3-005c report: composer shows refused requests; send waits for the thread

## Summary
- `shell/link.rs`: `ThreadSnapshot.refusals: Vec<Refusal{kind: Mode|Model|RemoveQueued, status, error}>`, built from `Rejected` `SetSession`/`RemovePending` outbox entries of the followed thread. A new `tidy_outbox` runs on every snapshot publish: it dismisses (a) `409 task_started` removal conflicts whose task the view shows finished, and (b) rejected session/remove entries older than a later accepted (Done) session/remove request. Switching threads (`open_thread`) dismisses all rejected session/remove entries.
- `shell/view.rs`: `apply_snapshot` passes the refusals to the composer.
- `compose/thread.rs`: `set_refusals`/`refusals`, `is_ready`; each refusal renders as a danger-colored status line (`thread-refused-N`); `clear_thread` clears them; the Send button is `disabled` until the first snapshot (`set_thread`). Enter / Ctrl-Enter / slash-send go through `send_text`, which already returns without touching the field when no thread is set, so typed text is kept.
- `locales/en/compose.ftl`: `compose-thread-refused-mode|model|remove` (`{ $detail }` is the hub's error code, else the status).
