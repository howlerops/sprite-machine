# M2B-002: hub Machine Durable Object (tunnel endpoint, presence, offline queue, ack) + machines table

## Summary

- `crates/hub/src/machines/` holds the runtime-agnostic `MachineCore` (resume tokens, durable command outbox, up/down `seq`, presence) on the protocol crate's `Sender` / `Receiver`, and an async `driver` that runs the tunnel.md §6 validation order against a `ThreadHost` trait; 31 native tests (fake Thread DO, simulated runner).
- `do/machine.rs` is the real Machine DO: hibernatable WebSocket, `setWebSocketAutoResponse` for the literal ping, one tunnel per machine (`superseded`), credential check (`smm_`, only the SHA-256 stored), an in-order frame queue, and an alarm watchdog for 3 x heartbeat silence.
- Admin API `POST /v1/machines`, `DELETE /v1/machines/{id}` (revokes, closes the live tunnel with `auth_revoked`), `GET /v1/machines`, D1 migration `0004_machines.sql`; the Thread DO now pushes its unacked commands to the Machine DO.
- The MVP-000 tunnel stub (`tracer/machine.rs`, the unauthenticated tunnel route) is gone: the tracer runner fetches a dev credential and talks to the real Machine DO; `cargo run -p cli -- e2e tracer` is green. 9 live tests in `tests/machine_do.rs` pass.

## The runner-side contract M2B-004 must follow

Everything is in `tests/machine_do.rs` (`Runner`): a runner built from `Sender<Value>` (up outbox) and `Receiver` (down) behaves as the hub expects.

1. `GET /v1/machines/{id}/tunnel` with `Sec-WebSocket-Protocol: sm.tunnel.v1` and `Authorization: Bearer smm_...` (never in the URL). Missing credential: HTTP 401. A wrong credential, or one of another machine, is accepted and then closed with `close{auth_invalid}` (WS 4002); a revoked machine's own credential gets `auth_revoked` (4003). Both mean: do not reconnect.
2. Send `hello` first and nothing else until `welcome` (frame before hello = `protocol_error`; no hello within 10 s = closed). `hello.machine_id` must be the machine the credential was issued for. `proto` must be 1.
3. On `welcome`: `up.on_welcome(resumed, last_up_seq)` (resumed: drop acked, resend the rest; fresh: renumber the whole outbox from 1, same `event_id`s, and resend it); on `resumed: false` also start the down `Receiver` fresh. Persist `resume_token` (the previous one is dead the moment `welcome` is sent: single use, 7 days; the hub keeps only its hash). Send `last_down_seq` = the highest command seq durably processed.
4. Down commands: `Receiver` rules per seq, dedupe by `idempotency_key` (7 days), then send `{"t":"ack","seq":n}` (cumulative). The hub renumbers its queue from 1 after a fresh stream, so the key dedupe is what prevents a double apply.
5. Up frames: `event`, `thread_open`, `command_result` with a ULID `event_id` that never changes on retransmit; the hub acks cumulatively after the Thread DO accepted the frame, a `nack` (forbidden / invalid_envelope / invalid_sequence / too_large) counts as an ack, drop the frame and fail the task locally. `thread_open` must come before the first event of a runner-started thread; threads created by a `dispatch` / `prompt` command are hosted without it.
6. A failed `prompt` / `dispatch` must be answered with `command_result{ok:false, idempotency_key, code}`: the hub fails the task (`RunStarted` + `RunError{code}`). `approval` / `cancel` failures are only recorded.
7. Heartbeat: `{"t":"ping"}` every `heartbeat_ms` (20 s); the hub answers `{"t":"pong"}` without waking. 3 x `heartbeat_ms` of silence makes the machine `offline`.
8. Before sleeping: `{"t":"presence","state":"asleep","reason":"..."}` (or `close{going_to_sleep}`); a loss after it is published as `asleep`, otherwise `offline`. A `close{normal}` clears the hint. A clean shutdown sends `close{normal}`.
9. A close frame with `superseded`, `auth_invalid`, `auth_revoked`, `version_unsupported` or `normal`: do not reconnect. `protocol_error`, `heartbeat_timeout`, `server_restart` (also sent when a thread host is unreachable; the frame was not counted): reconnect with backoff.

## Spec issues (most literal reading taken)

1. **Credential check lives in the Machine DO.** The hash is stored in D1 `machines.credential_hash` (registry, listing) and in the DO (the hot path needs no D1, and the tracer runs without migrations). `POST /v1/machines` provisions both; `DELETE` updates D1 and always tells the DO. Revoking by editing D1 alone would not stop a tunnel.
2. **HTTP 401 vs close on a bad credential.** tunnel.md §2 does not say. Missing credential -> HTTP 401 before the upgrade; wrong or revoked -> upgrade accepted, then `close{auth_invalid | auth_revoked}` so the runner gets the §3.8 code.
3. **3 x heartbeat silence is `offline` even after an asleep hint** (the literal §3.7 reading: "socket lost without one, or no heartbeat for 3 x heartbeat_ms -> offline"). The watchdog is an alarm; it reads the runtime's `getWebSocketAutoResponseTimestamp` (no binding in `worker` 0.8.7, called through `Reflect`; the live test checks it works) so pings the DO never sees still count. If a runtime lacks it, the watchdog does not close sockets on that guess.
4. **tunnel.md §4.2 last paragraph (Thread DO dedupes `event_id` for 24 h) is not implemented in the Thread DO**: `threads/**` was limited to the push hook, and `POST /internal/threads/{id}/events` takes no `event_id`. The Machine DO keeps the 24 h window itself and records the `event_id` only after the append succeeded, so a failed append is retransmitted, but a crash between the Thread DO append and the Machine DO's write can append once more. See discovered work.
5. **`command_result` / 7-day expiry can only fail a task for `prompt` and `dispatch`** (the hub appends `RunStarted` + `RunError{error, code}` itself; a `RunError` is only valid inside a run, turn-event.md §5). For `approval` and `cancel` there is no task to fail, so the failure is only dropped from the queue. Expiry runs at `hello` and on a push (no timer while offline).
6. **Presence is not published into tracer-hosted threads.** The e2e checks the tracer stream event by event; a `Presence` before `UserMessage` (the runner can connect after the prompt) would break it. Real threads get it.
7. **`Presence{busy}` from the runner is ignored** (no `busy` in the published presence states).
8. **Push races.** A Thread DO push is the full set of its unacked commands; the Machine DO withdraws a never-sent command that is missing from a snapshot (a retracted prompt). Two pushes that arrive out of order can briefly re-queue a withdrawn command only if the older arrives first; a withdrawn source id is never re-queued. The reconnect-time pull is additive only, for the same reason.
9. **Edits outside the allowed list.** `crates/sidecar/src/bridge/runtime.rs`: the new `Outcome` variants made its `match` non-exhaustive, `submitted` / `declined` are answered ACP `cancelled` (approvals only; elicitation is M1A-006c). `crates/hub/tests/d1_schema.rs`: the test asserted "no `machines` table"; it now only checks the other tables (the `machines` checks moved to `machines::tests`).
10. `Outcome::Declined` / `Cancelled` accept extra fields (serde does not deny unknown fields on unit variants of an internally tagged enum, the same quirk `parse_frame` works around for ping/pong). Existing behaviour for `Cancelled`; not changed.
11. **Build environment.** Parallel workers share `CARGO_TARGET_DIR` and the crates have the same relative paths, so cargo can reuse another worker's `libprotocol` (it showed up as a `Command::SessionConfig` match error that does not exist in this tree). I touched the sources before each run to force a rebuild; a leader merging concurrently built branches should not trust incremental artifacts.
