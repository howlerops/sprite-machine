# M2B-011a: runner checkpoint: encode thread ids that git refnames reject; compare-and-swap on take

## Summary

- Thread ids are encoded into the ref component: an id that is already a valid git component is unchanged. Otherwise `:` becomes `+` and `.` becomes `%` (neither occurs in a valid id, so the forms cannot collide). `encode_thread` / `decode_thread` are public and keep the length equal to the id length (max 128).
- `take()` creates the ref with an all-zero expected old value (`git update-ref <ref> <new> <zero>`). A take that loses a race for n recomputes n and retries (up to 16 attempts), so it never overwrites.
- `list`, `restore`, `diff` use the same encoding through `checkpoint_ref` / `checkpoint_numbers`.
- Tests: 4 new tests in `shadow_git.rs`; the 6 existing tests are unchanged and pass.

## Acceptance criteria

1. **Encoding of any valid thread id: met.**
   - `thread_ids_encode_to_valid_reversible_ref_components`: 20 tricky ids (`.`, `..`, `.hidden`, `a..b`, `a.lock`, `:`, `a:b.c`, ...). Each encoded name passes `git check-ref-format`, decodes back to the id, and plain ids are unchanged.
   - `every_short_id_round_trips_and_encodings_do_not_collide`: all 258 ids of 1 to 3 characters over `a . : - _ 0`. Round trip holds, and no two ids share an encoding.
   - `take_list_and_restore_accept_a_colon_in_the_thread_id`: take, list, restore and diff with `th:1`. The ref is `refs/sm/checkpoints/th+1/1`.
2. **Compare-and-swap on take: met.** `concurrent_takes_on_one_thread_claim_distinct_numbers`: 4 threads released by a barrier must get `[1, 2, 3, 4]`, and `list` must agree.
   - Mutation check: with the old-value argument removed from `update-ref`, this test fails with `left: [1, 1, 1, 1]`. The restored code passes.
3. **Existing 6 shadow_git tests pass: met.** They are unchanged, and all 10 tests pass.

## Design notes

- The encoded length equals the id length, so the 255-byte loose-ref filename limit is not a concern for ids up to 128 characters.
- `list`, `restore` and `diff` still do not validate the thread id (only `take` calls `is_valid_id`). They encode whatever they are given, so a malformed id fails inside git instead of with a clear error. This is pre-existing and was left alone to keep the change minimal.
- The zero oid is `"0"` repeated to the length of the commit id, so it is correct for both SHA-1 and SHA-256 repositories.
