# M1A-006c report: runner bridge robustness

## Summary

- The bridge now notices the agent exiting: running tasks end with `RunError{error, code:"harness_exited"}`, `Reattacher::connection_lost` runs, and the next prompt respawns the agent (via a `Connector`) and resumes the session.
- `AcpClient` can deliver `session/update` as the raw `params` JSON (`Updates::Raw`); the bridge feeds that to `on_session_update_json`, so `raw.payload` keeps unknown fields and unparseable updates become `Raw` events.
- `session/new`, `session/resume` and `session/load` return their responses (`Attached.response`); the bridge emits `StateSnapshot{session}` from them. MCP servers (per thread, with a default) are sent on all three.
- At startup every interrupt left open by an earlier process is ended at once (`InterruptResolved{expired}` + `RunError{expired}`), whatever its TTL.

## Criteria

1. Harness restart: MET. `a_dead_agent_fails_running_tasks_and_the_next_prompt_respawns_and_resumes` kills acp-mock while the turn waits on an approval. Asserts RunError `harness_exited` for `tk_1`, the stored session `Detached` (so `connection_lost` ran) and no open interrupt, then a second prompt: a new mock is started, receives `session/resume` for `sess_mock_1` and no `session/new`, and answers.
2. Raw updates: MET. `updates_reach_the_log_as_the_agent_sent_them_and_unparseable_ones_become_raw_events`: a hand-played agent sends a text chunk with unknown fields (envelope `raw.payload` equals the sent update; the old re-serialisation dropped them) and an update kind the typed schema rejects (asserted in the test), which becomes exactly one `Raw` event with the payload verbatim.
3. Snapshot and MCP servers: MET. `new_and_resumed_sessions_get_the_snapshot_and_the_threads_mcp_servers`: the agent's received `session/new` carries the default servers for `th_1` and the per-thread ones for `th_2`; `StateSnapshot{session}` (mode from the `session/new` response) comes before the run ends; in a second process `session/resume` carries the thread's servers and the snapshot comes from the resume response. Note: acp-mock records nothing and returns no modes, so the test observes it through a recording tee (for mock tests) and a hand-played agent.
4. Stale interrupts at startup: MET. `interrupts_stored_by_a_previous_process_fail_their_task_at_startup`: a Store pre-populated with a paused task and an approval 10 minutes from expiry; the manual clock never moves; the bridge emits `InterruptResolved{expired}` and `RunError{expired}` at once, the interrupt is removed and the task stored `failed`.

## Decisions and caveats

- "Byte-faithful" means the JSON value as parsed from the agent's line (`serde_json::Value`, key order not preserved, numbers as serde_json holds them), not the original text bytes. A line that is not JSON is still skipped by the client.
- MCP servers have no source in the tunnel `Command` (no field in dispatch/prompt), so they are bridge `Config`: `mcp_servers` (default) and `thread_mcp_servers` (per thread id). Wiring them to the hub is not part of this item.
- Respawn needs a way to start the agent again: `Bridge::connect_with(connector)` / `spawn_with(command_factory)`. `Bridge::connect` (fixed streams, used by the tracer) cannot respawn; its tasks still fail with `harness_exited` and `connection_lost` is called, and later prompts fail the same way.
- After a restart the session snapshot is emitted again at the first resumed prompt of a thread (the thread has a new agent process).
- A `session/update` whose params have no `update` object is still dropped with a warning (nothing to make a Raw event from).
- The startup stale-interrupt ending reuses `on_interrupt_expired`, so the outcome is `expired`; `ResolvedOutcome` has no "agent gone" variant.
- An approval command for a thread the bridge has not seen in this process still answers `unknown_thread` (not `unknown_interrupt`), as before.
