# M1A-001 report: sidecar (runner-core lib): config, tracing, /healthz server fn

## Summary

- `sidecar::config` parses `SM_*` env vars through a pure `Config::from_map`. `Config::from_env` only collects the map. Defaults are documented in the module rustdoc.
- `MachineCredential` holds the secret in memory. Its `Debug` writes `<redacted>`, and the `Config` Debug output never contains the secret.
- `sidecar::config::init_tracing(&Config)` installs a stderr subscriber. It is safe to call twice, and an invalid `SM_LOG` filter is an error on every call.
- `sidecar::server::serve(addr)` binds `addr`, serves `GET /healthz` (JSON `name`, `version`, `git_sha`) and returns a `ServerHandle` with `local_addr()` and `shutdown()`.
- 11 integration tests in `crates/sidecar/tests/healthz.rs` pass. Clippy with `-D warnings` and `cargo fmt --all --check` pass. The crate has no `main.rs`.

## Design notes

- `SM_HUB_URL` is optional (`Option<String>`), not required, since the library parses config without connecting. Empty values count as unset.
- The default state dir is `$XDG_DATA_HOME/sm` when `XDG_DATA_HOME` is absolute, else `$HOME/.local/share/sm`. Neither `dirs` nor any other new crate is used. Without `SM_STATE_DIR`, `XDG_DATA_HOME` or `HOME`, `from_map` returns `ConfigError::NoStateDir`.
- `ServerHandle::shutdown()` signals and awaits the server. Dropping the handle also signals it, but does not wait.
- The `/healthz` tests use a raw HTTP/1.1 request over `tokio::net::TcpStream`, so no HTTP client crate is added.

## Acceptance criteria

1. **Met.** `sidecar::server::serve(addr)` serves `GET /healthz` with 200 and build info JSON. It returns a handle exposing the bound address and `shutdown()`.
   - `healthz_returns_build_info`: status 200, `name` = `sidecar`, `version` = crate version, `git_sha` = `SM_GIT_SHA` at build time or `unknown`.
   - `shutdown_stops_listening`: port 0 resolves to a real port, and connecting after `shutdown()` fails.
2. **Met.** `Config::from_env()` reads `SM_HUB_URL`, `SM_STATE_DIR`, `SM_LOG` and `SM_HEALTHZ_ADDR`, plus `SM_MACHINE_CREDENTIAL`. Defaults are in the rustdoc. Parsing is the pure `from_map`.
   - `defaults_apply_when_env_is_minimal`: defaults for `SM_LOG`, `SM_HEALTHZ_ADDR` (`127.0.0.1:0`) and the state dir.
   - `all_variables_are_read`: every variable is read.
   - `state_dir_prefers_absolute_xdg_data_home`: the XDG rule.
   - `no_state_dir_and_no_home_is_an_error`, `bad_healthz_addr_is_an_error`, `empty_values_count_as_unset`: edge cases.
   - `machine_credential_is_read_and_redacted_in_debug`: `Debug` prints `<redacted>`, and the secret does not appear in the `Config` Debug output.
3. **Met.** `sidecar::config::init_tracing(&Config)`.
   - `init_tracing_is_safe_to_call_twice`: two calls both return `Ok`.
   - `init_tracing_rejects_invalid_filter`: an invalid `SM_LOG` returns `Err`.
4. **Met.** No `crates/sidecar/src/main.rs`. Checked by `test ! -e` above.
