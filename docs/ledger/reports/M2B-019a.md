# M2B-019a: runner tui: a line typed while a task runs is queued behind it

## Summary
- The TUI keeps its own queue of typed prompts. A line typed while a task runs is shown as `pending: <text>` above the notice and is sent when the running task has ended, one at a time, in typed order.
- A prompt the bridge still refuses (`thread ... already has a running task`) comes back to the front of the queue with a notice; it is never dropped.
- `App::incoming` now returns the actions it leaves (the next queued prompt), and the driver, the e2e UI loop and the test loop carry them out. `Feed::Refused` carries bridge refusals of typed prompts back to the UI.
- `cli e2e rc` and `web/tests/rc.spec.js` drop the "type again after the turn" step: the line typed during the phone's turn runs after it.

## Files changed
- crates/runner/src/tui/app.rs: the queue (`Queued`, `queued()`, `dispatch()`, `refused()`); `incoming` returns actions; `key` and `prompt` dispatch.
- crates/runner/src/tui/driver.rs: `Feed::Refused`; the loop executes the actions `incoming` returns.
- crates/runner/src/tui/session.rs: prompts typed here are tracked by command key; `command_result` for one of them sends `Feed::Refused`; the entry is removed when the bridge's first event for its task arrives (the bridge took it) or when it is refused; `Handle::tracked_prompts` (for tests).
- crates/runner/src/tui/render.rs: pending lines above the notice.
- crates/runner/tests/tui.rs: `prompts_get_unique_valid_ids` feeds each task to its end (each line is still sent at once when idle); `Rig::until` executes actions and handles `Refused`; the loop test ends the phone's turn before typing "thanks" (it used to rely on the bridge running a second task); new tests below.
- crates/cli/src/e2e/rc.rs: `type_unless_logged` removed; the `ui_loop` executes incoming actions and handles `Refused`.
- web/tests/rc.spec.js: `typeUnlessLogged` removed; its two calls removed.
- docs/ledger/reports/M2B-019a.md (this file).

## Notes
- Not a silent drop: a refused prompt that cannot be sent yet stays pending and shows the bridge's reason in the notice line. A prompt is never discarded.
- Phone prompts are still queued by the hub. The TUI cannot see hub-queued prompts, so when a task ends, a queued local line and a hub-queued phone prompt can both be sent. The bridge takes one and refuses the other, and the refused local line is queued again (see Discovered work).
- `cargo fmt --all` in this worktree changed only the files listed above.
- Follow-up (review): accepted prompts are removed from the session's map (the leak is fixed here, so it is no longer listed as discovered work), and the refusal path through `Session::command_result` is now tested.
- Shared target dir: the first `cargo test -p runner --test tui` after the edits ran a stale binary (the new tests were missing), so sources were touched and the suite was rerun. The verify results above are from the rerun.
