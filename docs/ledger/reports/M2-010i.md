# M2-010i: list rows carry form and auth interrupts

## Summary

`GET /v1/threads` rows now list every open interrupt of a `needs_you` row in
`pending_interrupts`, not only approvals. Each entry carries `kind` (`approval`, `form` or
`auth`). Approvals keep their ACP `options`; form and auth entries have `"options": []`.

The index column already held the data: `tasks.pending_interrupts` (migration 0015) is JSON
text, so no migration was needed. The Thread DO writes the column in the same upsert as
`status`, as before. The only change in the write path is that `index_row` no longer filters
to approvals and sets `options` to `[]` for non-approvals.

Decisions:
- `kind` is added to `PendingInterrupt` with `#[serde(default)]` defaulting to `approval`. Rows
  stored before this change held only approvals, so they still parse and compare equal in the
  reconcile. A row with an open form or auth interrupt now differs from its stored copy, so the
  hourly reconcile rewrites it. No separate backfill is needed.
- The field is additive. Existing approval entries keep their keys and gain `kind`.
- The client parser (`crates/client-gpui/src/inbox/model.rs` `parse_interrupt`) ignores unknown
  fields and defaults missing options to `[]`, so it does not break. It does not read `kind` yet.
  The inbox's quick answer (`inbox/model.rs` `begin_answer`, `inbox/view.rs`) takes
  `pending.first()`, so a form or auth entry listed first hides the quick Allow/Deny of an
  approval listed after it. The approval card (`approval/view.rs`) is fed from the thread's
  `Interrupt` event, not from this list, so it is unaffected. Not edited, per the item's scope
  (see Discovered work).
