# M3-019a: approvals by keyboard

## Summary
The gpui-kit `Button` and `Checkbox` already take focus, join Tab traversal and activate on Enter
and Space through their `on_click`. The approval card needed no behavioural fix. Two things were
added: an explicit `.tab_stop(option.enabled)` on each option button (documents that an
unanswerable option is not a stop), and two window tests through the transcript pane that drive
the card with key presses only.

Test-harness facts worth keeping: a fresh window has nothing focused, so the first Tab does
nothing (the test enters with `window.focus_next`, as the shell's focus root does in the app);
key events are delivered when a window update ends, so each key goes in its own `update_window`
followed by `render_frame`.

## Files

- crates/client-gpui/tests/approval.rs (two new tests)

## Criteria
- Each option focusable, Tab in order, plus preset checkbox: `an_approval_is_answered_with_keys_only_through_the_pane`.
- Enter/Space answers with the option's own id: same test (Enter -> allow, Space -> always, Enter -> never; Space on the preset box -> SetPreset).
- Disabled options skipped / ignore keys: `an_answered_cards_options_are_skipped_by_tab_and_ignore_keys` (no focus, no actions).
- Fails without the change: NOT literally. The behaviour pre-existed in gpui-kit, so the tests pass on the old code. Mutation check: with `.tab_stop(false)` on the options the key test fails (only SetPreset actions recorded). The tests are regression guards.
