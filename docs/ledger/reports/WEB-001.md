# WEB-001: mobile web page, pairing + session list with presence

## Summary
- Plain HTML + ES modules in `web/` (no bundler/framework), served by the hub via Workers Static Assets; 390x844-first, light/dark.
- Pairing per client-api §5.7: `/pair?code=` QR redeem, `/pair/device` (and a sign-in button) device code with `interval`/`slow_down` polling; user, org and role are shown and the token is stored only on Confirm. Sign out revokes + clears; any 401 returns to sign-in.
- Session list: `GET /v1/machines` (online/asleep/offline) + `GET /v1/threads`, grouped by machine, **polled every 5 s while the page is visible** (and on becoming visible); tapping a thread goes to `#/t/<id>` (stub until WEB-002).
- DEV_FIXTURES-only hub routes set a machine's presence and upsert thread rows; Playwright (pinned 1.63.0, exists on npm) runs 9 tests at 390x844 against `wrangler dev --local`.

## Notes
- Actual `GET /v1/machines` rows are flat (`id`, `presence` string, `presence_since`), not the spec's `machine_id` + `presence{state,since}`; the page accepts both.
- Redeeming a QR link happens before the confirm screen (the code is single use), so a declined link is revoked with `DELETE /v1/auth/sessions/current`.
- The shared `hub.wasm` in the common target dir can be overwritten by other worktrees' builds; one run saw a stale wasm (404 for the new routes) and passed after a re-touch and rerun.
- `web/test-results` is not gitignored (`.gitignore` is outside the allowed paths).
