# M3-006b report: thread composer uploads through the session

## Summary
- `shell/view.rs`: `sync_machines_target` (the one place the shell follows the session's hub and token, run from `render`) now also calls `ThreadComposer::set_upload_target(target)` when the target changes. Sign-in, a different hub or account, and a stored session at launch give the composer an `HttpUploader` for `{hub}/v1` with the session token; sign-out gives it `None`, so an attach fails with "Sign in to attach files.".
- `tests/shell.rs`: the fake hub gains the §5.6 routes (`POST /v1/attachments` recording Authorization, Idempotency-Key and body and answering a signed `upload_url`; `PUT .../upload` recording whether an Authorization header came and the bytes), a `FakeChooser`, and one window test (below).
- `CONVENTIONS.md` (section 8): use `DropZone` for file drops (hover-gated `on_drop` / `capture_any_mouse_up` lose drops after typing at this gpui pin); use `find_all(id).is_empty()` / `try_find` for absence checks.

## Criteria
- Shell gives the thread composer its upload target when the session changes and clears it on sign-out: MET. `sync_machines_target` in `view.rs`; proven by the window test below.
- Window test: attach in an open thread via the fake chooser, send, hub sees POST, PUT (no bearer) and prompt with the file part: MET. `the_thread_composer_uploads_through_the_session_and_stops_after_sign_out` clicks `attach-add` (fake chooser), types, clicks `thread-send`, then asserts: one `POST /v1/attachments` with `Bearer sm_session_token`, an Idempotency-Key and `name: notes.md, size: 7`; one PUT to `/v1/attachments/org_1/att_1/upload` with the bytes and no Authorization header; the `POST /v1/threads/th_a/prompts` body has parts `[text "see notes", file notes.md with the signed-read url]`.
- After sign-out an attach shows "Sign in to attach files.": MET. Same test: after `sign_out`, a send of a new file leaves the chip `Failed("Sign in to attach files.")`, the composer is blocked, and the hub saw no further attachment POST.
- CONVENTIONS.md note: MET.
- Tests fail without the change: MET. With the `set_upload_target` call removed the test times out waiting for the prompt (the chip fails with "Sign in to attach files." and the hub sees no attachment POST).
