# M1A-014: Attachments: user FilePart → ACP image/resource blocks

## Summary

A `prompt`/`dispatch` file part (signed https URL) is now fetched by the runner before the
prompt is sent to the agent, instead of being forwarded as an unfetched `resource_link`.

- Images (`image/png`, `image/jpeg`, `image/gif`, `image/webp`) become ACP `image` blocks
  (base64 `data`, `mimeType`).
- Other files are written to `<workspace>/.sm/attachments/<sanitized-name>` (never over an
  existing file; a suffix `-2`, `-3`, ... is added) and the prompt carries the text block
  `@.sm/attachments/<name>`, a reference relative to the workspace.
- Fetch guards: https only; every resolved address must be public (SSRF guard, pinned
  connection, no redirects, no proxy); size cap 20 MB by default, checked against
  `Content-Length` and by the streamed byte count; optional `sha256` verified.
- Any failure ends the task with `RunError{code:"attachment"}` before the prompt reaches ACP.
  Error messages never include the URL (it carries a signed credential).

## Acceptance criteria

1. **Met.** Image parts become image blocks: `image_file_becomes_an_image_block`. Other
   files go to `.sm/attachments/` and are referenced as `@path`:
   `text_file_is_stored_under_sm_attachments_and_referenced`. Name sanitizing and no-overwrite
   dedupe: `filename_traversal_is_sanitized`, `duplicate_names_get_a_suffix_and_keep_both_files`.
   Size cap: `size_cap_is_enforced_by_content_length`,
   `size_cap_is_enforced_while_streaming_without_content_length` (exact cap accepted),
   `declared_size_over_the_cap_is_refused_before_any_download`. Digest:
   `sha256_is_checked_when_given`.
2. **Met.** Non-https rejected (http, file, data, ftp):
   `non_https_urls_are_rejected_under_the_production_default`. Private, loopback, link-local
   and unspecified addresses rejected, including via an injected resolver and for mixed
   public/private answers: `private_and_loopback_addresses_are_rejected`,
   `address_classification_covers_the_non_public_ranges`. The loopback test allowance is
   `FilePolicy::insecure_loopback_for_tests`; `production_default_never_allows_the_test_flag`
   checks the default. Failure code `attachment`: `failed_downloads_fail_with_the_attachment_code`.
   Not tested at bridge level: the "prompt never reaches ACP" property comes from ordering in
   `start_task` (the blocks are built before `client.submit`), not from a bridge test.
3. **Met.** All seven listed cases are covered by the tests above, against a local plain-HTTP
   server with the explicit test flag.

## Security notes

- SSRF: the host is resolved in the runner and each address is checked. The connection is
  pinned to the checked addresses (`resolve_to_addrs`), redirects are not followed, and the
  proxy is bypassed (`no_proxy`) so a proxy cannot connect to an unchecked host. A DNS
  rebinding race between check and connect is closed by the pinning.
- The test allowance (`insecure_loopback_for_tests`) permits `http` and loopback. Only tests
  construct it. Production uses `FilePolicy::default()`, which sets it to `false`.
- Filenames: only the last path component is used, reduced to ASCII letters, digits, `.`,
  `-`, `_`, with leading dots removed. Creation uses `create_new`, so an existing file is never
  overwritten. The attachments directory is resolved through `Workspace::resolve`, so a
  symlinked `.sm` pointing outside the workspace is refused (unix test).
- Errors do not include the URL, since `reqwest` error text would carry the signature query.
- Known limit: the image MIME type is the declared one. Bytes are not sniffed.
