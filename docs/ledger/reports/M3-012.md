# M3-012 report: client: agent registry + launch managed agent form

## Summary
- `AgentsView::new(machines, LaunchConfig, Arc<dyn ManagedAgentClient>, window, cx)` renders an agents table, a disabled "Add BYO agent by URL" button and a "Launch managed agent" form.
- Source of the table: `GET /v1/machines` (client-api §5.1). One row per (machine, harness in `capabilities.harnesses`), with name (harness), kind (`Local harness`), where it runs (machine name), skills, health and presence. Online rows sort first.
- Skills: the hub returns none, so the column shows "Not reported" (`AgentRow.skills` is empty; the column is wired for when a source provides them).
- Health: the hub has no health probe, so it is derived from presence (online = Ready, offline = Unreachable, other = Unknown).
- BYO: always disabled, with the Fluent reason `agents-byo-disabled` (A2A edge, M2-004, P5). The switch is the const `A2A_EDGE_AVAILABLE`.
- Launch: disabled with `agents-launch-disabled-no-key` unless `LaunchConfig.model_key_configured` (injected flag; `set_model_key_configured` toggles it live). With a key, the form (name, harness, model, egress allowlist, optional loadout) validates every field, then calls `ManagedAgentClient::launch`. There is no real M4 route; the request shape `ManagedLaunchRequest` is a proposal and `FakeManagedClient` is the stand-in.

## Acceptance criteria
1. Agents table with card (name, kind, runs on), skills, health, presence: met. `the_table_lists_each_harness_with_where_it_runs_and_presence` asserts row labels such as "claude, Local harness, runs on my-laptop, Online, health Ready" for a hub-shaped body; model tests cover ordering, offline/unknown mapping and null capabilities (no rows).
2. Presence from machine presence: met (same tests).
3. Registry gap shown honestly: met. The intro string says no hub registry exists; only local harnesses are listed. Skills "Not reported".
4. BYO disabled with Fluent reason: met. `the_byo_button_is_disabled_and_says_why`, `byo_is_disabled_until_the_a2a_edge_exists`.
5. Launch disabled with reason without a key; validates and calls the injectable client with a key: met. `without_a_model_key_launch_is_disabled_with_a_reason` (click does nothing, client untouched), `with_a_key_an_invalid_form_shows_errors_and_a_valid_one_calls_the_client`, `a_failing_client_is_reported`, `setting_the_key_flag_enables_the_form`; model tests `submit_*`, `invalid_form_reports_every_problem`.
6. Fluent strings with catalog test: met. `every_string_id_the_agents_module_uses_is_in_the_catalog` checks both directions (missing and dead ids).

Caveat: the table is a header row plus fixed rows of flex cells, not the gpui-component `Table`/virtual list. Fine for the handful of local harnesses; see discovered work.

## Shell mounting (for the shell worker)
Construct `cx.new(|cx| AgentsView::new(&machines, LaunchConfig { model_key_configured }, client, window, cx))` for the Agents section. `machines` = `MachinesResponse::parse(body)?.machines` from `GET /v1/machines`; call `set_machines` on each refresh and `set_model_key_configured` when settings change.
