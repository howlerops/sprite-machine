# M2-010m: thread list reports failed runs

## Summary
`GET /v1/threads` now reports the stored statuses `failed` and `cancelled` as themselves instead of folding them into `done`. The `status=` filter accepts `failed` and `cancelled`; `status=done` matches only `done`. client-api.md §5.2 documents the six values.

Decision on `cancelled`: reported separately. No spec text said cancel is done, and neither client breaks: the desktop client sends unknown values to Idle (Done section) and web falls back to `done`.

**Important limit:** the Thread DO never writes `failed` or `cancelled` today. `index_row` (crates/hub/src/threads/core.rs, outside my paths) yields only open/running/waiting/done, so a failed or cancelled run currently lists as `idle`. This item makes the list, filter and spec side correct; the producer is Discovered work (M2-010n). Because of that, the live test cannot create a failed row; it covers filter acceptance and that a done thread is not matched by failed/cancelled.
