# M3-004c: keep the capped mode on reopen

## Summary
- Runner: when a thread's session starts, its effective (capped) permission mode is written to `sessions/<thread>/permission_mode`. An idle-close reopen and a `-c` continue both read it and cap it again by the machine's local mode (`Router::recorded_mode`), instead of using the local mode.
- A thread with no record (stored before this change) still starts in the local mode.
- tunnel.md "Permission mode cap" reopen sentence updated.

## Files changed
- crates/runner/src/server/mod.rs (`PermissionMode::save` / `load`, record name)
- crates/runner/src/server/router.rs (`start_session` records the mode; `recorded_mode` used by `reopen` and `continue_last`)
- crates/runner/tests/server_mode.rs (`a_thread_started_in_plan_on_a_default_machine_is_reopened_in_plan`, `a_thread_started_in_plan_on_a_default_machine_continues_in_plan_with_c`)
- docs/specs/tunnel.md (reopen sentence only)
- docs/ledger/reports/M3-004c.md

## Criterion
- Met: "A thread started in plan on a default machine is reopened in plan after an idle close". Test `a_thread_started_in_plan_on_a_default_machine_is_reopened_in_plan` dispatches with `plan` on a `Default` machine, closes the idle session with `server::close_session`, prompts again, and asserts the second agent process receives `session/set_mode:plan` before `session/prompt`.
- Also met (`-c`): `a_thread_started_in_plan_on_a_default_machine_continues_in_plan_with_c`, same assertion after `continue_last`.
- Both tests fail with the corresponding change reverted (reopen: `let mode = self.ctx.permission_mode;`; `-c`: `let mode = self.ctx.permission_mode;` in `continue_last`). The fixes were restored afterwards.
