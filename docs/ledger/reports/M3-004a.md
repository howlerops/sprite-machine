# M3-004a: cap a remote permission mode by the local mode

## Summary
- Runner: `PermissionMode::capped(requested)`; a dispatch's `permission_mode` now applies only if the same or stricter than the machine's local mode (plan < default < acceptEdits < bypassPermissions), else the local mode applies. Applied as `session/set_mode` before the first prompt; the session reports it via the usual `current_mode_id` state delta. (Before, the dispatch field was ignored.)
- The runner advertises its local mode in `hello` as feature `permission_mode:<mode>` (no protocol struct change); the hub relays it as `capabilities.permission_mode` in `GET /v1/machines`.
- Composer: offers only modes up to the machine's mode, lowers a carried-over looser choice, and shows a note (local mode, or "X is looser than this machine allows ...").

## Spec text added
tunnel.md 3.1: "`capabilities.features` carries `permission_mode:<mode>` (`plan`, `default`, `acceptEdits` or `bypassPermissions`): the machine's **local** permission mode (`sm rc --permission-mode`), the loosest mode a remote request can get (see `dispatch`). Absent means the runner did not say."

tunnel.md 3.5 dispatch: "**Permission mode cap** (plan 4.10, "the local permission mode applies"). `permission_mode` is a request. Modes are ordered from strictest to loosest: `plan` < `default` < `acceptEdits` < `bypassPermissions`. The runner applies the requested mode only if it is the **same or stricter** than its local mode; otherwise (looser, or not a known mode) its local mode applies. The session runs in that effective mode from before the first prompt (ACP `session/set_mode`) and reports it as `StateDelta{session}` `current_mode_id`, like any mode change. The dispatch does not fail because it was capped. A runner reopening an idle-closed session uses its local mode."

client-api.md 5.1/5.2: `GET /v1/machines` capabilities gain `"permission_mode": "default"`; POST /v1/threads: "`permission_mode` is a request: the machine runs the thread in it only if it is the same or stricter than the machine's own local mode ... The machine advertises that local mode as `capabilities.permission_mode` in `GET /v1/machines` (omitted when unknown), and clients offer only modes up to it and say when a choice was lowered."
