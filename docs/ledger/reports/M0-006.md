# M0-006 report: protocol::acp re-exports the ACP v1 schema

## Summary

- `crates/protocol/src/acp` now re-exports the ACP v1 types (`agent_client_protocol_schema::v1::*`).
- `protocol` depends on the types-only `agent-client-protocol-schema` crate pinned to `=1.12.0`, not on the SDK. The SDK pulls `uuid` (getrandom) and process/stdio code, which the wasm32 hub must not link.

## Acceptance criteria

1. **Met.** `agent-client-protocol = "3"` is pinned in `[workspace.dependencies]` with `default-features = false`. `crate::acp` re-exports the v1 types. The SDK is not a dependency of `protocol`, per the tokio and wasm rule in the item.
   - Evidence: `Cargo.toml`, `crates/protocol/src/acp/mod.rs`.
2. **Met.** Ten fixture tests, each deserializing into the SDK schema type and re-serializing to an equal `serde_json::Value`.
   - Tests: `session_update_agent_message_chunk`, `session_update_agent_thought_chunk`, `session_update_tool_call`, `session_update_tool_call_update`, `session_update_plan`, `session_update_usage_update`, `session_update_available_commands_update`, `session_update_current_mode_update`, `request_permission`, `elicitation_create`.
   - Output: `test result: ok. 10 passed; 0 failed`.
   - The `session/update` fixtures deserialize into `SessionNotification`, the params type for `session/update`.
   - No cargo feature was needed. `usage_update` (`SessionUpdate::UsageUpdate`) and elicitation are stable in schema 1.12.0. The `unstable_*` gates are not used.
   - Fixture values avoid serde defaults that are omitted on serialization, for example `status: pending` on tool calls. Such values would fail the equality check.

## Deviations

- **Schema version.** The item says `agent-client-protocol-schema` 1.13.0. I pinned `=1.12.0` because `agent-client-protocol` 3.5.0 pins exactly `=1.12.0`. Using 1.13.0 would put two schema crates in the graph, and the runner's SDK types would not match `protocol`'s types. The 1.13.0 `v1` module differs from 1.12.0: it has `x-deserialize-default-on-null` schemars annotations, and the `sender_session_id`/`recipient_session_id` fields and their builders were removed from one struct. Both changes need checking before any future bump.
- **Build directory.** The shared `CARGO_TARGET_DIR` was locked by another session's build. I used a private target dir under the scratchpad for all verify commands. My earlier blocked test run was killed; it was my own process.
- **Co-author line.** The commit trailer follows the attribution reminder in the session context (`Claude Haiku 5.5`), not the `Claude Opus 5.5` line in the item text. The model running this item is Haiku 5.5.
