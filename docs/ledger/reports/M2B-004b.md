# M2B-004b: runner: wss:// tunnel (rustls + webpki roots on tokio-tungstenite)

## Summary

`TunnelConfig` hub URLs may be `wss://` or `https://`; the client connects over TLS with rustls (ring provider, installed once) and webpki roots. `TunnelClient::with_tls_roots` is the trust hook for tests. Plain `ws://` / `http://` is refused before any socket opens unless the host is loopback (`127.0.0.1`, `::1`, `localhost`). No native-tls or openssl in the runner tree.

## Files changed

- `crates/runner/src/tunnel/tls.rs` (new): `hub_url` (scheme normalisation, loopback rule), `is_loopback`, `webpki_roots`, `client_config` (installs the ring provider once via `Once`), 3 unit tests
- `crates/runner/src/tunnel/client.rs`: `tls` field (default webpki roots), `TunnelClient::with_tls_roots`, `connect` takes the TLS config, uses `connect_async_tls_with_config` with `Connector::Rustls`
- `crates/runner/src/tunnel/mod.rs`: `mod tls;`
- `crates/runner/tests/tunnel_tls.rs` (new): TLS fake hub with a CA generated by `rcgen`, 5 tests
- `crates/runner/Cargo.toml`: tokio-tungstenite feature `rustls-tls-webpki-roots`; `rustls` (ring, no default features), `webpki-roots` 1; dev `rcgen` 0.13 (ring), dev `tokio-rustls` (ring)
- `Cargo.lock`

`TunnelConfig` itself is unchanged: `crates/runner/src/tracer.rs` builds it with a struct literal and is outside this item's allowed paths, so the trust hook is a builder method, not a field.

## Acceptance criteria

1. **Met.** TLS over rustls, no native-tls/openssl: `cargo tree` check above. Hello/welcome over TLS with the test CA trusted via the hook (and `https://` base mapped to `wss://`): `hello_and_welcome_complete_over_wss_when_the_test_ca_is_trusted` (also checks the Authorization header arrives over TLS and the protocol `close{normal}` on shutdown). Untrusted certificate refused: `a_certificate_from_an_untrusted_ca_is_refused` (hub presents a cert from CA-A, client trusts only CA-B; the hub's TLS handshake is refused at least twice and no tunnel connection is accepted). Production trust store: `the_default_webpki_roots_do_not_trust_a_test_ca`. Provider install is idempotent (`Once` in `tls::client_config`).
2. **Met.** `plain_ws_to_a_remote_host_is_refused_before_connecting` (`ws://example.com:8080`, `ws://192.0.2.10:8080`, `http://10.1.2.3` all return an error containing "loopback" without retrying). Loopback still works: `plain_ws_to_localhost_still_connects`, the existing tunnel_client tests (`ws://127.0.0.1` fake hub, 37 passing), and `e2e tracer`. Host classification unit tests: `plain_ws_is_allowed_only_to_loopback`.

The wss tests fail on the base commit: tokio-tungstenite had no TLS feature, so a `wss://` / `https://` base was rejected by the upgrade request.

## Design notes and limits

- The loopback rule checks the host string in the URL, not what DNS resolves `localhost` to.
- Only webpki roots are trusted in production. Hubs signed by a private CA need a follow-up (native roots or a configured CA).
- Test PKI is generated at test time (`rcgen`); no key material is stored in the repo.
