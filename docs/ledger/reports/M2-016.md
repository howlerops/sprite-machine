# M2-016: hub D1 schema + migrations (org-wide metadata)

## Summary

- Migration `0002_org_metadata.sql` adds the org-wide tables from plan §4.2: orgs, users, members (owner/admin/member/viewer), devices (trusted, revoked_at), agents (local/managed/byo, card cache), workspaces, tasks with a FTS5 title index and sync triggers, notification_prefs, append-only audit_log, usage_rollups. `machines` is not created.

- `wrangler d1 migrations apply DB --local` applies 0001 and 0002 cleanly; `scripts/hub-test.sh d1_schema` passes end to end on a fresh local D1.
- No router change. Nothing in `router.rs`, `do/`, `threads/` or `tracer/` was touched.

## Design notes

- Tasks use `seq INTEGER PRIMARY KEY AUTOINCREMENT` as the FTS rowid. A plain table rowid can be renumbered by VACUUM, which would desync the FTS rows.
- `audit_log` is append-only by trigger, and its org foreign key has no cascade. An org with audit rows cannot be hard-deleted; that is deliberate, per the audit requirement.
- The `Db` futures carry no `Send` bound (Workers are single-threaded). The D1 impl uses `async fn`, which satisfies the `impl Future` trait methods.
- Integers bind to D1 as JS numbers, which is exact below 2^53. No column reaches that.
