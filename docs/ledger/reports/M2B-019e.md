# M2B-019e: runner tui: a runner-typed line the hub nacks is shown as a notice and kept

STATUS: DONE. All verify commands pass.

## Summary
- A `prompt_submit` the hub nacks is now handed from the tunnel client (`refuse_prompt`, via a `PromptRefusal` channel on `Shared`) to the TUI host, which feeds it to the session as `Feed::Refused`.
- The TUI keeps each line it sent up in a shared session (`in_flight`) until its task shows in the thread. A refused line goes back into the input (prepended if the input is not empty) with a notice; it is not re-queued, so a permanent refusal does not loop.
- Before this, the nack was only logged: the runner's `fail_task` handles only `event` frames, and the TUI had forgotten the line once sent.
