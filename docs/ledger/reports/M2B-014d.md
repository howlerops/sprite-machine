# M2B-014d report: machine_back to every subscription, with machine_id (generic title)

## Summary

- `machine_back` goes to every subscription of each user (the once-per-user rule is removed), like the other kinds.
- The payload carries `machine_id`. No prompt text and no machine name: the title stays generic ("Machine back online", plan §4.2). The phone looks up the name itself.
- `NotifyJob` gains an optional `machine_id`. Queued jobs from before this change have none and send the same payload minus `machine_id`.

## Files changed

- `crates/hub/src/notify/job.rs`: `NotifyJob.machine_id` (optional, skipped when absent); `payload()` adds `machine_id` when the job has one.
- `crates/hub/src/notify/presence.rs`: `machine_back_job(thread_id, machine_id)` sets `machine_id`.
- `crates/hub/src/notify/service.rs`: `process_job` drops the per-user `announced` set, so every subscription of the user is sent to.
- `crates/hub/src/notify/tests.rs`: `machine_id: None` in the existing literals; new native test `a_machine_back_goes_to_every_subscription_with_the_generic_title_and_machine_id`.
- `crates/hub/src/do/machine.rs`: `announce_machine_back` passes the machine id to `machine_back_job`.
- `crates/hub/tests/presence_notify.rs`: the first test uses an admin-created machine "Garage Mac" and checks the generic title, `machine_id`, and that the name is absent from the payload. The once-per-user test is replaced by `a_machine_back_goes_to_every_subscription_of_the_user`. Helper `named_machine`.
- `docs/specs/client-api.md` §5.8: `machine_back` payload carries `machine_id`; the title stays generic.

Reverted from the earlier attempt: the `machines` name lookup (`store::machine_name`), the `Notification` name field, and the D1 read in `process_job`.

## Acceptance criteria

1. **Met.** A user with two subscriptions gets the push on both, with `machine_id`, and no prompt text.
   - Live: `a_machine_back_goes_to_every_subscription_of_the_user` (two pushes, `machine_id` on each, `assert_no_more_than(2)`). Fails without the change: the second `wait_for(1)` times out, because the old code sent one push per user.
   - Live: `a_machine_back_with_queued_work_sends_one_push_with_ids_and_a_generic_title` (no prompt text, `machine_id` equals the machine).
   - Native: `notify::tests::a_machine_back_goes_to_every_subscription_with_the_generic_title_and_machine_id` (Ada's two subscriptions, Bob, Vic; Eve excluded).
2. **Not met, by decision.** The title names the machine. The coordinator ruled that plan §4.2 (ids + a generic title) wins, so the title is the generic "Machine back online" for every machine. The fallback therefore has nothing to choose between. The tests assert the generic title and that the machine name is absent from the payload (`a_machine_back_with_queued_work_sends_one_push_with_ids_and_a_generic_title`).
