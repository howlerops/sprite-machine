# M2B-014d report: machine_back to every subscription, with machine_id, and a title that names the machine

## Summary

- `machine_back` now goes to every subscription of each user (the once-per-user rule is removed), like the other kinds.
- The payload carries `machine_id`. No prompt text.
- The title is "<machine name> is back online". The name is read from the `machines` row when the job is sent; an unknown machine (a dev machine has no row) keeps "Machine back online".
- `NotifyJob` gains an optional `machine_id`. Queued jobs from before this change have none and still send the generic title.

## Files changed

- `crates/hub/src/notify/job.rs`: `NotifyJob.machine_id` (optional, skipped when absent). `Notification` gets `machine_name` (`with_machine_name`) and `title()`: "<name> is back online" for a named `machine_back`, else the kind's generic title. `payload()` adds `machine_id` when the job has one.
- `crates/hub/src/notify/presence.rs`: `machine_back_job(thread_id, machine_id)` sets `machine_id`.
- `crates/hub/src/notify/store.rs`: `machine_name(db, org_id, machine_id)` (`SELECT name FROM machines WHERE id = ? AND org_id = ?`).
- `crates/hub/src/notify/service.rs`: `process_job` drops the per-user `announced` set. For a `machine_back` with someone to send to, it reads the machine name once (before the sends) and passes it to the `Notification`.
- `crates/hub/src/notify/tests.rs`: `machine_id: None` in the existing literals; new native test `a_machine_back_goes_to_every_subscription_and_names_the_machine`.
- `crates/hub/src/do/machine.rs`: `announce_machine_back` passes the machine id to `machine_back_job`.
- `crates/hub/tests/presence_notify.rs`: the first test now uses an admin-created machine named "Garage Mac" and checks the title and `machine_id`. The once-per-user test is replaced by `a_machine_back_goes_to_every_subscription_of_the_user` (two subscriptions, two pushes, both with `machine_id`). Helper `named_machine`.
- `docs/specs/client-api.md` §5.8: `machine_back` payload carries `machine_id`; its title is the named or generic form.

## Decisions to review

- **The machine name is in the push title.** The plan's §4.2 rule is "ids + a generic title". This item asks for the machine name, so the name (user-chosen text) now appears in the encrypted push title. The name is not queued; it is read from D1 at send time. Confirm this is acceptable.
- **Name lookup failure.** A D1 read error in `machine_name` fails the job, so the queue retries it as a whole. Nothing is sent before the read.
- **Still per machine, leading edge.** The 60 s debounce from M2B-014 is unchanged.
