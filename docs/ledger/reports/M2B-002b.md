# M2B-002b: GET /v1/machines in the client-api §5.1 shape; DEV_FIXTURES 404 live test

## Summary
- `GET /v1/machines` now returns `{machine_id, name, kind, presence:{state, since}, capabilities:{harnesses, spawn, max_sessions}}` per row (client-api §5.1); revoked machines are left out.
- Capabilities are stored in D1 (`machines.capabilities`, migration 0012) from every accepted runner `hello`; `null` before the first hello.
- `web/src/sessions.js` reads only the new shape (flat fallback and `revoked` flag dropped).
- `scripts/hub-test.sh` takes `HUB_DEV_FIXTURES=0` to start a hub without DEV_FIXTURES; the smoke test checks the `/v1/dev/*` and `/v1/dev/fixtures/*` routes answer 404 there.
- Not fully met: a live two-org scoping test is not possible with the current API (see Acceptance).

## Acceptance
1. **Met for shape, revoked exclusion and web; partly met for org scoping.**
   - Shape: live `the_machine_list_is_the_client_api_shape_and_shows_the_hello_capabilities` (machine_do.rs) asserts the exact five keys, `presence.state`/`since`, `capabilities` null before hello and `{harnesses, spawn, max_sessions}` after a real runner hello.
   - Revoked: live `revoking_a_machine_closes_its_tunnel_and_it_cannot_reconnect` asserts a revoked machine is absent from the list; native `the_list_is_the_client_api_shape_scoped_to_the_org_and_leaves_out_revoked` too.
   - Org scoping: native `the_list_is_the_client_api_shape_scoped_to_the_org_and_leaves_out_revoked` (two orgs in the fake D1: viewer of org A sees only A's live machine; org B sees only its own). **Not** a live two-org test: `POST /v1/auth/bootstrap` is once per hub and no route creates a second org, so a live run cannot have two orgs. Needs a DEV_FIXTURES org fixture (proposed below).
   - Web: `web/src/sessions.js` uses only the new shape; the pairing spec (9/9) passes.
2. **Met.** Live `dev_fixture_routes_are_404_when_dev_fixtures_is_unset` (smoke.rs) probes 5 `/v1/dev/*` routes and both `/v1/dev/fixtures/*` routes with `Bearer dev`; with `HUB_DEV_FIXTURES=0` all answer 404 `not_found`. The default run asserts the same routes are not 404 and the credential route answers 201, so the 404 is the gate.

Behaviour notes: revoked machines are excluded (no flag). `POST /v1/machines` still answers the flat `machine` object (out of scope; see discovered work).
