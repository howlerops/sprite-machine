## Design notes and limits

- The Store outbox is the source of truth; each connection rebuilds the `Sender` via `Sender::from_parts` after `welcome`. `from_parts` uses the default window of 256 (its signature has no `max_inflight`); `welcome.max_inflight` is not honoured.
- Down commands are committed (`commit_down_frame`: key + `last_down_seq`) when received, fed to the bridge, and acked only after `CommandSource::processed`. A crash between commit and the bridge applying it loses that command (the hub will not resend it).
- After a fresh stream, a late `processed(seq)` from the old numbering could clear a same-numbered new command's pending entry (rare; acks could run early).
- An enqueue/`restart_outbound_stream` race is avoided with a client-side lock because the Store reads and rewrites the outbox in two steps.
- HTTP 401/403/426 on upgrade end `run` with an error (no retry). `auth_revoked` calls `CredentialSource::wipe`.
- Not done (outside the item): `wss://` needs a TLS feature on tokio-tungstenite (only `ws://` works today); `presence{asleep}` before OS sleep; `thread_open` sending.

## Discovered work

```yaml
- title: "runner: wss:// support for the tunnel (TLS feature on tokio-tungstenite)"
  why: "tokio-tungstenite is built with only `connect`; production hubs are wss. Pick rustls + root store and install a crypto provider."
- title: "sidecar store: close the commit-before-apply window for down commands"
  why: "Add Store::seen_key (read-only) and commit_down_frame on bridge `processed`, so a crash cannot lose a command that the client already counted as processed."
- title: "sidecar store: outbound_since(seq) and an atomic restart_outbound_stream"
  why: "The client re-reads all unacked rows on each wake and needs an external lock around restart_outbound_stream."
- title: "runner: presence hints and thread_open from the client"
  why: "Send presence{asleep} before OS sleep and expose TunnelSink::thread_open for local sessions (tunnel.md §3.4, §3.7); body shapes are already supported by the outbox."
- title: "protocol: Sender max_inflight from welcome"
  why: "Sender::from_parts / on_welcome do not take the hub's max_inflight."
```
