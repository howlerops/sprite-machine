# M3-011f: desktop inbox: clicking a thread row opens it

## Summary

- A click on a row's title/detail area emits `InboxEvent::OpenThread { thread_id, workspace }` from `InboxView`. `AppShell` subscribes to the inbox and calls `AppShell::open_thread(thread_id, workspace, cx)`, which shows the thread on the Inbox page and makes the session link follow it (the M3-011c entry point).
- The click target is a sibling of the row's buttons (Allow, Deny, Rename, Archive), so their clicks never reach it. No stop-propagation is needed.
- Keyboard: the inbox has no keyboard selection (no focused or selected row, rows are not focusable), so Enter does nothing. This is recorded as discovered work, not built here.
- Resets: branch was behind `v2` with no commits of its own, so it was reset to `v2` (7bca43d) before starting.

## Files

- `crates/client-gpui/src/inbox/view.rs`: `InboxEvent` enum, `EventEmitter<InboxEvent>` impl, `InboxView::open_thread`, the clickable title column (`inbox-open-<thread_id>`) in `render_row`.
- `crates/client-gpui/src/inbox/mod.rs`: re-exports `InboxEvent`.
- `crates/client-gpui/src/shell/view.rs`: subscribes to the inbox in `AppShell::new` (`_inbox_events`) and routes `OpenThread` to `open_thread`.
- `crates/client-gpui/tests/inbox.rs`: 2 new window tests (`a_row_click_opens_that_rows_thread_with_its_workspace`, `quick_allow_answers_and_does_not_open_the_thread`).
- `crates/client-gpui/tests/shell.rs`: fake hub gains `GET /v1/threads` (rows from `HubState.threads`); 2 new window tests (`clicking_an_inbox_row_shows_its_thread_and_follows_it`, `quick_allow_on_a_row_answers_and_does_not_open_its_thread`).
- `docs/ledger/reports/M3-011f.md` (this file).

## Criteria

1. Met. A row title click emits `OpenThread` with the row's `thread_id` and `workspace`: `a_row_click_opens_that_rows_thread_with_its_workspace` (events == `[OpenThread { thread_id: "th_run", workspace: Some("/work/other") }]`). The shell turns it into `open_thread`: `clicking_an_inbox_row_shows_its_thread_and_follows_it` (fake hub sees subscribe `["th_a"]`, `open_thread_id() == Some("th_a")`, `thread-back` shown).
2. Met for the pointer. Keyboard (Enter on a row): the inbox has no keyboard selection, so there is nothing for Enter to act on. Not implemented; see discovered work `M3-011f-D1`.
3. Met. Quick Allow does not open the thread: `quick_allow_answers_and_does_not_open_the_thread` (inbox: event count unchanged across the Allow click, hub receives the answer) and `quick_allow_on_a_row_answers_and_does_not_open_its_thread` (shell: after Allow on `th_a`, the hub's subscribed list stays `["th_b"]`, `open_thread_id()` stays `None`, and the answer POST for `th_a` / `int_1` arrives).
4. Met. Each new test fails without the change (see Fail check).

## Notes

- The title/detail column is the click target, not the whole padded row. The padding and gaps around the buttons do not open the thread.
- `cursor_pointer()` is not available at this gpui pin, so the row shows no pointer cursor on hover.
- Shared target dir: the doc-test step once failed with "extern location for client_core does not exist" (another worktree replaced the rlib). Rebuilding `client-gpui` restored it, and the doc-tests then passed. Same cause as M3-011c-D4.
- Flake (not caused by this change, not reproduced): one full run of `tests/shell.rs` had `the_banner_follows_a_client_core_connection` fail once. The test was not touched; it passed 6 of 6 when run alone and in the full suite run that followed.
