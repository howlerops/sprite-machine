# M2B-007: runner: `sm rc` server mode (spawn, capacity, permission mode, names, --continue)

## Summary

`sm rc` (and `sm run` as an alias) connects the machine to the hub, advertises the discovered harnesses, and runs a session per dispatched thread. Each session has its own `Bridge::spawn_with` over its own harness process and its own sidecar store (a shared store lets one bridge's start-up end other sessions' interrupts). A router reads the tunnel's commands, forwards each to its session, and answers `capacity`, `harness_missing`, `unknown_thread` and `invalid` itself. `--spawn worktree`, `--capacity`, `--permission-mode`, `--name-prefix` and `-c` are implemented; the spawn mode and last session are saved per project.

## Decisions and limits

- The runner's `--permission-mode` is authoritative; the dispatch's `permission_mode` is ignored. It is applied as `session/set_mode` right after the dispatch is handed to the bridge (so the first prompt may start in the agent's default mode). A failure to set it is logged, not reported to the hub.
- Capacity counts sessions with a running or paused task. A prompt for an idle session over capacity also gets `capacity`.
- A worktree with uncommitted changes is kept on session end (logged). Worktrees left by a crashed runner are not swept at start.
- `-c` re-registers the last session of the current directory via `thread_open` and resumes it on the next prompt; with no prior session it only logs a warning.
- MCP: the agent's `mcp_capabilities` are known only after the bridge's own `initialize`, which the bridge does not expose, so `local_mcp_servers` gets `McpCapabilities::default()` (stdio servers only).
