# M2-003b report: GitHub OAuth + PKCE, members and invites

## Summary
- Authorization code + PKCE (S256 only): `GET /v1/auth/github/authorize` -> GitHub -> `GET /auth/github/callback` -> app redirect with a one-time hub code -> `POST /v1/auth/github/token` (code + verifier) -> ordinary session (7-day web, 30-day desktop).
- Redirect URIs are an allowlist: `http://127.0.0.1:<port>/callback` / `http://[::1]:<port>/callback` (RFC 8252 §7.3) or the hub's own `/auth/github/callback`; anything else is 400, never a redirect. The code exchange with GitHub is server side with `GITHUB_CLIENT_SECRET`; the hub user is found by GitHub user id.
- Members + invites: `GET /v1/members` (viewer), `POST/GET /v1/invites`, `DELETE /v1/invites/{id}`, `PATCH/DELETE /v1/members/{user_id}` (admin, never above your own role, never yourself). An invite by GitHub login is accepted by that account's first sign-in. Removed members lose their sessions at once.
- Migration 0014 (github_id, oauth_requests, oauth_codes, org_invites); client-api.md §5.9; live suite with a mock GitHub (authorize/token/user).

## Security notes
- Redirect allowlist: exact-match parser (no `localhost`, no https, fixed `/callback` path, explicit port 1-65535 without leading zero, no query/fragment/userinfo/backslash/space, length cap) or exactly `<origin>/auth/github/callback`; checked in `authorize` before anything is stored. A bad one is a 400 JSON answer. A bad or used `state` at the callback is also 400 with no redirect (no trusted target). Hub origin is `HUB_PUBLIC_URL` if set, else the request Host (same approach as the device-pairing URLs); production should set `HUB_PUBLIC_URL`.
- State / verifier: `state` (256 random bits, `ost_`) is stored only as SHA-256, single use (atomic UPDATE), 10 minutes, and bound to the hub's own PKCE verifier for the GitHub leg (challenge sent to GitHub, verifier sent with the exchange) and to the app's S256 challenge, redirect URI and `state` (required, echoed). `plain` is refused. The hub code (`oac_`, 256 bits, hash only) is single use (atomic claim), 2 minutes, redeemable only with the verifier of its challenge and the same redirect URI (constant-time compare); any miss burns it.
- Token exchange: server side only, form POST with `client_secret` from the Worker secret `GITHUB_CLIENT_SECRET` (var fallback only for local `--var`; never in config or source). The GitHub access token is used once for `GET /user` and dropped; GitHub error bodies and tokens are never logged or audited; audit details are redacted by `audit::redact`. A failing GitHub leg sends the app `error=server_error`.
- Identity: users are mapped by `github_id` (unique index), never by login; the login is refreshed on sign-in and a stale holder of the same login is cleared. An account with no hub user and no open invite creates nothing. A user an admin created with a login and no `github_id` is linked once by login.
- Responses that carry a code are `302` with `Cache-Control: no-store` and `Referrer-Policy: no-referrer`; the web page gets the code in the URL fragment.
- Not done: rate limiting of `/v1/auth/github/*` (codes are 256-bit, so guessing is not the risk, but state creation is unauthenticated and writes a row; expired rows are purged on each authorize).
