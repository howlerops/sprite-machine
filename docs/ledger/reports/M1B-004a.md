# M1B-004a — gpui spike: app shell + virtualized transcript pane

## Summary
Standalone Cargo project `spikes/gpui` (empty `[workspace]`, lock copied from root, root dev profile) at the
root's exact GPUI pins. The shell (title bar + sidebar placeholder + transcript pane) opens via
`gpui_kit::open_window`; the pane renders the in-memory `transcript-10k` log (10k+ events → 2,504 rows) in a
`v_virtual_list` built by a pure view model. Headless test: 22 of 2,504 rows laid out; wheel scroll by 200
rows makes row 200 the first visible row. Ran the binary under xvfb + lavapipe; it rendered correctly.

## GPUI API notes vs CONVENTIONS.md
- `.when(...)` / `.when_some(...)` need `use gpui_kit::prelude::*;` (`FluentBuilder`).
  `use gpui_kit::*` + `use gpui_kit::component::*` is not enough on `Observed<…>` (the
  `.test_support()` wrapper). §0 should list `prelude::*` (headless_smoke.rs already imports it).
- `.test_support()` (`gpui_kit::TestSupportExt`) is available without the `test-support` feature. Without the
  feature it returns the element unchanged, so view code can call it unconditionally.
  `.aria_label(…)` must come after `.id(…)` (`StatefulInteractiveElement`).
- `VirtualList` is not observable itself. To scroll it in a test, wrap it in an element with
  `.id(...).test_support()`: `window.scroll` dispatches the wheel at the observed element's centre.
  A negative y delta scrolls down.
- `find_all(id)` matches on the **last** path segment. Give each row a unique wrapper id (`("row", ix)`)
  and an inner element with a shared id (`"transcript-row"`). `find_all("transcript-row")` then counts
  the laid-out rows. Rows that are not rendered drop their registration, so the count is the virtualized
  set. Use `.visible()` to skip overdraw rows.
- `v_virtual_list` needs every item size up front (only the height is used for vertical lists).
  Variable-height wrapped text needs measuring or a different list; the spike uses fixed one-line rows with
  `.truncate()`.
- §1's snippet `|window, cx| cx.new(|cx| AppShell::new(window, cx))` is fine. `open_window` returns
  `Result<(AnyWindowHandle, Entity<V>)>`, so `gpui_kit::Result` resolves through the glob.
