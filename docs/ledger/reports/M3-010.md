# M3-010: client: diff viewer (desktop)

## Summary

`crates/client-gpui/src/diff/` now holds a diff viewer, not yet wired into the task view.

- `model.rs` is plain Rust. `DiffInput { path, old_text: Option, new_text }` (with `From<&protocol DiffContent>`) becomes numbered lines, hunks, collapsible gaps, and the display rows of the unified and split layouts. Binary, too-large and identical inputs become a `Notice`.
- `view.rs` is `DiffView`, a `v_virtual_list` with fixed 20 px rows, so only visible rows are laid out. It emits `DiffEvent::OpenFile { path, line }`.
- Entry point: `cx.new(|_| DiffView::new(DiffInput::from(&content), Some(workspace_root)))`, then `cx.subscribe(&view, ..)`.
- Strings are in `locales/en/diff.ftl`.

Decisions:
- `similar = "2"` was added to `client-gpui/Cargo.toml`. It is already in `Cargo.lock` (2.7.0, via gpui-component), so no new crate was fetched. It replaces the spike's hand-written LCS. The diff has a 2 s deadline, after which the result is still correct but less minimal.
- Limits: 2 MiB or 100k lines per side, 2000 chars per line. Lines are sanitized (control characters dropped, tabs become 4 spaces).
- Context is 3 lines. A run of unchanged lines shorter than 2 is shown, not collapsed.
- "Open file" is offered only if the workspace root is known and the diff path resolves inside it (`resolve_path`). A relative path is joined to the root. An absolute path must be under the root. Any `..` is rejected, so an agent-supplied path cannot point outside the workspace.
- The open line is the new-file line of the hunk's first change. For a pure deletion it is the line where the text was removed.
- The approval card's capped inline diff was not changed, because it is in another item's paths. It could later reuse `DiffModel`.

## Criteria with evidence

- **Unified and split views:** `unified_then_split_layouts_show_numbered_lines` clicks the mode buttons and checks the row labels for both layouts. The model's `split_pairs_removed_with_added_and_pads_the_short_side` covers the pairing.
- **Chunked rendering:** `a_large_diff_lays_out_only_the_visible_rows` uses 30k lines with a change every 7th line, giving more than 30k rows. At most 60 rows are laid out before and after a scroll of 15k rows, and the rows differ after scrolling.
- **Collapsing context into gaps:** `unchanged_context_collapses_into_expandable_gaps` checks the label "Show 49 unchanged lines" and that clicking it opens the gap and the row count grows by 49. `expand_all_opens_every_gap` covers "Expand all". The model tests cover the gap boundaries and the rule that a one-line gap is not collapsed.
- **Open file:** `open_file_from_a_hunk_emits_path_and_line` checks `OpenFile { /work/repo/src/lib.rs, 12 }`. The action is absent, with no event, when there is no root (`open_file_is_absent_without_a_workspace_root`) and when the path is outside the root (`open_file_is_absent_for_a_path_outside_the_workspace`).
- **Line numbers:** the aria labels carry old and new numbers, and the model tests assert them.
- **No newline, binary, too large:** `missing_newline_binary_too_large_and_identical_say_so` checks the "No newline at end of file" row and the binary, too-large and identical messages. The toolbar's mode buttons are hidden in these cases.
- **Fluent:** `every_string_id_in_the_code_is_in_the_catalog_and_every_catalog_id_is_used` scans the sources for `"diff-..."` literals. The test fails if one is missing from `diff.ftl` or a catalog id is unused.
- **Each test must fail without the change:** the tests assert on behaviour that does not exist without the module. I did not mutation-test individual assertions.

## Not covered

- Syntax highlighting is not done. The viewer is plain monospace with add/remove tinting from theme colors.
- No word-level (intra-line) highlighting.
- Pixel output is not checked; the render proof is separate.
- The `Open file` hunk action has no keyboard shortcut yet.
