# M2B-004f: macOS sleep watcher FFI checked, logind mock bus test

## Summary

- Type-checking the macOS module for `aarch64-apple-darwin` found a real compile error: the leaked `struct Context` clashed with the `anyhow::Context` import (E0255, then E0599 on `.context`). Renamed to `PowerContext`. The module now type-checks and passes clippy `-D warnings` for `aarch64-apple-darwin`, including its new unit tests.
- Every IOKit and CoreFoundation declaration was checked by hand against the SDK headers (table below). Message values are pinned by unit tests that run on the macOS CI job.
- New `tests/sleep_logind.rs` runs the real `LogindSleepWatcher` against a mock `org.freedesktop.login1.Manager` on a private `dbus-daemon` (6 tests: signal mapping, Inhibit arguments, fd held/closed, replace, drop, and `forward` ordering).
- The sleep/wake on a real Mac is a human step; steps below.

## Files changed

- `crates/runner/src/sleep/macos.rs`: `Context` renamed `PowerContext`; module doc updated (no longer "not compiled"); `#[cfg(test)] mod tests` (message values, `classify`, scalar widths).
- `crates/runner/tests/sleep_logind.rs`: new, Linux only.
- `docs/ledger/reports/M2B-004f.md`: this report.

No Cargo.toml or Cargo.lock change: the test uses the existing `zbus` and `libc` dependencies of the crate. `tests/sleep_hook.rs` is unchanged.

## FFI check against the SDK

| Declaration here | SDK header | Documented signature or value | Match |
|---|---|---|---|
| `IORegisterForSystemPower(void*, IONotificationPortRef*, IOServiceInterestCallback, io_object_t*) -> io_connect_t` | `IOKit/pwr_mgt/IOPMLib.h` | same | yes |
| `IOAllowPowerChange(io_connect_t, long) -> IOReturn` | `IOPMLib.h` | `long notificationID` | yes (`isize` is pointer-sized, as C `long` on Apple LP64) |
| `IONotificationPortGetRunLoopSource(IONotificationPortRef) -> CFRunLoopSourceRef` | `IOKit/IOKitLib.h` | same | yes |
| `InterestCallback(void* refcon, io_service_t, uint32_t messageType, void* messageArgument)` | `IOKitLib.h` `IOServiceInterestCallback` | same | yes |
| `io_connect_t`, `io_object_t`, `io_service_t` = `u32`; `IOReturn` = `i32` | `mach_port_t` (`natural_t`), `kern_return_t` (`int`) | | yes |
| `kIOMessageCanSystemSleep` = `0xE0000270` | `IOKit/IOMessage.h`: `iokit_common_msg(0x270)` | `sys_iokit` = `err_system(0x38)` = `0xE0000000`, `sub_iokit_common` = 0 | yes |
| `kIOMessageSystemWillSleep` = `0xE0000280` | `iokit_common_msg(0x280)` | | yes |
| `CFRunLoopGetCurrent`, `CFRunLoopAddSource(rl, source, mode)`, `CFRunLoopRun`, `kCFRunLoopDefaultMode` | `CoreFoundation/CFRunLoop.h` | `CFStringRef` constant | yes |

`IOCancelPowerChange` and `IODeregisterForSystemPower` are not declared: the watcher never vetoes a sleep, and it lives for the whole process (context and port are leaked on purpose), so there is nothing to deregister. Declaring them unused would trip `dead_code`. Tests also pin `kIOMessageSystemWillNotSleep` (0x290), `SystemHasPoweredOn` (0x300) and `SystemWillPowerOn` (0x320) as `Other`.

## How the macOS check was done here

- `rustup target add aarch64-apple-darwin` worked. `cargo check -p runner --target aarch64-apple-darwin` does **not** get that far on this host: `ring` needs a C cross compiler and the macOS SDK (`cc: unrecognized option -arch`; with `CC=clang`, `bits/libc-header-start.h` missing). The host has no macOS SDK.
- Instead a scratch crate (outside the repo) holds the real `sleep/macos.rs` plus the platform-independent types copied from `sleep/mod.rs`, with only `anyhow` and `tokio` as dependencies. `cargo clippy --target aarch64-apple-darwin --tests -- -D warnings` on it passes. `--tests` builds the new unit tests (compiled, not run: Linux cannot run Mach-O). This type-checks the FFI declarations and the `unsafe extern` blocks as Rust; it cannot check the link against the real frameworks, which the macOS CI job does.
- The leader should check the `macos` CI job after merge.

## logind mock bus test

`dbus-run-session` itself was not used. The test starts `dbus-daemon --session --nofork --print-address=1` as a child (killed on drop), so it knows the bus address and each test gets its own bus; this needs the `dbus-daemon` binary on the machine and fails with a clear message if it is missing (no silent skip). The mock `Manager` is served with zbus (the crate the watcher uses) under the name `org.freedesktop.login1`. Its `Inhibit` returns the write end of a `pipe(2)` and keeps the read end: the read end reports EOF exactly when the client has closed the inhibitor fd. `LogindSleepWatcher::connect_to(address)` connects the real watcher; `PrepareForSleep` is emitted with `emit_signal`.

| Test | Covers |
|---|---|
| `prepare_for_sleep_true_and_false_map_to_will_sleep_and_resumed` | real proxy signal signature, `true` -> `WillSleep`, `false` -> `Resumed` |
| `take_delay_asks_for_a_sleep_delay_inhibitor_and_holds_its_fd` | `Inhibit("sleep", "sm", _, "delay")` arguments; fd open on the client |
| `release_delay_closes_the_fd_and_is_idempotent` | fd closed after `release_delay`; second release is Ok |
| `taking_the_delay_again_closes_the_previous_fd` | replacement closes the old fd |
| `dropping_the_watcher_releases_the_inhibitor` | no leaked inhibitor |
| `forward_writes_the_hint_while_the_fd_is_held_then_releases_and_retakes_on_resume` | with the real watcher: delay taken at start, hint written while fd still held, fd released after the hint, fresh inhibitor on resume |

## Manual steps on a Mac (human)

1. On a Mac (Apple silicon or Intel), check out this branch, `cargo build -p runner`, and run the unit tests: `cargo test -p runner sleep::`.
2. Start the runner against a hub so `presence` is observable (or run with `RUST_LOG=runner=debug,info`). Confirm no "OS sleep hook disabled" warning appears at start (that would mean `IORegisterForSystemPower` returned 0).
3. In another terminal watch the log: `log stream --predicate 'eventMessage contains "powerd"'` is optional; `pmset -g log | tail` shows sleep/wake after the fact.
4. Put the Mac to sleep: `pmset sleepnow` (or close the lid / Apple menu > Sleep). Before the display goes dark the runner should log the hint write (debug "sleep hint not written" only if there is no live connection), and the hub should show the machine `asleep`.
5. Wake the Mac. Confirm the runner is still alive, reconnects, and the hub shows presence back.
6. Repeat sleep/wake 3 times to confirm `IOAllowPowerChange` is acknowledged each time (a missed ack shows as a ~30 s delay before sleep, visible in `pmset -g log` as "Sleep ... delayed by sm").
7. Failure to look for: sleep taking about 30 s (ack missing), runner exiting, or the hub never seeing `asleep`.
