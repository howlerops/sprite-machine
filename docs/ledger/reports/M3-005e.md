# M3-005e report: bounded outbox; readable, dismissable refusals

## Summary
- `client-core/src/outbox.rs`: the outbox keeps only the newest `DEFAULT_MAX_DONE` (64) `Done` entries. Pruning runs whenever an entry becomes `Done` (rows deleted from memory and the cache); `Outbox::with_max_done(cache, n)` sets another bound and prunes at once. Rule (documented in a code comment on the constant): `Queued` entries are never pruned (still to be sent); `Conflict` and `Rejected` stay until dismissed or superseded (existing `tidy_outbox`); `Exhausted` stays for the user. The readers of `Done` are safe: the approval controller treats `Done` and a missing entry alike (clears the local answer), and `tidy_outbox` only needs the newest accepted session/remove request, which is always inside the window.
- `shell/link.rs`: `Refusal` now carries `local_id` and a `DismissHandle` (weak sender to the link's command channel, so a kept snapshot does not keep the link alive; all handles compare equal, identity is `local_id`). `Refusal::dismiss()` sends `Command::Dismiss`, which removes the entry if it is still `Rejected` and republishes the snapshot.
- `compose/thread.rs`: each refusal line shows a plain sentence for `forbidden` and `invalid_request` (other codes fall back to the code, none falls back to the HTTP status) and a Dismiss button `thread-refused-dismiss-N`; the click dismisses the entry and removes the line at once. The catalog key is built from parts because `tests/compose_commands.rs` scans the file for whole `compose-thread-` ids.
- `locales/en/compose.ftl`: `compose-thread-refused-code-forbidden`, `...-code-invalid-request`, `...-dismiss`, `...-dismiss-a11y`; the three refusal lines read "The hub refused the mode change. { $detail }".
