# M1A-003 report: sidecar (runner core): ACP client + session table (concurrency, pending tasks)

## Summary

- `sidecar::acp::client::AcpClient` speaks JSON-RPC over newline-delimited JSON to one agent, spawned as a child (`spawn`, `kill_on_drop`) or over any reader and writer (`connect`). It advertises fs read/write, terminal, and elicitation form and url.
- `sidecar::acp::sessions::SessionTable` runs one prompt at a time per session. A prompt sent while one is in flight is a pending task. Pending tasks can be listed and removed, and run in arrival order.
- `session/update` goes to a caller-supplied `mpsc::UnboundedSender`. Agent requests (permission, elicitation, `fs/*`, `terminal/*`) go to a caller-supplied `ClientHandler` trait.
- `cancel` sends `session/cancel`. The running prompt ends `cancelled`, and a waiting permission or session-scoped elicitation is answered with a cancel.
- 8 integration tests pass, plus 1 ignored helper that the subprocess test re-runs. Clippy, `cargo fmt --check` and the test list count pass.

## Design notes

- Reader task: one task reads the agent's stdout. Responses go to the waiting call, `session/update` goes to the channel, and each agent request runs in its own task, so a handler that blocks does not stall the reader.
- Per-session driver: a submit to an idle session starts a driver task. The driver takes the next queued task under the table lock and clears `driving` when the queue is empty, so there is never more than one driver per session.
- Cancel race: `session/cancel` sets a per-session `watch` flag. Permission and elicitation handlers race against it. The flag resets when the next prompt starts.
- Closing: dropping the client aborts the reader, fails queued tasks with `Closed`, and drops the child, which `kill_on_drop` kills and tokio reaps. A line from the agent that is not JSON is logged with `tracing::warn` and skipped, so an agent that writes logs to stdout does not break the connection.
- The handler trait uses `impl Future` return types, so `AcpClient` is generic over the handler and the trait is not object-safe.
- The subprocess tests re-run the test binary as the agent. `CARGO_BIN_EXE_acp-mock` is not set for another package's tests, and the mock binary is not built by `cargo test -p sidecar`.

## Acceptance criteria

1. `initialize` advertises fs, terminal and elicitation{form,url}: MET. `initialize_advertises_fs_terminal_and_elicitation` reads the wire request. `session/new(cwd, mcpServers)` works and `session/prompt` streams `session/update` and returns the stop reason: MET. `prompt_streams_updates_and_returns_stop_reason`.
2. N concurrent sessions on one acp-mock: MET. `concurrent_sessions_on_one_agent_stay_separate` runs three sessions, two rounds, against one in-process `acp_mock::run`. It is not a separate OS process; the stdio test below covers the process case with one session.
3. A second prompt on a busy session is queued as a pending task (visible: list, remove), not interleaved, and runs after the first finishes: MET. `second_prompt_queues_as_pending_task_and_runs_after`. No B text arrives while A is blocked, and the queue order is B, C, D, with C removed.
4. `session/cancel`: the running prompt ends `cancelled`, and a pending permission is answered `cancelled`: MET. `cancel_ends_prompt_and_answers_pending_permission_cancelled`. The test plays the agent by hand, so it reads the client's `cancelled` answer on the wire. The queued task then runs.
5. Agent requests route to the handler trait (permission, elicitation, terminal/*): MET. `agent_requests_route_to_the_handler`. `fs/*` is routed in `route` but no test drives it, since the mock does not call `fs/*`.
6. Child processes are reaped on drop (kill_on_drop): MET. `subprocess_is_reaped_on_drop` (checked by mutation, see above). The stdio agent works end to end in `subprocess_agent_serves_acp_over_stdio`.
