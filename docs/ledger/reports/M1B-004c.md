# M1B-004c: gpui spike: terminal pane (alacritty_terminal)

Branch worker attempt 1. Spike-only change under `spikes/gpui/`.

## Summary

- `TerminalPane` (gpui-kit view, `spikes/gpui/src/terminal_pane.rs`) renders the visible grid of an `alacritty_terminal::Term` as styled rows at a fixed cell size (9 x 18 px), fed by the `terminal` fixture's `append` chunks plus an ANSI test string.
- Pure grid-to-rows mapping (`grid_rows`) and the VT model are in `terminal_model.rs`; key-to-bytes encoding (`encode_key`) is in `terminal_input.rs`. Neither imports GPUI.
- Key presses on the focused pane go to an injected `std::sync::mpsc::Sender<Vec<u8>>`. In the app the sink is the runner's terminal stdin.
- `alacritty_terminal` pinned to `=0.26.0` (latest on crates.io at the time, with `vte` 0.15.0 as its parser).
- All 5 verify commands exit 0. The terminal filter runs 20 tests; the full spike suite runs 36 lib + 6 integration tests, all passing.

## GPUI and alacritty API notes that differ from CONVENTIONS.md

- There is no `window.key(...)`. The pinned `gpui-kit` test API is `window.press("ctrl-c", cx)` (key down + up, parsed keystroke) and `window.input("ls", cx)` (one key-down per character with `key_char` set). `press` and `input` take no focus target.
- Keyboard focus: `window.focus(&handle, cx)` takes `cx` as well. Put `track_focus(&handle)` and `on_key_down` on the same `div().id(..)` before `.test_support()`; the observed wrapper then carries the aria label.
- `find_all("terminal-line")` returns only the laid-out rows (matched on the last id segment), so each row uses a wrapper id `("terminal-row", ix)` and an inner shared id.
- Rust 2024 `impl IntoElement` return captures borrowed arguments. A row builder taking `&StyledRow` failed with E0515, so it takes the row by value.
- alacritty_terminal: vte's bare LF calls `linefeed()`, which does not honour LNM (`CSI 20 h`), so a line feed kept the column. The model now inserts a CR before any LF not preceded by a CR (the pty `onlcr` step), with the CR state carried across `feed` calls.
- The fixture's closing `snapshot` repeats the whole output; it is not fed (the append chunks already carry it). Its exit status is not shown.
